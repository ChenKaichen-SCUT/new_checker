# 阶段 2：解析反例

下列均为逻辑构造；不以有限枚举证明它们成立。
初始变量为 0，除特别说明外为 ISA 级 WB 内存或无 C na-UB 的模型。

## C1 删除中间写

P0: W(x,1); W(x,2)。P1: r=R(x)。
源允许先执行第一写、再执行 P1 读、最后第二写，r=1。
只保留 W(x,2) 的目标中唯一写值是 0 和 2，rf 值匹配排除 r=1。
两侧最终 x 都可为 2，故入口/出口内存相同不足以推出上下文等价。

## C2 重复读被合并

P0: a=R(x); b=R(x)。P1: W(x,1)。
按读0、写1、读1执行得到 (a,b)=(0,1)；合并成一次读强制 a=b。
任何将两次读同地址绑定到同一个符号值的 checker 都会漏掉该反例。

## C3 compiler barrier 被加强为 mfence

P0: W(x,1); CB; r=R(y)。P1: W(y,1); CB; s=R(x)。
TSO 可先将两个写放入各自 store buffer，再读另一个仍为0的位置，得到 r=s=0。
若两侧 CB 均改 MF，假设仍读0：令 a,c 是两写、b,d 是两读。
MF 产生 a→b、c→d；读初始值产生 b rb c、d rb a。
得到 ob 环 a→b→c→d→a，矛盾。删除 MF 的相反方向则增加行为。

## C4 sfence 不能作为 mfence

以 SF 替换 C3 的 CB。SF 排序进入 fence 的访问，但没有 fence→后续普通读的
Store→Load 约束；以上 store-buffer 执行仍可能。映射 MF 排除它，非等价。
并非“更强总是更安全”：它会使验证器漏掉源反例。

## C5 RMW 拆分

两个线程各原子 fetch_add(x,1)，初始 x=0，所有操作完成。
mo 对两成功 RMW 全序，RMW 原子性要求第二个读取第一个的写；
两个写值必为1、2，最终2。
拆成 R(x);W(x,old+1)，两个读都可先读0，然后都写1，最终1。
这是原子性差异，不是位向量加法是否正确的问题。

## C6 失败 CAS 的排序消失

初始 x=y=z0=z1=0。
P0: W(x,1); locked_CAS(z0,expected=1,desired=2); r=R(y)。
P1: W(y,1); locked_CAS(z1,expected=1,desired=2); s=R(x)。
两个 CAS 必失败，读0，均不发出写。然而它们仍是 RMW.tso：
po 进入 RMW 与从 RMW 出发的 po 给出 a→cas0→b 和 c→cas1→d。
r=s=0 又给 b rb c、d rb a，形成 Coherence-II 环，源不可能。
若失败 CAS 被改普通 Rtso，则 W→RMW 的边丢失；两个写延迟、CAS读0、另一变量读0
的 TSO 执行成立。因此“失败不写”不等于“没有 locked 排序”。

## C7 地址别名

源 W(p,1); r=R(q)，目标把 r 固定为入口时 q 的值。
令 p=q，同线程读自己的写使 r=1；固定初值0的目标不匹配。
给不同操作数建立不同的符号地址常量再断言它们不等，会漏掉此类错误。
本检查器比较符号地址，且不添加 p≠q。

## C8 tied operand 和早期覆盖

`asm("addl %1,%0" : "=r"(out) : "0"(in) : "cc")` 的输出寄存器必须在入口持有 in。
目标把输出初始化为0会把2*in变成in。不能把 `"0"` 当另一个无关输入。

`asm("movl $0,%0; addl %1,%0" : "=r"(out) : "r"(in) : "cc")`
没有 early-clobber：合法分配可能令两个操作数共享寄存器。第一条清零破坏后续输入。
把 token 当独立寄存器会错误得到 in。改 `"=&r"` 才排除该分配。
因此必须检查所有合法分配，或保守拒绝此声明。

## C9 输出写回与隐式内存

`"=r"(*p)` 的宿主输出回写是一项 C 内存事件，并不是寄存器内部 τ。
`"m"(*p)` 的隐藏地址寄存器也是输入；early-clobber 不能只检查显式 r 操作数。
原型只接受输出为局部标量标识符，内存输出保留独立 m 操作数和对应显式事件。

## C10 C UB 与标志

机器 `addl` 在 0x7fffffff+1 得到0x80000000；有符号 C int 加法引入 UB。
两者在继续比较结果的上下文中不等价。目标 IR 只能用明确 BV 加法。
`add; adc` 中 cc clobber 只描述块外接口，不能删除 add 对 CF 的块内影响；
第一版拒绝 adc、条件跳转、setcc 及未建模的 flags 消费。

## C11 伪证书与空前提

若证书可把 P 改成 false，所有 SMT 义务都 UNSAT，但未证明任何真实输入。
P、模型、源文件、目标文件必须由 checker 重建/绑定；不能相信候选证书给出的自由假设。

## C12 仅比较最终标签或笼统 RMW 类别

同为 RMW 的 xadd 与 xchg 的新值不同；同为 CAS 的成功判定若把 == 改成 !=，
其可选写、返回值和 ZF 都不同。必须逐一检查表达式、写有效位及错误/输出。
只比较 kind 或只比较成功路径不足以接受。
