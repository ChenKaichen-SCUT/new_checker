# 算法创新性：具体比较与 No-Go

2026-10-21 核对第一手材料。不能因为既有工具没有 GNU/LLVM/Dat3M 适配器就
宣称算法空白，也不能因本原型有清晰证书接口就宣称独立方法创新。

| 工作 / 核对位置 | 现有机制及实际前提 | 本轮与它的关系 |
|---|---|---|
| [Semantic Program Alignment, PLDI 2019](https://cs.stanford.edu/people/sharmar/pubs/veceq.pdf)，§3.1、Lemma 3.1、Corollary 3.2 | 根据候选路径对和关系不变式构造 PAA；独立核验局部关系、未覆盖路径不可能、空步环排除及出口观察。候选由轨迹引导不意味着轨迹本身就是证明 | 本轮有相同的 producer/checker 原理。域内路径纯分支被总结为 ITE、效果顺序固定，因此映射只是有序匹配；未设计比 PAA 更强的关系/路径合成 |
| [Direct Construction of Program Alignment Automata, 2021](https://arxiv.org/abs/2109.01864)，作者摘要 | 针对轨迹覆盖不足，直接从程序构造 PAA。这里仅使用摘要所支持的构造方向，不据此声称已核完所有定理 | 说明不能把“从完整程序而非测试轨迹枚举”当成本轮独有创新。它不自动提供 TSO/实际导入桥；该桥差别不足以证明新算法 |
| [Stellite, ESOP 2018](https://www.cs.kent.ac.uk/people/staff/mjb211/docs/esop18.pdf)，§4.3、Theorems 1–3 | 在 C++11 片段模型中，比较同一上下文 A/R/S 下的开放历史及顺序保证；有 adequacy/full abstraction，以及有限但失去完备性的版本 | 本轮固定事件端点/po，不研究它可表达的事件结构变换。共享环境/组合并非首次提出；统一 rf/co 是必要证明步骤，不是单独算法发明 |
| [VALID, CGO 2016](https://plv.mpi-sws.org/validc/paper.pdf)，§3.1 CIM/§3.2 MD | 已有无需移动元数据的 shared-action 匹配及依赖 metadata 的另一方案；区分可删除动作、支持重排/引入/删除，含控制流处理。无环可靠性与循环限制需区分 | 本轮 Q 单位来源不靠 debug 行号，但 GNU→LLVM 仍依赖来源契约。固定顺序的 rank 匹配比其一般共享动作匹配更窄，不能声称发明自动事件匹配 |
| [DESTIVA, OOPSLA 2026](https://mikekben.github.io/resources/OOPSLA_DESTIVA.pdf)，Lemmas 4.3–4.6、Theorem 4.7、§4.3 | 从实际修改集构造空间分解，片段精化经函数组合推出全函数精化；需要编译插桩准确记录修改集，其可靠性讨论明确承认该前提 | 本轮保存所有事件、检查完整分区，不使用修改集隐藏未证范围；但其摘要边界和组合原理已有。不同 TSO 模型需要另证，并不构成不可替代的分解算法 |
| [Slicing Shared-Memory Concurrent Programs, ICSME 2023](https://personales.upv.es/josilga/papers/ICSME2023.pdf)，§§II,V,VI | threaded dependence、调用上下文、干扰可行性和时间戳；修正既有切片的上下文/时间旅行问题 | 本轮不切掉程序或义务；自由变量跨边界分析是更简单的标准数据流。它不提供 CAT 图相容性，但本轮也没有提出新的并发切片机制 |
| 既有 [本仓库 HCC 开放组合证明](../hcc/01-contract-and-proof.md) 与 [L3 全局关系附录](../levels/04-formal-appendix.md) | 任意开放读响应、逐实例覆盖、统一全局 rf/co 的端点保持组合 | 新 ACTC 定理把前提组织成可导出的区域计划和独立边界检查；不是重新命名一条尚未存在的上下文定理 |

以上不是直接可执行的跨模型组合：PAA/DESTIVA 的函数模型和 Stellite/VALID
的并发模型不能靠拼接工具输出成为本项目证明。GNU 源义务、Clang 元数据、
完整 Q 与 pthread/查询契约仍需逐项落实。本轮明确补足受限模型里的这些接口，
但没有找到现有机制合理组合无法表达的最小算法障碍。

## 可归纳为已有原则的完整机制

完整前端语义恢复 → 按公共效果切分 → 总表达式摘要 → 两侧自由变量边界 →
有序全覆盖关系 → 独立普遍等式 → 固定端点全局 TSO 输送 → 实际查询绑定。
每一步均有具体实现及充分条件；核心仍是有限符号执行、标准关系证明和覆盖检查。
未引入新的不动点、语义匹配搜索、反例引导划分、不可观察事件消除或更一般历史关系。

自动生成一份好读的证书是系统改进；在已支持域内，它让遗漏边界、实例和节点
能被明确拒绝。但生产接受域没有扩大，完整 CK 客户端障碍没有关闭，也没有成本
优势测量。不能以本次正例数量或 SMT UNSAT 替代这些缺失证据。

## 分开判断

- **受限可靠性：成立的条件式推导。** 逐区域开放等式和全覆盖足以推出本轮
  ACTC-TRANSFER；实现有针对性验收，但没有机械证明 Python/Java/Clang。
- **独立算法创新：No-Go。** 当前机制可归纳为已有原则的受限实现，没有实质
  算法差异或不可直接解决的区分问题证据。
- **真实自动化突破：有限。** 新增候选/核验分离和可复核边界；既有源适配器及
  pthread 宿主限制仍在。没有把特例解析增加当作本轮成果，也未扩大真实客户端接受率。
- **ISSTA 完整实验：No-Go。** 本轮交付后停止；没有依据以大规模实验弥补方法
  创新和现实适用性的缺口。工具系统价值仍可独立讨论，但目前不能声称论文已成立。
