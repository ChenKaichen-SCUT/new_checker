# 基线能力、文献机制与 Go/No-Go

本轮使用第一手论文与仓库既有审计。恢复受控实验后仅实测本仓库 ACTC
与新原型的同对象对照，见 [对照记录](../../experiments/diagnostics/review-01/comparison.json)。
外部工具仍为机制审阅，未执行工具不填写失败或宣称胜负。

## 1. 与现有方法比较

| 方法 | 已有机制、前提与语义方向 | 本轮方案的实际差别/未闭合条件 |
|---|---|---|
| [TInA, ASE 2019](https://rbonichon.github.io/papers/tina-ase19.pdf)，尤其验证流程；亦见仓库[全文审计](../correspondence/01-literature-audit.md) | GNU asm lifting，重编译、CFG/块对应和符号验证；测试回退不构成普遍证明。功能语义不直接给出本项目固定 CAT 的全部并发保证 | 本轮要绑定实际 Q 和并发端点；这属于待实现跨模型桥，不能由“不直接导入 Dat3M”证明新算法。尚无实测优于 TInA 的缺陷发现 |
| [VALID, CGO 2016](https://plv.mpi-sws.org/validc/paper.pdf)，§3.1–3.2、§5 | 已有 shared-action 匹配、引入/删除/重排分析及控制条件处理。CIM 不依赖移动元数据但有 CFG 前提；MD 依赖元数据。C11/LLVM 并发规则，非完整功能等价检查 | 枚举类型化候选、核对所有未匹配端点不是空白。新 guarded 公式未证明比其控制/合并规则具有新算法机制或成本优势；不直接移植其删除规则到 TSO |
| [Alive2, PLDI 2021](https://web.ist.utl.pt/nuno.lopes/pubs/alive2-pldi21.pdf)，§§3–7；[官方实现说明](https://github.com/AliveToolkit/alive2/blob/master/README.md) | LLVM 函数的符号精化、内存与 UB/poison，提供具体反例；不要求逐指令同构。有界循环可能漏报；官方说明不支持跨过程变换 | 本轮局部环境更弱，不建模全部 LLVM UB，也不提供完整闭合程序反例。源→验证模型错误包含与通常目标⊆源的优化精化方向不同。没有适配/运行对照，不作工具胜负判断 |
| [Stellite, ESOP 2018](https://www.cs.kent.ac.uk/people/staff/mjb211/docs/esop18.pdf)，§4.3 | 开放历史和上下文保证；内部不要求简单端点同构；有充分性与有限化条件 | “开放环境+上下文关系”不是新机制；本轮 exact-history 观察更强、更窄，不应把严格拒绝当更强检测 |
| [PAA, PLDI 2019](https://cs.stanford.edu/people/sharmar/pubs/veceq.pdf)，§3.1 | 自动候选路径对应、关系不变量、未覆盖路径不可行检查，候选不可信 | 多候选、独立核验、路径完整性均已有。本轮部分映射/guard 并未证明超出这类关系验证的能力 |
| 本仓库 L1/L2/L3/ACTC | 独立开放字段检查、来源/覆盖/实际 Q/查询绑定；当前域下有序匹配 | 本轮原型能输出经独立重核的诊断证书，但无条件总序域由退化引理化为原有秩对应；没有新增自动检错范围证据 |

此外 [RUSTInA, ICSE 2021](https://arxiv.org/pdf/2102.07485) 已形式化 GNU
接口合规并提供自动检查/修补。错误 clobber、寄存器约束等应区分为接口
合规问题，不能把全部“inline asm 缺陷”都重新定义为本轮的转换不一致问题。
本轮没有实现这些工作的替代品，也没有排除其可组合能力。

## 2. 针对当前仓库的增量判断

| 问题 | 基线事实 | 本轮能够严格声称的增量 |
|---|---|---|
| 已有 raw asm 共享写丢失 | 历史真实输入/日志和解析论证已存在；早期不能把打印 IR 自动反向认证 | 设计了从实际 Q 的完整消费得到空公共体与参考端点比较的路径；两次新 raw 后端运行都检测到读写端点缺失，且同输入提升正例通过；它仍不是新增发现 |
| 人工错误返回、操作数、实例、A 标签等 | ACTC/L3 已能拒绝这些实例 | 共同见证/歧义集合实际核验通过；同一批 Q 的 ACTC 也全部拒绝，没有基线漏报增量 |
| 历史 ITE 导出问题 | 已有实际不完整标记及历史拒绝，随后已修复 | 明确属于证据边界，禁止误报实际后端分支错误；不是新增检测能力 |
| 固定总序上的候选搜索 | 基线直接按完整公共序列对应 | 本轮解析证明该搜索退化。更多搜索步骤不是增量 |
| 条件互斥复制 | 原实现不提供一般条件共享事件/活跃子图对应 | D_G 摘要层设计有区分例和包含证明，但实际提取与验证前提未实现；已有 TV/路径对齐原理可直接解释核心机制 |
| 唯一根因或完整可执行反例 | 原工具并未声称从任意局部 SAT 得到它们 | 本轮也未解决；只能报告义务/观测区间/可能位置集合 |

新的输出字段、失败分类或把第一次失败改为列出全部失败，具有审阅便利性；
这与新的检测/定位算法贡献必须分开。最小偏差集合的成本依赖字段粒度；
两个同语义实现缺陷可能产生同一摘要，故不能将其解释为实际错误代码的
唯一最小修复。暂无证明或数据说明该成本函数比既有 TV 反例更有效。

## 3. 结论

**数学层面：** 已给出无条件模型的反例可靠性条件和总序退化证明；另给出
有限 guarded 摘要模型中有条件定义使用、部分映射与逐输入开放历史包含的
条件定理。这些不依赖有限测试，且不新增源安全/编译正确性的假设。

**算法创新：No-Go。** 当前实现仍退化到已有保序对应；更一般的 D_G
设计是有限关系语义与完整路径/事件覆盖的直接构造，尚无区别于已有符号
等价、事件匹配或翻译验证的实质新机制。也没有成本优势证明。

**实际价值：受限证据生成已验收。** 三次新 Dat3M、13 项固定分类及同对象
基线对照支持历史回归与诊断材料生成。没有新增上游缺陷、完整客户端覆盖、
唯一根因或闭合执行反例。不能从这批固定样本推算误报率、漏报率或性能收益。

**当前 ISSTA Research 路线：No-Go。** 不据设计例子启动规模实验或继续
增加解析特例。将来只有在单独审阅后，找到不能合理归结为上述已有机制的
关键障碍/分解规则，并补齐真实摘要前提，才有依据重新评估。工具诊断可用性
可以单独研究，但本轮没有可发表系统贡献已经成立的结论。
