# 开发记录、失败与剩余缺口

## 范围与版本

最初任务包含实现与小规模验收。中途用户将阶段限定为分析/设计，执行随即暂停；
其后用户明确要求继续原型、编译、后端、SMT 与测试，才恢复运行。没有外部目标
访问或利用活动。以下材料全部保留，不能将计划、失败或旧版本混作最终成果。

| 材料 | 实际状态 |
|---|---|
| `development-01/branch` | 早期正常历史 Q 回放；非最终版本 |
| `acceptance-01`、`acceptance-commands-01` | 固定计划、一次实际 Clang 捕获；direct adapter 不接受 `ptr noundef null`，在 Dat3M 前失败 |
| `acceptance-02` | 恢复授权后：两次新 Clang 同次 AST/LLVM、三次新 Dat3M；13 项分类达到预期。随后强化对象域，故诊断以 final-03 为准 |
| `final-03` | 最终原型重开 acceptance-02 原始捕获及历史实际 Q，13 项重新生成与独立核验；没有再次编造/捕获后端对象 |
| `unit-01` / `unit-02` | 先 38 项，增加混合宽度对象不重叠检查后最终 39 项；保留两版输出 |
| `review-01` | 10 项同对象 ACTC 对照完成；之后审阅脚本误将复用模板的 SMT 文件名解释为每调用独立文件而停止 |
| `review-02` | 调度过早，final-03 未全部写完时读取失败；没有形成通过结论 |
| `review-03` | 审阅脚本对仅含文件/哈希引用的旧模板义务误要求内嵌 `smt2` 字段；失败保留 |
| `review-04` | 最终审阅：依原始哈希解析共享 SMT 文件和内嵌文本，逐字节核对并重求解；不补造证明文件 |

上述审阅脚本问题是本轮证据汇总代码的实现错误，不是上游缺陷、捕获缺陷或
数学反例。修正没有跳过义务：共享文件必须真实存在，哈希必须相符；存在内嵌
文本时也必须逐字节相等。每条引用仍单独登记。

## 已关闭的原型问题

1. 入口仅接受已核对的 `ptr null` 或 `ptr noundef null`；不把非空参数当空。
2. 域只由源对象建立，不允许错误目标添加限制来排除源反例。32/64 位完整对象
   分别采用 4/8 字节自然对齐；对象区间不重叠，以 65 位加法比较端点，避免
   地址溢出。已核对前端提供常对象、类型和生存期；未知地址表达式保守拒绝。
3. 核验器先用阶乘计算候选数量并检查上限，再物化排列。截断或 UNKNOWN 不能
   支持否定结论。资源上限是可用性限制，不是语义假设。
4. 正负结论都重开真实输入；负例共同赋值须击败完整候选集；最小偏差集合另行
   重算。篡改候选数、域赋值、映射或前沿的单元攻击均被拒绝。

## 没有解决的事情

- 全公共 po 强制唯一秩映射；穷举不是新的对应算法。独立核验器和生成器共享
  公式/参考语义 kernel，不能宣称两个完全独立实现或机械验证的检测器。
- 新模块仍使用有限宿主和固定运行时协议。用户 Fence、CAS 条件事件、循环、
  间接调用、未知别名、任意 CFG 均未加入当前实现；03 的 guarded 定理仅为设计。
- 诊断的最小成本依赖字段粒度。错误返回值可能只在后续断言条件被发现，错误
  操作数与错误算术可能不可区分；不能自动给出唯一源代码根因或精确内部 pass。
- 匹配所有已识别 worker 的开放端点不等于完整 Q/宿主/查询检查。实际 main 查询
  错绑在新模块范围外，由原 ACTC 独立拒绝，不给新模块记检错收益。
- 不产生闭合可执行反例；合法源输入、真实路径、完整激活、统一 rf/co/fr/CAT、
  初始化和错误监视器仍需额外证据。局部模型允许在完整程序不可达的读响应。

## 历史缺陷与原始软件

原始 [Dat3M 报告](../11-dartagnan-reproducer.md) 不变。
固定后端 `b81ec6c55503e824bb0ddc4ebac6c6f0a63d56d8` 的
`VisitorLlvm.visitCallInst` 对不能识别的 asm 仅构造返回非确定值而没有副作用。
本轮新捕获确认每个真实 worker 的公共体为空，源参考分别有一个 32 位原子读写。
读写均丢失，不宜只写“写值错误”。定位自动到观察区间和原来源/LLVM 位点，
不能由此宣布定位到某个内部编译 pass。

两线程初始 x=0、各 FAA(+1) 的历史预期有解析依据：固定 TSO 原子性使读取
来自对应写在同对象 co 的直接前驱，两个完成写依次为 1、2，正常 join 后观察 2。
新原型没有把这一解释伪装成自动闭合执行证书。EXPECT=0 的 PASS 只是实际
后端现象，检错依据是独立恢复的完整 worker 端点与参考语义不一致。

历史 ITE 缺字段仍只说明导出器证据不完整。不能据此声称实际后端选错分支；
相应反例返回 CAPTURE_UNKNOWN，修复导出器后的原始分支 Q 正常开放比较通过。

冻结完整 CK event-counter 仍保留原始两 TU、配置、循环、回调、syscall 与
113 个存活 asm。新方法没有完整 Q/宿主摘要，结论为缺前提而未能分析完整客户端。
不宣称零误报、零漏报或“已完成搜索无缺陷”。受控 CK harness 仅使用未修改的
上游例程，不能冒充完整上游应用。没有新增真实上游缺陷。
