## 1. 实际链与必须区分的对象

| 层 | 仓库中的实际对象/入口 | 已有保证 | 不能推出的结论 |
|---|---|---|---|
| GNU C/asm | `capture_ck.py`、Clang observer、源文件/依赖/AST | 同次来源捕获；特定约束、类型、展开与调用上下文检查 | 任意 GNU C、数据竞争程序或未知别名有定义 |
| 原始 LLVM L | `provenance.py`、`local_ports.py`、`p1_entry.py` | 原始 asm 位点与接口、受限 C/LLVM 参数表达式核验 | 编译器所有优化正确；缺少来源必然是编译缺陷 |
| Event IR 与实际 L' | `prepare.py`、`lowering.py`、`translate_all` | 独立参考语义；实际替换区间与未改框架；L1/L2 | 后端正确导入实际 L'；全部动态实例得到保留 |
| 最终 Q | `run_pipeline.run_backend`、Snapshot、`endpoints.py` | 同次求解实际对象、完整表达式/事件；局部读写/配对解释 | 导出器已经机械验证；部分实例检查等于全图保证 |
| 组合和宿主 | `composition.py`、`program_main` | 有限宿主、全部公共效果、边界、创建/完成协议及覆盖 | 循环/间接调用摘要存在；未知宿主可自动忽略 |
| 实际查询 | `p0_queries.py`、P0Audit | property/监视器/assumption、安全与 bound 查询身份 | PASS 证明导入正确；SAT 自动对应源错误执行 |

原 E2E-SAFE 的 C0–C4 与八项 Γ 原文保留。L1 是开放块等价；L2 是实际
静态位点保证；L3 要求所有声明范围内实际激活和 Q 对应；L4 才消费完整
宿主与实际查询。ACTC 也仍依赖完整宿主适配。诊断模块不得绕过这些分层。

源语言边界继续使用 D2 的冲突排除：普通 C 并发读与 asm 并发写同一对象的
旧 P1 输入不能被当作无条件 C11 基准。非固定输入必须来自有效、类型正确、
执行期间不被并发修改且与 asm 写对象分离的对象。volatile 或一次编译成功
不能补足该前提。诊断算法若无法判断，报告源域 UNKNOWN/UNSUPPORTED。

## 2. 分类：现象、充分证据、结论强度

| 类别 | 可独立检查的最小证据 | 合理报告 | 不能自动报告 |
|---|---|---|---|
| GNU 输出/输入/tie/clobber 绑定 | 原源表达式/AST/LLVM 约束和定义使用的完整连接；不一致的具体字段或普遍式反例 | 接口契约不满足；有语义见证时才是接口差异 | 前端缺少规则就是 Clang bug |
| 输入值/地址/宽度差异 | 合法入口域、已连接的对象/参数、实际表达式及反例 | 开放地址/值/类型义务差异 | 唯一根因一定是操作数绑定，而非更早宿主计算 |
| 返回值传播 | 实际读响应→后续 LLVM/Q 表达式→监视器的完整依赖 | 跨调用/后继观察差异 | 仅一个不同的死寄存器就是可观察错误 |
| 缺失/额外共享读写 | 全部适用源操作、完整 Q 与语义可消费的边界；不存在合法消除证书 | 指定公共历史契约下事件集合不同 | 任意被优化掉的普通读取都是误编译 |
| 错误更新值 | 来源值、实际写表达式、完整候选空间下的共同开放见证 | 开放写值差异 | 反例读响应一定可由全程序 rf 实现 |
| RMW 配对/A/RMW 标签 | 两侧实际端点、标签与真实 pair 指针；不以打印名称配对 | 原子结构契约差异 | 源错误可达，或弱化排序必然破坏某个指定性质 |
| Fence/程序顺序 | 已解释的屏障种类、边界与完整事件关系、明确比较方向 | 排序充分条件不满足；在覆盖语义中可给结构差异 | 未支持 Fence 类型就判后端丢屏障 |
| 分支/条件事件 | 路径覆盖、guard 语义、活跃定义、条件端点完整性 | guard/活跃历史差异 | 未处理 CondJump 就将其当无条件或空事件 |
| 动态调用/线程遗漏 | 独立源激活域、实际 create/start/argument、双向覆盖 | 激活/实例契约差异 | 仅观察到两个 Q 线程就证明源最多两个 |
| ITE 导出截断/依赖缺失 | 实际表达式类与导出 schema/依赖清单不一致 | CAPTURE_UNKNOWN / 证据完整性失败 | 实际后端必然选错 ITE 分支 |
| 查询错绑 | 同次 property/监视器/assumption/栈、安全与 bound 的完整核对 | 查询身份错误；SAFE 门禁关闭 | worker 开放等价能覆盖查询，或最后 UNSAT 足够 |
| 未支持 C/未知别名/循环 | 缺少的语义定义、归纳摘要、生命周期证明 | UNSUPPORTED，记录具体义务 | 真实缺陷或“没有缺陷” |

分类是症状而非因果归因。比如先错误读取参数、再正确执行加法，与正确读取参数、
随后执行错误算术，可能产生完全相同的端点摘要。只看摘要不能区分两种实现原因。
只有更细的真实中间对象与已证相邻阶段关系才能缩短故障区间。

## 3. 三种反例不可混用

1. **候选映射反例**：存在输入使某一映射失败。其他映射可能成立。
2. **开放语义反例**：一个合法开放赋值排除所有覆盖完整的候选映射。
   它证明指定开放观察关系不同，不保证输入/读响应在当前宿主可达。
3. **完整执行反例**：合法源输入、完整源/目标路径和激活、统一 rf/co/fr、
   指定 CAT 约束、对象有效性、宿主/运行时和错误观察均经过独立验证。
   当前新增设计/草稿不提供这一升级；保留 `closed_program_counterexample=false`。

局部值 SAT、图属性失败、schema 缺失和全程序 SAFE 不能使用同一 BUG 标签。
程序级安全转移仍需要源错误→目标错误方向；编译器通常的目标行为⊆源行为
精化方向不能未经转换就用于验证器 TRUE 回传。双向开放等价是这里使用的强
充分条件，但不是所有正确优化都必须满足的必要条件。

## 4. “最早错误阶段”的边界

需要真实、相邻、同一接口与输入域的对象序列，并且前序每个区间都有已核验
等价证据，才能说第 k 个区间是**最早被证明不同的观测区间**。未捕获的中间
pass 不能自动定位；前序 UNKNOWN 时只能报告当前区间；前后错误互相抵消时，
最终等价也不能证明中间正确。

历史 raw asm 直接导入路径是 `原始 L → Q`。另行生成的正确 L' 只是对照，
不能插入该实际路径后宣称已证明错误发生在 L'→Q。捕获 ITE 不完整则停在
导出证据边界，不能将缺字段视作真实 Q 没有分支。

## 5. 本轮审阅到的原工具边界

ACTC 从全部效果单位有序匹配，并且全部共享值等式保留。它对目前受控
错误已经能够拒绝，新增诊断即使给出更丰富 JSON，也不等于新增检测能力。
其拒绝中有些是范围失败，不能全部统计为 TP。现有语义字段失败只有相应
候选和作用域的意义，并没有宣称已生成完整可执行源反例。

原固定接口仍使用有限强宿主检查和可核验来源；本轮没有引入外部 HCC 提供者。
未知对象/宿主不能移入新的隐含 Γ。完整 CK 客户端缺实际完整 Q、循环/回调/
对象/系统调用契约，不能靠诊断层自动消除这些前提。
