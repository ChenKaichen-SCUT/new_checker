# 最强已有方法组合：明确接口，而非概念拼接

本轮决定见 [00](00-delivery.md)。这是已有机制的可行性论证，不是新算法设计或
已实现工具报告。上一批材料原样保留。

## 1. 固定研究域

本轮只讨论以下域 D：

- x86-64、有效且对齐的普通 WB 内存，固定有限对象与位宽；无混合大小、
  设备内存、自修改、异常、动态分配、递归或循环。
- 每线程控制流为有限 DAG。直接调用可以展开为有限静态调用上下文。
  线程创建来自有限、无递归的创建结构；创建条件、参数、join 和运行时事件
  必须被解释，未知对象拒绝。这里的有限界是输入结构的一部分，不是实验展开界。
- 既有受限 GNU 接口及已定义宿主表达式；不声称完整 GNU C/C++。
  指针地址保持符号值，别名不能凭名字排除。
- 共享效果使用 R、W、locked RMW（含强 CAS 的条件写）及 MFENCE。
  CAS 失败仍有 A 标记的读；成功写须指向实际读端点。
- 对象是原始 S、真实 L/L′、同次求解的实际 Q；从源语义得到的 `P_S`
  与从 Q 独立解释的 `P_Q` 不得互相抄写预期效果。

源/目标均解释到基线固定版本 `tso.cat` 的端点模型 **T**，包括其依赖与框架：

```
H = po-loc | rf | co | fr
K = (po & ((R×M) | (W×W)))
    | (po & (W×R) & ((M×A) | (A×M)))
    | (po ; [MFENCE] ; po)
T: acyclic(H)
   empty(rmw & (fre ; coe))
   acyclic(K | co | fr | rfe)
```

这里关系中的 M 是内存读写事件集合。对排序检查可将 fence 关系限制到内存端点；
纯节点和 fence 本身不作为读写端点。创建/join 等框架语义还必须由程序解释保留。
对这里列出的公理，这种限制不丢失环：通信边的两端都是内存事件；若一个环经过
非内存节点，其邻接边只能来自同线程的 fence/po 路径，可压缩成内存端点间的
fence 边。只由这些非内存节点组成的环又会违反同线程 po 的无环性。
此理由不自动适用于含额外原生关系的其他 CAT 模型。
参见[基线精确对象定义](../revision/02-objects-and-obligations.md)。

[x86-TSO 原文 Theorems 3–4](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-745.pdf)
证明其操作与公理定义对应，支持 locked 指令；这不是对本项目特定 Java 编码器、
GNU 宿主语义或 CAT 文件版本的自动证明。使用 T 使下面的推导有确定语义对象；
从真实 x86/GNU 到 T 的桥接仍显式列入证据或 TCB。

### 安全观察及方向

固定有限安全监视器，观察包含错误位以及事先声明的外部输出。
断言错误在语义公式中是可观察状态，不作为 C 的任意 UB 或 PAA 的“错误/发散”
合并类别。不要求终止/公平性，不观察时间、纯指令数或 fence 数。
必须包含达到错误的合法有限前缀，不能只编码正常返回。

本轮核心要求为：

`Obs_T(P_S) ⊆ Obs_T(P_Q)`，

所以 Q 安全蕴含 S 安全。源 asm 的活跃输出不是都要单独成为外部观察，但必须
通过宿主数据/控制语义正确影响后续行为。要宣称目标反例真实，另证反向或提升
具体反例。两向都检查才可称 EXACT。

“封闭”指完整有限程序已经含所有本轮允许的线程和宿主上下文。
这不限制它有几个 asm，也不要求来源唯一；但不能直接外推为任意未给定上下文。
通用上下文结论另按第 5 节处理。

还必须区分两个验收等级。单向 SAFE 允许过近似，可能接受丢失排序或原子性的
目标，因为它增加行为。若同时要求忠实保留 RMW/Fence，则不能只交付这个等级：
应检查反向包含，并核对声明的转换规则中的真实 pair、失败读 A、guard 和排序
契约，或给出替代规则的语义证明。[02](02-minimal-obstacle-and-lemma.md) 给出
一种明确契约；G 的 QBF 检查本身不自动恢复已删除的 pair。
即使封闭程序对固定监视器双向等价，也不是任意上下文下的原子性等价。
本报告所称“六项可由已有机制组合处理”，包含这些额外规则/契约义务，
不把单个 SAFE 公式当成六项保证的总证书。

## 2. 强组合 G：全局执行包含兜底

这条组合选择已有机制承担其真正能承担的职责；不要求把每个被审计工具都放在
接受路径上。Stellite/SEQ 的不适用部分不能被当作一个“可靠历史 oracle”。

| 层 | 输入→输出 | 已有机制 | 最终接受前必须成立 |
|---|---|---|---|
| 真实对象解释 | S/AST/L/L′/Q→两侧有限带类型程序 | 基线接口/对象解释；Isla 等 ISA 事件语义思路 | 捕获忠实、宿主及错误完整、模型固定；这些适配尚未全部实现 |
| 候选对齐 | 两侧 DAG/表达式→候选路径、数据与调用关系 | PAA/JTFG；有限静态候选搜索 | 只提建议；不得从来源提示删掉合法源路径 |
| 访存候选 | 访存/guard→匹配、可交换/删除建议 | VALID CIM/MD | C11/LLVM 规则不得未经证明当 TSO 安全方向规则 |
| 全局语义 | 两侧程序→`F_S(i,z_S)`、`F_Q(i,z_Q)` | 有限公理执行图编码、符号精化 | 所有 guard、值、创建、配对和全局 rf/co 均忠实表达 |
| 见证与认证 | 包含公式→统一见证或拒绝 | QBF/Skolem 合成及独立证书检查 | 正确量词、全部目标选择一致；不得只相信 solver 的 TRUE 字符串 |
| 可选快捷证明 | 已检查实际映射条件→模型关系结论 | Kater/KATI、既有 TSO 模拟/规则 | 使用已证明规则的准确方向和所有实例前提；不能替代数据与覆盖 |

这并非声称当前源码已经能直接连接这些模块。它指出无需发明新的对应理论即可
构造一个**有效、可能昂贵**的有限判定基线，并明确尚欠哪些工程与语义适配。

### 完整执行变量

公共输入 i 固定对象布局、初值与调用参数。每侧 z 至少表示：

- 全部可达分支与可能激活，合法有限前缀的截取及创建/join 条件；
- SSA/局部值、每个潜在读的独立响应、每个动态出现的执行条件；
- 全部实际执行的读写/fence、同线程顺序、真实 rmw 配对；
- 单个全局 rf 和每地址 co，以及由它们计算的 fr/rfe/fre/coe；
- 错误监视器和外部输出。

`F_P` 包含类型/表达式/路径良构、每个读的供值、co 良构及 T 的全部公理。
非执行节点不能贡献访存或满足另一个读的 rf。初始化写也属于良构性条件。
源侧潜在出现从源调用和创建结构产生，不能用目标发现的数量代替。

没有循环不代表每个静态源点执行一次：内联/多调用产生有限上下文身份，
多 worker 产生有限激活身份，分支可令其不执行。全部身份进入有限公式，
而不是先要求源静态节点与 Q 静态节点数相等。

### 接受公式与独立见证

所需有效式为：

```
∀ i,z_S. Legal(i) ∧ F_S(i,z_S)
          ⇒ ∃ z_Q. F_Q(i,z_Q) ∧ ObsEq(i,z_S,z_Q)
```

固定有限域可位化为 QBF。可由已有求解/合成机制生成候选布尔函数向量
`f(i,z_S)`；检查器重建公式，证明：

```
Legal(i) ∧ F_S(i,z_S)
∧ ¬(F_Q(i,f(i,z_S)) ∧ ObsEq(i,z_S,f(i,z_S)))
```

不可满足，并检查 f 的输入依赖与语法。f 是完整目标执行的统一离线见证，
可依赖源全执行选择；不冒充在线调度器或编译器的因果策略。
全局 co/rf 只产生一份，不允许每个区域独立生成互不相容的版本。

这是标准 Skolem 证书方式。已有 [QBV/Squolem](https://www.cprover.org/qbv/)
及 [QBF 证书文献 §1–2](https://drops.dagstuhl.de/storage/00lipics/lipics-vol305-sat2024/LIPIcs.SAT.2024.1/LIPIcs.SAT.2024.1.pdf)
明确支持这类独立验证；本轮没有运行任何求解器或生成实例证书。
预处理引入的辅助变量/量词必须保留依赖与等可满足性的证明，不能自由交换量词。

**标准可靠性推导。** 任取合法源执行 g。语义忠实性给出满足 `F_S` 的赋值 z。
已验证的代入公式给出 `F_Q(i,f(i,z))` 和相同观察；目标语义忠实性将其解码为
合法目标执行。故源每个观察在目标存在。这个推导不需要输入一个正确来源映射，
也不要求内部事件双射；需要的是完整且正确的语义编码。

有限真值域保证这种函数在包含成立时存在，但证书可能很大。
这一存在性/判定性是逻辑结论，不是用枚举或实验替代证明，更不表示已有可用性能。

### 对 μ 的诚实解释

G 的 μ 可以是由 f 诱导的执行关系和候选路径说明；它自动选择一个充分目标见证，
不承诺每个源操作都有可观察目标节点，也不声称恢复真实历史来源。
若还要求较小、可读的逐操作来源证书，那是附加要求，不能由全局包含免费获得。
但把共享见证写成因子/片段形式的研究也已有
[Skolem Functions for Factored Formulas](https://arxiv.org/pdf/1508.05497)，
故“分解全局存在量词”本身不能直接当作新机制。

### 跨模型“编译正确”不足以拼接

即使已知 `TSO(S)⊆A(S)`、`TSO(Q)⊆A(Q)` 和 `A(S)⊆A(Q)`，
仍不能推出 `TSO(S)⊆TSO(Q)`。集合实例：
`TSO(S)=A(S)={bad}`，`A(Q)={bad,ok}`，`TSO(Q)={ok}` 即否定该推论。
这是量词/包含方向反例，不是声称某具体模型恰取这些集合。
因此，把 Stellite/SEQ 两侧都编译到 TSO，并未自动得到所需保证；
还需另一侧的反向桥接、等价或直接 TSO 证明。

## 5. 真正的上下文定理已经解决哪种组合问题

假定在**同一 T 与观察**下，已有 `∀C. Obs(C[A_j])⊆Obs(C[B_j])`，
且每次替换后仍在允许上下文域内，接口、前提、RMW 边界都满足。
在有限程序中依次替换 n 个位置，得到 P0,…,Pn。
每次取其余程序为 C，得 `Obs(P_{j-1})⊆Obs(P_j)`；
包含传递给出 `Obs(P0)⊆Obs(Pn)`。

这个标准证明允许每一步选择不同完整执行见证；不要求把独立局部 co 强行拼在
同一个原始图上。Stellite 正文 §3.2 已指出多块可依次变换。
因此上一批的“全局见证拼接”只能作为**不充分局部判据的风险**，
不能被当成对这些已有上下文定理的反例。

若规则依赖只在原程序成立的局部不变量，必须证明每个中间程序也满足它；
若某个真实 RMW 被切断，必须扩大区域或验证允许这种边界的定理。
没有满足这些条件，组合未成立；但首先应归类为定理前提未满足。

## 6. 可行性与成本的界限

G 没有逐片段环境兼容性 oracle，语义和证书接口可有限编码；
但本项目尚无完整编码器、QBF 接线、证书验证器或工程正确性证明。
不能把这份论证称为“已经实现可靠组合”。

若总潜在事件数 n、总数据位数 b，rf/co 可用二次数量布尔变量表示，
闭包/无环检查可用多项式大小编码。无环程序的路径数仍可指数增长，
全局包含又有 `∀∃` 交替，见证函数可能很大。符号编码不必枚举 n! 个 co；
不能用朴素枚举上界声称所有已有方法都付出该成本。

局部证明可以避免在每个候选上求解全局 rf/co，但需要合适且已证明的充分条件。
下一文审查一个最小条件，并检验它是否真正超出已有关系方法。
