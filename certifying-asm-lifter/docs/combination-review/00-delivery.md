# 已有方法组合可行性审查：交付与决定

日期：2026-10-20。基线：
`58dccfad29c9285f4280b90e6372fd202d1d2483`。
本轮仅做文献与静态审阅、解析推导及最小候选引理；不设计完整新算法，
不修改认证器，不运行编译、求解、测试或转换实验。

## 决定

**No-Go（本轮候选的独立算法创新）。**

在固定 x86/TSO、有限位宽/对象、有限无环控制流与有限线程范围内，没有找到
必须增加新算法机制才能表达并认证的转换。最强已有路线是：独立构造完整程序
执行图语义，用标准行为包含与可独立检查的全局见证作最终依据；已知程序对齐、
访存匹配与模型关系检查用于搜索和分解。它有明确的形式接口，不是直接可运行的
GNU→Dat3M 工具；真实输入语义与工具对象的桥接仍需落实。

这一决定并非“有限问题可判定，所以不可能有创新”。更有效的分解仍可能有价值，
但本轮最有希望的窄候选——带执行条件的跨片段排序检查——能够归约为已知路径
覆盖加关系包含，且与 CompCertTSO 的屏障优化重合。没有证明成本优势或表达力
分离，不能把接口实例化称为新算法。

## 相比上一批，收紧了什么

1. **共享环境并非一律需要新拼接算法。** 真正的上下文精化可通过有限次替换及
   传递性组合。Stellite 已具有这样的定理；不能省掉其同一环境和适用模型前提后，
   再把产生的问题称作新缺口。
2. **给出了不留历史 oracle 的强基线。** 完整有限执行图包含可编码为
   `∀源执行.∃目标执行`；已有 Skolem 证书机制可让检查器独立验证统一见证。
   来源提示只影响候选搜索，不能限制被包含的源执行域。
3. **分离了“模型不适用”与“需要新方法”。** SEQ 的 PSna、Stellite 的 RA
   不能直接当固定 TSO；但这项桥接缺口本身不证明需要新算法。
4. **闭合了一个窄的关系推论。** 保持全部读写端点、真实 RMW 配对与活跃值，
   并在正确方向检查 TSO 排序关系包含，可以允许 Fence/纯节点非双射。
   这是明确条件下的解析推论，不是已实现的新认证能力或独立创新定理。

## 结论的强度

- **逻辑推导**：标准包含证书的可靠性、有限上下文替换的传递性、固定模型下的
  端点保留/排序包含推论；完整前提写在正文。
- **尚未建立**：一般非双射共享读写的廉价组合检查、该组合的工程实现精化、
  多调用真实 GNU→实际 Q 的新增验收、搜索成本优势。
- **没有本轮实验发现**：例子都是解析构造或对已有源码的引用，不是新运行材料。
- **仍有外部边界**：源语言/ISA 桥接、捕获器、编码器与证明核；Hetrify 系列的
  全文缺口沿用上一批，不用它支持排除性创新结论。

可以保留**工具/系统贡献候选**：将真实 GNU 接口、实际编译结果、最终求解对象和
转换证据自动连接，并做到覆盖完整、失败关闭、可独立复核。
目前没有足够材料判断达到可发表水平，尤其不能靠旧 CK 单例或后端 PASS 推出。

本轮到此停止，等待审阅。若后续获准，应先决定是否转为上述工具/系统路线；
没有依据自动进入“新算法实现”或大规模实验。
