# 最小障碍、受限引理与已有机制的边界

基线、固定域 D、观察和模型 T 均沿用 [01](01-strongest-combination.md)。
以下是解析审查，未增加实现或运行实例。符号程序不是捕获的 Clang/Dat3M 输出。

## 1. 四类障碍不能互换

| 具体障碍 | 分类 | 已有路线能做什么 | 仍欠什么；本轮判断 |
|---|---|---|---|
| 两个相同宏展开的 asm，旧检查器要求唯一存活位置 | 工具实现不支持 | PAA/JTFG 的联合路径/关系候选不要求恢复唯一历史来源；G 可直接比较全程序 | 真实对象解释和候选接线；不是新定理障碍 |
| 行号/来源提示错误，CIM 又依赖块对应 | 部分算法前提不满足 | 不用该硬过滤；由完整源域和全局 G 验证语义候选 | 不能把 VALID 原工具当作无提示完整算法；也不能据此排除其他已有搜索 |
| Stellite/SEQ 的结论想直接应用于 TSO | 定理前提不满足 | 它们提供组合接口；固定 TSO 可用直接图语义或已有 TSO 模拟 | 缺少模型/观察桥接；不是“RA 定理自动适用于所有 CAT” |
| 每个区域各找一个 rf/co，最后不能合并 | 不充分的判据 | 同模型的真正上下文精化可逐次替换；G 用一个全局见证 | 必须修正量词/环境接口；不是对已有上下文定理的反例 |
| 成功 CAS 有两个端点，失败只有一个执行端点 | 旧实现或规则实例化问题 | 带 guard 的执行语义、真实配对和全局公理足够表达 | 原子标签、条件写、输出与覆盖不能遗漏；不需发明“条件存在”概念 |
| 多个片段之间删除冗余 MFENCE | 局部判据可能太强 | 已有 TSO fence 优化；路径覆盖＋关系包含可给充分条件 | 下面的窄引理闭合，但没有独立新机制 |
| 同一次执行中合并/删除共享读写 | 可能合法，也可能本来错误 | G 可判包含；特定上下文定理/模拟可以证明合法子类 | 不能凭局部值相同推合法；当前窄引理不涵盖 |
| G 的完整包含代价高 | 潜在成本问题 | 符号共享、关系检查、局部规则、因子化见证均已有 | 本轮无成本分离证明或测量；不能宣称所有已有方法必然过慢 |

最值得尝试的候选是：**不恢复唯一来源，检查所有实际路径的内存端点覆盖，并
保留跨区域的排序足迹，允许 Fence/纯节点变化。** 但要判断是否创新，必须先写出
它真正需要的条件。下面显示这些条件已能用现成路径覆盖和关系蕴含机制表达。

## 2. 最小问题 F：非双射总事件，保留读写端点

给定 D 内的完整源程序 P 和目标程序 Q，允许纯计算、分支、Fence 节点增删、
复制、合并。不同互斥源分支上的静态 asm 可对应同一目标静态位置。
**不允许在同一次执行中合并两个执行的内存读写端点，也不允许消除执行的共享
读写端点。** 这是窄问题的实质限制；一般非双射读写仍归 G 或其他专门规则处理。

源 locked 指令的端点展开来自独立参考语义；目标来自真实 Q。不能为了建立
端点双射而把源效果定义成目标已有节点。初始化写、创建的线程和宿主共享效果
也属于覆盖域；不是只取“看起来像 asm”的事件。

一个开放线程执行记录包含：

- 输入、创建参数、分支条件、所有局部值和每个读的独立返回值；
- 实际执行的内存端点、类型/宽度/地址/值/A 标签、线程身份、po 和实际 rmw；
- Fence 位置、live-out、错误监视器和约定的外部输出。

它暂不选择 rf/co；其读值不被限制为某个局部内存数组最后一次写入的值。
合法全局执行再通过 rf/co、供值和 T 公理约束这些开放响应。
安全前缀在宿主/指令语义允许的观察点截取，不能把成功原子操作截成半个 RMW。

## 3. 可以独立检查的证书前提

以下记候选证书为 ν。**这些是需要实际验证的义务，不是给输入增加未经检查的
正确映射假设。** 本轮没有实现其检查器，也没有声称基线已经满足它们。

**F1，真实对象与语义。** 两侧捕获和解释忠实，采用同一个 T 和输入域；
创建/join、宿主表达式、断言、外部观察都已解释。作用域外对象拒绝或明确留在
条件定理的 TCB 中，不能生成无条件端到端结论。

**F2，完整开放路径模拟。** 从每个合法源入口和每组开放读响应出发，ν 提供真实
目标路径及局部状态关系；检查其入口成立、路径转移有效、出口/观察保持。
每个源出边要么被覆盖，要么有从真实语义推出的不可行证明。无环性保证有限
进展，不允许通过源/目标空边循环躲过出口。线程激活与子线程参数同样检查。
必须包括合法错误前缀；不能从“原程序安全”导出路径限制。

F2 可以用 PAA/JTFG 式关系边、guard 覆盖、状态关系检验表达，或直接检查有限 DAG
公式。这是有限明确的义务，不调用未定义的“所有历史正确”oracle。
开放响应全称化是比仅要求合法 T 执行更强的充分条件，可能拒绝某些合法优化。

**F3，路径内的全覆盖端点关系。** 对 F2 的每对路径，检查一个实际执行端点间的
双射 f，包括初始化写。f 保持线程、R/W、地址、位宽、值、A 标签和实际 rmw；
保持所有内存端点之间的同线程 po。不能只检查候选列出的端点：
两侧各自由独立解释器产生的全部执行读写集合必须等于 f 的定义域/值域。
线程身份可以有已检查的重命名；创建因果和 join 保持。

不同路径可用不同 f，静态位置不要求双射。候选在互斥分支上共享目标节点并不
违反 F3；同时执行的两个源端点抢占一个目标端点则违反 F3。
若拆分区域，跨区 rmw 仍须在完整 f 上检查，不能随分区丢掉。

**F4，完整边界排序条件。** 用 f 将源关系重命名到目标端点域。令

```
B = (po & ((R×M) | (W×W)))
    | (po & (W×R) & ((M×A) | (A×M)))
F_P = (po ; [MFENCE_P] ; po) restricted to M×M
F_Q = (po ; [MFENCE_Q] ; po) restricted to M×M
K_P = B | F_P
K_Q = B | F_Q
```

F3 使两侧 B 相同。要求对**每对被覆盖的开放路径**：

```
K_Q ⊆ K_P⁺.                       (SAFE)
```

这里 `⁺` 为非空传递闭包。边界检查涉及同线程前缀/后缀的所有相关内存端点，
不能只比较区域内部。证书若采用 symbolic guard，则包含式在执行条件下全称成立，
不能把条件边无条件合并。

等价认证另需反向的 F2/F3，以及 `K_P ⊆ K_Q⁺`。
额外添加源没有的目标排序通常**缩小**行为，因此不自动满足 SAFE。

**F5，全局框架。** 无变化上下文使用恒等关系，但其共享事件仍在全图中。
除了列明的 T 公理，若实际模型、运行时、验证属性还有其他约束，就必须证明其
输送；否则本引理不适用。不能省略 creation/join 或额外 CAT 约束后仍称为实际模型。
下面证明仅针对所列 T 及已保持的框架。

## 4. 受限引理及解析证明

**引理 F（端点保持下的 TSO 排序包含）。**
若 F1–F5 都成立，则

`Obs_T(P) ⊆ Obs_T(Q)`。

若反向条件也成立，则观察等价。这不要求全部事件节点同构；
但要求每次执行的全部内存读写端点及 rmw 保持。

**证明。**

1. 任取一个合法源全局执行 g，包括被观察的错误前缀情形。
   把其实际读值代入 F2 的开放响应。F2 给出真实目标线程路径、相同合法激活
   及相同观察。F3 给出所有执行端点上的 f，既无遗漏源读写，也无额外目标读写。
   分支和活跃输出由路径/状态关系保持，不是事后根据 rf 调整程序。

2. 在这**同一个**全图上定义
   `rf_Q=f(rf_P)`、`co_Q=f(co_P)`。f 保持地址、值、线程及初始化写，
   所以每个目标读恰有类型/值正确的供值写，每地址 co 仍是全部执行写上的严格
   总序。由 `fr=rf⁻¹;co` 及同/异线程限制的定义，
   `fr,rfe,fre,coe` 全部随 f 输送。这一步避免了任意拼接局部环境见证。

3. po-loc 保持，因此
   `po-loc_Q|rf_Q|co_Q|fr_Q` 是源同一关系的重命名。源 coherence 无环，
   目标也无环。真实 rmw 保持，故
   `rmw_Q & (fre_Q;coe_Q)` 仍为空。
   失败 CAS 没有执行写/配对，但其读取的 A 标签仍参与 B；证明没有删去它。

4. 假设目标 `K_Q|co_Q|fr_Q|rfe_Q` 有环。每个 K_Q 边按 F4 替换为
   非空 K_P 路径；其余边按第 2 步原样重命名回源。得到源
   `K_P|co_P|fr_P|rfe_P` 中的非空有限闭合游走；有限有向图中该游走包含环，
   与源 T 一致性矛盾。故目标通过最后一个 T 公理。

5. F1/F5 保持其余框架，第 1 步保持观察，因而构造了与任意源观察相同的合法
   目标执行。得到包含。反向条件成立时交换两侧重复论证，得等价。证毕。

这是一条闭合的**条件引理**：其数学结论不依赖实验；真实编译对象是否满足 F1–F5
仍需独立验证。它没有证明现有代码已实现 F2–F5，也没有证明任意 GNU/x86 到 T
的完整桥接。

### 为什么这不是本项目的新算法成果

核心论证是保持通信关系、用关系包含输送无环性；候选/覆盖使用标准关系程序验证。
这与 [Kater 的关系检查](https://plv.mpi-sws.org/kater/paper.pdf)、
[KATI 的模型约束充分条件](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.CONCUR.2024.33)
在方法上重叠。Kater/KATI 不替我们检查实际地址/值/覆盖，但增加这些对象适配
不等于出现新关系算法。下一例甚至已有专门的 TSO 屏障优化规则覆盖。

## 5. 非平凡例子：多个真实 asm 模式与条件 RMW 后的冗余 Fence

下面是**待认证情形的语义设计例**，不是本轮运行的新 C/LLVM/Dat3M 实例：

```
worker 0:
    W(x, 1)
    if b:
        old = locked_CAS32(z, expected=1, desired=2)
    else:
        old = locked_FAA32(z, 1)
    MFENCE
    r = R(y)
    monitor(old, r)       // old 真正参与安全观察/后续控制

worker 1:
    W(y, 1)
    MFENCE
    s = R(x)
    monitor(s)
```

两侧完全保持分支、RMW、输出和宿主；目标只删除 worker 0 的 MFENCE。
`b` 可取两值；CAS 可成功或失败。两个分支可源自不同宏/内联上下文；
来源提示是否唯一不参与本证明。各路径的真实语义/实例覆盖必须由 F2/F3 给出，
不能手填寄存器映射或把这个图当作实际 Q 的替身。

这些操作模式不是为证明杜撰的新指令：
原始 CK x86-64 头文件包含 `ck_pr_faa_32` 的 `xaddl`、CAS 及 `mfence`
生成模式，见[本仓库保留的 CK 来源与版本](../15-ck-acceptance.md)
以及[上游头文件](https://github.com/concurrencykit/ck/blob/8f0847cfe57b1479d8e63b89028831d94d0e4d26/include/gcc/x86_64/ck_pr.h)。
但本轮没有取得“固定 Clang/Dat3M 确实执行了该 Fence 消除”的新产物；
不能把现实所需的模式审查升级成已经通过的真实转换。

**排序推导。** 任取被删除 Fence 的边 `(u,v)`，u 在它之前，v 在它之后。
每条分支都经过带 A 的 RMW 读 a；该原子操作与 Fence 之间没有其他共享写。
若 u 在 a 之前：

- u 是读，则 `u B a` 来自 R×M；
- u 是写，则 `u B a` 来自 W→R 且 a 带 A；
- a 是读，故 `a B v` 对任意后续内存 v 成立。

若 u 就是 a，则已有 `a B v`。若 u 为成功 RMW 的写 w，
对 v 为写用 W×W，对 v 为读用 w 的 A 标签，均有 `w B v`。
若允许 a 与 Fence 之间出现普通读 u，它也直接以 R×M 给出 `u B v`。
失败路径没有 w，不需要补一个虚构写。故 `F_P` 中被删边都在 `B⁺` 内。
其余排序不变，两侧 K 的闭包相等。满足 F1–F5 的真实对象因此可得 EXACT。

这个例子超出旧检查器的多 asm/Fence 接入范围，且对失败路径、活跃输出与
边界排序有实质要求。**它不区分我们与最强已有方法。**
[CompCertTSO 扩展稿 §6 的 FE1](https://fzn.fr/projects/wmc/readings/compcerttso-long.pdf)
已经用“所有前驱路径上有 fence/原子操作，之间无写”的分析消除冗余 fence。
本文补清本项目的行为方向和实际端点前提，不能把既有规则重新命名为创新。

## 6. 留下的真正问题及停止理由

一般非双射读写会破坏步骤 2 的通信关系直接输送，需要更强的模拟或全局见证。
但这不是一个已成立的独立创新缺口：G 可以表达，已有上下文方法覆盖部分情形；
尚未找到既合法、真实需要、又不能合理复用这些机制或具有已证成本分离的最小例子。

因此本轮不提出“唯一必须新增”的核心机制。F 是值得复核的受限充分条件，
并非新方法立项的依据。若以后研究更便宜的局部证书，必须先展示它相对已有
TSO 规则、关系检查、全局符号包含及因子化见证的具体差别，再提出新算法。
