# 对抗分析、成本边界与论文决定

本文件中的反例均为逻辑构造，未编译、未送求解器、未执行测试。
它们攻击明确简化后的判据，不声称推翻具有完整前提的 Stellite/SEQ 等定理。
模型、观察、行为方向见 [01](01-strongest-combination.md)；
窄引理及其 F1–F5 见 [02](02-minimal-obstacle-and-lemma.md)。

## 1. 跨片段共享环境：局部存在不等于全局存在

两个线程都对初值 0 的 x 执行一次 locked FAA(+1)。
孤立看每个区域，都可选“读初值 0、写 1”的局部执行。
若把它们同时拼起来，则两个写之间 co 必须择一：

```
init_x co w1 co w2    或    init_x co w2 co w1
```

取第一种。r2 从 init_x 读，所以 `r2 fre w1`；且 `w1 coe w2`。
因此 `(r2,w2)` 同时属于 rmw 和 `fre;coe`，违反原子性。
另一种次序对称。两份局部见证都存在，合起来却不存在。

**结论。** 不能把 `∀片段.∃环境见证` 换成 `∃共同环境.∀片段`。
G 用完整全图的单个见证避免此错误；F 用同一源 rf/co 输送避免它。
真正的上下文精化已经量化相同环境，可按有限次替换组合，
不要求以上错误的局部独立拼接。这不是对 Stellite 的反例。

## 2. 只保留最终内存值会漏掉源错误

源线程 `W(x,1); W(x,2)`，目标只保留 `W(x,2)`。
另一个线程读取 x，并在值为 1 时进入错误。
源有先执行第一写、观察线程读取、再执行第二写的 SC 执行，因此也是 TSO 行为；
目标没有值为 1 的供值写。两侧线程结束后 x 都为 2，仍不能推出 `S⊆Q`。

这是**不正确转换在安全转移方向上的反例**，不是“尚无算法处理的合法转换”。
全局包含检查应拒绝；F3 也拒绝遗漏的写。

### 即使两次写的值相同，也不能任意合并

初值 x=0：

```
T0: W(x,1); W(x,1)
T1: r1=R(x); W(x,2); r2=R(x)
```

源存在 SC 次序：T0 第一写、r1=1、T1 写 2、T0 第二写、r2=1。
若目标把 T0 两写并成一写：

- r1=1 要求从该唯一写 1 读取；
- T1 的读→写顺序与 coherence 迫使该写 1 在 T1 写 2 之前；
- r2 位于 T1 写 2 之后，不能再越过该同地址新写读到旧写 1。

形式上若 `w1 co w2`，`r2 fr w2 po-loc r2` 成环；
若 `w2 co w1`，`w1 rf r1 po-loc w2 co w1` 成环。
两种 co 均不允许 r1=r2=1。故断言 `!(r1==1 && r2==1)` 的源错误会被目标隐藏。

Stellite 讨论的重复写删除用于常规优化方向 `Q⊆S`；
不能不核对方向就拿来转移目标 SAFE。这一例同时说明“非双射”不天然代表应接受。

## 3. 区域内部正确但跨区域顺序错误

源 T0：`W(x,1); W(y,1)`；目标反过来。
观察线程 T1：`r=R(y); s=R(x)`，初值均为 0。
目标有顺序执行产生 r=1,s=0；源由于 W→W、R→R 及通信关系成环而禁止它。

如果认证目标是 EXACT 或目标反例真实性，仅分别匹配两个单写区域会误收。
若认证目标只有 SAFE，还须检查相反的丢失行为：用
`r=R(x);s=R(y)` 观察线程可区分源允许、目标禁止的 r=1,s=0。
不能仅找到目标多了行为就宣称破坏 `S⊆Q`。
F3 保持全部内存端点 po，明确排除此交换；G 按实际选择的方向检查。

## 4. 错误的 RMW 拆分与失败 CAS 排序

### 有 A 标签，不代表配对正确

第 1 节两个 FAA 若都拆为普通读取和写入，且仅保留标签却删掉真实 rmw，
可以令两读都读到 0，而无原子性条件阻止。局部表达式和 A 标签都可相同。
因此 rmw 的实际端点关系必须独立核对，不能由汇编文本或预期事件形状推断。
F3 和 G 都直接包含这个关系。

### 失败 CAS 的 A 标签仍有排序效果

初值 x=y=z=0：

```
T0: W(x,1); locked_CAS(z, expected=1, desired=2); r=R(y)
T1: W(y,1); MFENCE; s=R(x)
```

考虑 CAS 读取 0 而失败。其读 a 带 A，因此 `Wx B a B Ry`；
另侧 `Wy F Rx`。若 r=s=0，就有
`Wx → a → Ry fr Wy → Rx fr Wx` 的 TSO 全局环。
错误目标把失败读变成无 A 的普通读，会丢掉 `Wx→a`，普通 store buffering
次序可允许 r=s=0。

这首先破坏 EXACT/反例真实性；由于删除排序可能只增加行为，
不能单靠这个例子指认 SAFE 方向错误。保留 A 是本项目要求的严格语义契约，
F3 因而比最低限度单向 SAFE 更强。G 若只检查 SAFE，可能合法地接受这类过近似；
如用户要求同时保留原子/排序语义，必须附加该契约或检查双向包含。
**不能混淆“足以保守证明安全”和“忠实转换”。**

### 条件写 guard 必须跟随读值

强 CAS 的写存在条件是实际读取值等于 expected。
把失败分支也执行写，或者成功分支不写，都改变供值/后续读及 old 的关联。
在 F2/F3 中必须对同一开放响应证明 guard、old、写值和实际配对一致。
仅让每条路径分别“找到一个符合预期的读值”会错误交换量词。

## 5. Fence 候选引理最容易被过度推广的地方

把 [02 的例子](02-minimal-obstacle-and-lemma.md) 改成：

```
W(x,1)
if b: locked_CAS(...)
MFENCE
R(y)
```

若 b=false，已没有原子操作提供 W→R 排序。删除 MFENCE 后，
配合另侧 `W(y,1);MFENCE;R(x)`，可出现原来禁止的两读 0。
把“存在一条路径经过原子操作”当作“每条可执行路径都经过”不成立。
F4 的带条件全称检查拒绝；CompCertTSO 的 FE1 也要求所有路径的前提。

另一过度推广是允许原子操作与 Fence 之间有新的普通写 u。
u→后续读的顺序不能借助位于 u 之前的原子操作建立；F4 的缺边直接暴露。
F 的证明并未允许任意 Fence 消除。

## 6. 来源、活跃输出与实例覆盖不能由局部匹配推出

**交换两个返回值。** 同一线程连续两次 FAA，独立匹配两次加法都正确，
不代表可交换其 SSA/后端寄存器用途。存在第一次返回 0、第二次返回 1 的执行；
后续 `assert(first==0)` 能区分错误绑定。F2 的后继状态关系必须连接真实
源/目标变量；检查其公式与读响应依赖，不能手填“哪个寄存器就是返回值”。

**遗漏 worker。** 源创建两个 worker，目标只有一个；目标事件集合内部仍可完全
匹配。若源潜在出现集合是从目标反推，就会漏掉第二次执行。
F2 的源创建/激活推导及 F3 的完整定义域必须独立来自源结构。
有限线程并不等于可省略覆盖；分支创建要保留其 guard 和参数。

**不可信提示。** 只在被提示的 asm 上检查语义，未被提示的 asm 静默忽略，
会让坏提示改变源行为域。提示只能排序候选；每条源路径和每个执行端点仍来自
源解释。若提示错误但另一个候选语义充分，允许接受的是语义关系，不是“历史来源
已恢复”。两个行为完全对称的位置可能根本无法唯一恢复来源。

**自选不变量。** 证书写 `b=true` 可以隐藏第 5 节的反例。
必须证明该条件由合法输入及真实前缀推出；不能以候选需要为由增加。
组合多个变换时，若某条规则依赖前缀不变量，还必须在每个中间程序证明它；
仅在原程序为真不足以应用有限替换定理。

**切断 RMW。** 若一个区域只有读、另一区域只有写，独立区域定理可能不适用。
Stellite 对其 LL/SC 边界已有明确限制；不能忽略后声称发现其组合漏洞。
F 选择全图真实配对；局部实现可以扩大区域，或另给有效的边界定理。
需要新增这样的边界定理并不自动意味着已有全图路线无法处理该输入。

## 7. 全局 G 的风险：能表达不等于已可用

G 的标准见证检查只需验证一个全称代入公式；寻找见证仍可能很昂贵。
以下瓶颈必须保留，而不是在 No-Go 判断中隐藏：

1. 输入程序的语义编码必须忠实于真实 GNU/宿主与最终 Q，尤其是 UB、错误前缀、
   地址别名、线程创建和实际配对。论文关于公式/自动机的可靠性不证明这个编码器。
2. `∀源执行.∃目标执行` 允许见证依赖源整个执行，因此是离线行为包含；
   若要求因果在线策略，会是不同且可能更强的问题，本轮不偷换。
3. 覆盖很多路径与并发关系时，变量量和见证大小可能很大。有限 DAG 本身也可以
   简洁表示指数多路径；不能以路径展开为唯一实现，再声称存在必然指数输出。
4. 把全局见证分片需要保留共享变量依赖；[既有因子化 Skolem 研究](https://arxiv.org/pdf/1508.05497)
   已研究类似逻辑问题。仅提出“用 CEGAR/摘要降低成本”没有形成独立机制。
5. QBF 预处理/求解器的 TRUE 不是完整转换证据。
   要验证实例绑定、公式重建、量词依赖、见证和证明；使用可信 SAT 判定器还是
   小证明核也应明确标注。本轮只说明已有证书方法可复用，没有实现它。

**本轮没有成本比较数据，也没有针对这些转换的下界/复杂度分离定理。**
F 不求解 rf/co，只检查路径关系和 B/F 的包含，可能有实用价值；
但这正是已有局部规则/模型关系方法的价值，不能据此宣布超过它们。

## 8. 六个问题的审查结论

| 用户要求 | 最强已有组合的结论 | 是否证明需要独立新算法 |
|---|---|---|
| 多 asm、多次内联 | 独立源域＋路径/关系候选＋全局包含可表达；原型适配尚缺 | 否 |
| 缺失/错误提示 | 提示不进最终语义前提；候选独立检查，不保证唯一历史来源 | 否 |
| 条件事件/非双射 | 全局 G 可比较不同结构；F 对 Fence/纯节点给窄充分条件 | 否 |
| 动态出现/路径覆盖 | 有限调用/创建 DAG 的完整语义＋已知路径覆盖，不从目标反推源 | 否 |
| RMW/Fence/活跃输出 | 全局 T、真实 pair/guard、数据与观察约束；F 展示一种组合 | 否 |
| 验证器安全转移 | 必须 `S⊆Q`；普通优化定理的 `Q⊆S` 不够 | 否，但易用错方向 |

“否”表示没有建立新增机制的必要性或优势，不表示这些工程与证明义务已经完成。
若要求额外的严格原子/排序契约，单向观察包含不足，必须检查相应契约或双向保证。
完整执行语义提供了明确接法；不是已存在一个开箱即用的 GNU→Dat3M 工具。

## 9. 独立算法创新与工具/系统贡献分别判断

**本轮候选：No-Go（独立算法创新）。**

- 联合候选、SMT、路径覆盖、统一见证和关系包含都是已有机制。
- 最有希望的跨片段排序例子已有 FE1 类规则；F 是这些机制的明确实例化。
- 未找到真实合法转换的表达力分离，也未证明成本优势。
- Stellite/SEQ 的模型桥接和实际对象适配是必须完成的工作，但未显示需要新的
  correspondence synthesis 原理。
- 不能据此宣称“任何未来高效分解都不可能创新”，也不能通过改名制造新贡献。

**工具/系统贡献：保留候选，不作可发表承诺。**
有潜在价值的对象是完整真实链：未改写 GNU 接口、实际编译产物、同次最终 Program、
全部路径/实例、独立证书以及可靠拒绝。论文可围绕可信边界、自动化覆盖、
真实前后端错误和复核能力评价；不能用已知算法包装成新理论。

进入这条路线前应先获用户下一轮授权，并至少明确：

- 与“独立语义编码＋已有对齐＋全局包含/规则”的可信基线相比具体增加什么；
- 哪些语义桥接在证明内，哪些在 TCB，是否确实能关闭程序级结果转移门禁；
- 独立真实程序的覆盖是否超出旧 CK 单例，失败原因是否有可解释边界；
- 使用成本与独立复核成本能否接受，材料是否足以复现实际对象来源。

这些是后续研究条件，不是本轮实验计划的自动批准。
当前没有新的真实输入验收、实现保证、性能结论或论文就绪结论。

## 10. 交付停止点

本轮完成最强已有组合的明确接口、前提/方向审查、障碍分类、受限候选引理与解析
反证。没有开始完整新算法、认证器修改或实验。保留全部历史通过/拒绝证据。
**交付后停止，等待审阅；不继续推进实现。**
