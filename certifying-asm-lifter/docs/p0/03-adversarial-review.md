# P0 对抗性审阅与剩余可信边界

## 1. 本轮关闭了哪些实现缺口

原系统只知道 worker 区域和有限实例已匹配，尚不能证明 main 的用户性质被提交给验证器。
P0 增加了完整 main 消费、源/LLVM/Q 初始化和共享 load、真实 handle→join、
完整用户/内部 Assert 清单，以及实际 Task/formula/query/result 的绑定。

新代码没有为通过验收更改原 E2E-SAFE、ISA 参考语义、TSO 模型或 CK 上游接口。
新增 `--p0-query-audit` 保留旧构建路径；旧入口仍不释放程序级判定。
故障构建与正例构建分离，实际修改对象而非写手工事件 JSON。

八项 Γ 的语义内容未增加，不等于可信代码的字节数没有增加：
新增 `P0Audit.java`/插桩脚本属于已声明的 Γ_capture，
`p0_host.py`、`p0_queries.py` 和门禁驱动属于 Γ_check。
这些新增可信实现的源码、摘要和构建接点均交付；没有把尚未检查的 main、实例
或查询事实改写为一个新的“相信它正确”的前提。

**自动事实门禁在 D₀-P0 已落实；原 Γ 的语义前提没有闭合成机器证明。**
如果把“关闭 P0”理解为无外部语义假设的整程序正确性，本轮没有做到，也没有这样发布。
本轮完成的是用户批准的、随完整原假设清单交付的条件式转移。

## 2. 对证明与代码的攻击

| 攻击 | 必要条件及当前处理 |
|---|---|
| 用源程序最终安全帮助 host 比较 | 所有 main 共享读为独立自由 U，worker 输出为既有开放符号；host 义务无 rf/co、PASS 或最终 x=2 前提 |
| 主断言消失而区域全部 EXACT | 完整源/LLVM/Q 操作清单和实际 monitor census；实际删除负例在 host 层拒绝 |
| 两次 join 数量没变但目标错误 | handle 声明→alloca→load→create→实际线程对象关系；实际单字段故障拒绝 |
| 最后 bound UNSAT 掩盖安全查询 | 分阶段审计，SAFE 要求两个实际返回值及各自公式；不安全程序第一次 SAT 不释放 |
| 第一安全查询偷偷加 false assumption | 实际传参独立核对；真实负例即使两次 UNSAT/PASS 仍拒绝 |
| 属性中报告变量导致“等价”错判 | 存在投影私有报告布尔量，并检查它不与基础公式/assumption 混用；不手填变量名 |
| assumption 与 monitor 同名形成循环 | 显式自由变量分离。审阅发现并补全此充分条件后重做最终五例 |
| 读对文件名却混入另一运行 | 固定构建/模型/candidate、Program 身份、run ID、前后对象一致、实际 dump 摘要；原 Γ_capture 仍必要 |
| 额外共享 Store/Fence/assume 被跳过 | 未消费语句、指令和事件拒绝；所有事件类型、标签、实际读写字段检查；当前源 main 写/Fence 清单为空 |
| pthread 模板看起来正确便推导通用精化 | 不这样做。模板识别只是绑定 Γ_runtime 所作用的实例，语义契约仍外部 |
| 后继条件擦掉已发生的用户错误 | 主/worker 用户段不允许额外 assume；协议及编码的错误前缀保全仍需原 Γ_runtime/Γ_encode |
| 局部 rf/co 相容便推导全局相容 | 仍使用原端点保持引理：从同一个源图运输同一套 rf/co；不以局部 SAT 拼接 |
| 输入之外偷偷扩展接受域 | 原 provenance、constant bindings、single live asm 等限制不变；新 main 文法严格拒绝其他宿主语义 |
| UNKNOWN/超时/导出不完整 | 实际审计未完成、未知返回、义务非预期结果、命令超时或不完整字段，均无法到达 SAFE 分支 |

最后一行的拒绝路径由代码审阅与解析器回归支持；
本轮没有额外运行真实后端超时/UNKNOWN 故障，不把未运行的情形记成动态检测成功。
字段/schema 的完整性仍依赖忠实导出器，不能仅由 `complete=true` 证明。

## 3. 新发现与修补的范围

1. 查询日志与先前概念格式有差异：包含 license 元信息，实际控制路径以 EOF 结束。
   最初两次保守拒绝保存；修复解析规则时保留实际 completed、阶段/栈/数量检查，
   没有把 EOF 本身当“运行成功”。
2. 公式级查询引理必须显式要求 assumption 不出现在监视器自由变量中。
   仅检查其不在基础公式和私有报告变量中不够；该充分条件已加入最终代码。
3. 对实际 audit、Program 和 SMT 再次核对运行 receipt 中的摘要，减少混用/改动窗口。
   这不把 OS/文件系统从 TCB 移除。
4. 没有发现需要改变原 E2E-SAFE 或参考 asm 语义的新反例。
   三个新增后端错误是**受控注入**，不能计为新发现的真实上游 Dat3M 缺陷。
   既有已复现上游转换错误的材料保持原样，本轮不重新计数。

## 4. 不受本轮结果支持的主张

- 不是任意 GNU C/C++、所有 D₀、非固定参数或多调用上下文的程序级认证。
- 不是 pthread 运行时、整个 LLVM、Clang 优化器、Dat3M 编码器或求解器的形式化验证。
- 不是 unbounded 循环、任意线程数或未建模 create/join 失败路径的安全性。
- 不是一般 metadata 不可信条件下的对应合成。
- 不是安全 SAT 到真实源错误的通用回译算法。
- 没有新增独立算法创新主张，也没有解决系统论文的覆盖率、比较、公平评测和成本证据不足。
- 一个 CK 例程和一个性质变体仍不足以证明第三方库的普遍适用性。

## 5. 停止点

P0 的实现、原前提下的条件式推导、最小正负验收及完整材料已交付。
未经下一次批准，不进行 P1 非固定参数、多调用上下文、新指令、其他库或大规模实验。
下一次审阅应先决定是否接受当前 Γ_runtime/Γ_encode 的明确可信边界；
如要求削减该边界，需要单独的语义验证工作，不能通过多跑几个 PASS 取代。
