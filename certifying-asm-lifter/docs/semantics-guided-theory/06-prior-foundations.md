# 06　已有理论基础、直接复用边界与尚待解决的算法问题

基线：`8142a6bb212e685e1397d68ce8d33e65afe48886`。审阅日期：2026-10-22。
本文只进行文献核查、数学分析和问题界定；不以本轮未验收的实现、pilot、配对运行
或故障记录作为证据。也不改写历史 L1–L4、ACTC、guarded 定理及八项 Γ。

**当前判断：用独立并发语义产生真值、测试验证器、采用语义保持变形及翻译验证，
各自都有直接先例。将它们组合到 GNU asm→LLVM→Dat3M 具有明确工程目标，但
独立算法创新尚未成立。** 本章给出可以复用的原理、不能省略的前提，以及需要在
后续理论工作中具体解决的问题；不预先宣布这些问题已有新解。

## 1. 首先固定三种不同的正确性方向

令 `Exec_M(P,i)` 是初始化/输入 `i` 下符合模型 `M` 的合法执行，
`O_M(P,i)={obs(e) | e∈Exec_M(P,i)}`。观察 `obs` 必须预先固定，不能为了使
比较通过而删除返回值、共享状态或错误事件。对性质 `φ`：

* 一个独立合法见证 `e` 满足 `¬φ(obs(e))`，足以确定该输入任务为 UNSAFE。
* SAFE 的真值需要证明所有合法执行均满足 `φ`；有限测试未发现错误不充分。
* 对每个已枚举结果有合法见证，仅证明集合包含于真实结果集合；还需要完备性，
  才能用该集合授权 SAFE。反之，可靠过近似全部满足性质可以证明 SAFE，却不能
  用其中未经具体化的元素授权 UNSAFE。

普通编译精化常要求 `O_Mt(T(P),i) ⊆ O_Ms(P,i)`：目标不能增加源禁止的观察。
源错误向验证模型的转移则需要对每个源错误存在相应目标错误；完整观察包含
`O_Ms(P,i) ⊆ O_Mt(Q,i)` 是其一个充分但较强条件。两种方向不可互换。
若目标验证器的 UNSAFE 仅承诺“可能错误”，而不承诺真实反例，则抽象假警报也
不能未经工具契约核对就判为实现错误。

一个实际源执行与一个目标执行不同，不证明两个程序行为集合不同。报告完整
差异时应给出某观察属于一方且不属于另一方的证据；报告错误安全结果时应另行
绑定实际用户性质、查询假设、完整性/bound 条件和同一次工具结果。
这些是判定问题本身的逻辑要求，不作为本项目的新颖性主张。

## 2. MCFuzz 的确切工作和适用前提

这里的 MCFuzz 是 Chengyu Zhang、Ting Su、Yichen Yan、Fuyuan Zhang、Geguang Pu
和 Zhendong Su 的 **Finding and Understanding Bugs in Software Model Checkers**，
ESEC/FSE 2019，DOI `10.1145/3338906.3338932`。不是对多线程程序安排调度的同名
工具。其 §3.1 明确假定种子程序有效、终止且确定；§3.2 给出 ER、ECR、FCR：
分支可达、分支执行次数、合并全部计数性质。§3.3 的流程是插桩、具体执行、
性质构造、调用模型检查器。ER 可以产生安全/不安全任务；ECR/FCR 通过确定运行
的计数值构造安全性质。论文 §4.2/4.4 还区分 UB、工具不支持和真实错误，不能把
所有结果不一致都计作缺陷。[作者论文，§3–4](https://tingsu.github.io/files/fse19-MCFuzz.pdf)

可直接复用的是“程序加有独立真值的性质”作为测试单位，以及把若干局部检查
组合为一个有清楚真值的任务。不能直接复用的是“执行一次得到的计数就是所有
执行的计数”：固定输入并不消除并发调度及弱内存非确定性。

**反例（本章推导，不是 MCFuzz 的缺陷）。** 初始化 `x=0`。线程 0 执行
`r=FAA32(x,1); c=(r==0)`，线程 1 执行 `FAA32(x,1)`；`c` 仅由线程 0 写，
join 后观察。固定 TSO 下两个 locked FAA 的合法先后顺序分别给 `c=1` 和 `c=0`。
一次执行得到 `c=1`，不能据此把 `assert(c==1)` 的真值定为 SAFE。正确验证器
返回 UNSAFE 不是假警报。这个反例甚至不依赖 store-buffer 弱行为。

因此，从该工作到本项目需要的是并发观察集合或带方向的证据 oracle；只把
“具体运行一次”替换为“一次 Dat3M 求解”既不满足完备性，也破坏独立性。

## 3. 并发测试和模型 oracle 的直接先例

| 工作 | 已有原理及明确前提 | 可复用内容 | 本项目仍需补足的具体联系 |
|---|---|---|---|
| [C4，High-coverage metamorphic testing of concurrency support in C compilers，STVR，§3](https://johnwickerson.github.io/papers/c4_stvr.pdf) | 内存模型生成小测试；HERD 枚举可能结果并加强断言；观察精化变形维持 oracle | 从结果集合构造性质；以有证明的变形扩充测试 | 被测对象改为验证器后，SAFE/UNSAFE 的方向及属性编码证据必须重新明确；不能把 `member(O)` 或并发变形测试声称为首次提出 |
| [Téléchat，Compiler Testing with Relaxed Memory Models，CGO 2024，§II–III](https://lukegeeson.com/assets/publications/cgo24/paper.pdf) | 分别用源和体系结构内存模型比较源/编译结果的可能观察；不把硬件采样当完备 oracle | 模型驱动行为集合比较、明确源/目标模型 | 需要独立连到 GNU 接口、LLVM 位置、实际 Q 及安全查询；观察集合相同不自动给出事件级定位 |
| [diy7，官方生成器文档，§7–12](https://diy.inria.fr/doc/gen.html) | 从关系环、候选顺序松弛和通信关系生成有针对性的 litmus 测试 | 关系组合驱动生成、固定线程/环大小及系统化变体 | 若本项目只根据操作类别/邻接标签打分，不能据此宣称比关系驱动生成更“语义感知” |
| [Herding Cats，TOPLAS 2014](https://arxiv.org/abs/1308.6810)；[Herdtools7 官方说明](https://github.com/herd/herdtools7) | 公理内存模型及其执行模拟；herd7、diy7、litmus7 分别承担模型模拟、生成和硬件运行 | `rf/co/fr` 图约束、模型参数化、模拟与硬件观察的区分 | 必须证明测试 DSL 到所选模型输入的对应；“使用 herd7”本身不证明 GNU 源程序有效或完整捕获 |
| [A Better x86 Memory Model: x86-TSO，2009 扩展报告](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-745.html) | 给出操作式写缓冲与公理式 TSO 的等价定义，并独立检查执行见证 | 双语义 oracle 及独立见证检查的理论基础 | 需逐项核对本项目 FAA、Fence、初始化、终态观察和冻结 CAT 的实例化；既有等价定理不能自动验证新 Python 编码 |

C4 的变形目标是保留用于判断的观察性质，而非任意结构修改。普通 mutation
可以产生新语义，再重新求 oracle；这与证明过的 metamorphic relation 是不同机制。
两者都可以有用，但在算法说明、证明和评测中必须分开。

两个独立实现相同的有限输出有助于发现实现错误，却不替代对应的普遍语义定理。
更不能将 Dat3M 的编码复制一份换名字后称为独立 oracle。可考虑复用上述成熟
模型理论，同时让操作执行器、图枚举器和具体见证检查器的构造相互独立；但相同
AST/类型解析器、位宽约定或观察函数仍是公共可信表面，应明确列出。

## 4. 语义保持变形及翻译验证的先例

| 工作 | 已有机制 | 直接适用边界 |
|---|---|---|
| [EMI，Compiler Validation via Equivalence Modulo Inputs，PLDI 2014](https://www.cs.ucdavis.edu/~su/publications/emi.pdf) | 对选定输入集合保持等价；利用动态执行与静态编译之间的差异生成变体 | 在并发程序中，输入固定仍有多个合法执行；单次未覆盖分支不能直接当作所有执行均不可达 |
| [Alive2，PLDI 2021](https://web.ist.utl.pt/nuno.lopes/pubs/alive2-pldi21.pdf) | 基于 SMT 的有界 LLVM 翻译验证；显式处理精化及源/目标非确定性 | 可复用公式、量词及反例表达原则；不能把 bounded 结论直接用于无界行为，也不能将 LLVM 精化自动当作 GNU/TSO 整体证明 |
| [VALID，CGO 2016](https://plv.mpi-sws.org/validc/paper.pdf) | 并发访存模式匹配；检查重排、引入、消除和 CFG 变化；无循环范围有可靠性条件，循环采用启发式 | 表明“生成并发程序并检查 LLVM 并发变换”已有直接先例；固定模型、方向及接口仍需逐一对应 |
| [Stellite，ESOP 2018](https://www.cs.kent.ac.uk/people/staff/mjb211/docs/esop18.pdf) | 开放历史及代表性上下文给出组合式变换验证；有限版本以更强历史条件换取可检查性 | 可借鉴边界交互摘要；不能将纯局部值等价当作任意并发上下文等价；该文模型也不是本项目 CAT 的自动证明提供者 |
| [TInA，ASE 2019](https://rbonichon.github.io/papers/tina-ase19.pdf) | 面向验证的 inline asm lifting 与专用翻译验证 | GNU 汇编提升及独立验证并非本项目首次提出；实际并发事件/查询联系仍需另外建立 |
| [CompCertTSO 项目](https://www.cl.cam.ac.uk/~pes20/CompCertTSO/) | 特定 ClightTSO 语言与编译链的验证编译 | 可借鉴明确机器内存语义与模拟证明；不能作为 Clang、GNU 扩展或 Dat3M 的即插即用正确性假设 |
| [Optimuzz，PLDI 2025](https://kihongheo.kaist.ac.kr/publications/pldi25.pdf) | 用定向灰盒生成触发特定编译优化，再以翻译验证检查；选择覆盖及目标变异 | “定向生成 + 翻译验证”已有直接先例；本项目需要说明语义反馈比目标位置/覆盖反馈多解决了哪个算法问题 |

尤其要区分变形关系的方向。设 `P'` 是生成的变体：

* 若 `O(P') ⊆ O(P)`，则 `P` 的全称安全性质可转移到 `P'`；但 `P` 的某个
  不安全见证可能被变形消除。
* 若 `O(P) ⊆ O(P')`，则原不安全见证可保留；但 `P'` 可能增加违反原安全性质的
  观察。
* 若要求两类 oracle 都无条件复用，可要求观察等价，或为所选性质分别提供足够的
  定向证书。不能只写“语义保持”而不指定量词和观察。

这些包含推论是集合语义的直接结论，不是本项目的新定理。
面对互斥分支上的 FAA 合并，实际证明还需保证 guard 互斥且完备、操作数与返回值
一致、条件求值无额外共享效果、每次执行的原子事件和必要顺序可对应。仅比较
两个分支的汇编文本不足以应用任何上述结论。

## 5. 本项目需要解决的问题，不等于已经建立的创新

下表把算法问题与普通接入工作分开。它们是候选研究目标；本章没有给出完成这些
目标的新算法，也没有证明现有方法组合不能解决它们。

| 编号 | 需要明确求解的问题 | 应交付的理论对象 | 不构成该问题已解决的材料 |
|---|---|---|---|
| F1 | 从定义良好的有限并发语言产生可双向判定的任务，区分完备安全证据与存在不安全见证 | DSL 语义、oracle 方向、枚举完备性/拒绝条件、独立检查规则 | 被测验证器的 PASS/FAIL；仅两个实现偶然结果一致 |
| F2 | 从跨层语义边界或关系障碍选择下一测试，而不是仅选择新语法标签 | 可计算反馈状态、更新/选择规则、每种候选的可行性和类型不变量 | “使用 SMT、反馈、图关系”等机制清单；预置唯一历史缺陷模板 |
| F3 | 在保持所需性质真值的前提下改变真实编译结构，触发互斥事件、复制/合并和活跃输出处理 | 观察映射、定向 metamorphic relation、上下文及统一 `rf/co` 的组合条件 | 单次路径没经过某语句；删除共享操作后仍有一个相同结果 |
| F4 | 在源码、LLVM、Q、查询之间找到最早已被证实的不一致，而非最早解析失败 | 每层独立比较关系、来源/实例覆盖证书、局部见证到完整执行的提升规则 | Q 中按名字未找到事件；仅存在一个源/目标执行对不同 |
| F5 | 在重新编译及完整合法性保持下缩减反例，保持所宣称的错误类别 | 良基缩减关系、检查谓词、见证/全体目标排除的更新规则 | 手改 Q、保留某错误字符串、仅保留后端 PASS |

F1 大部分可以直接建立在成熟 TSO 模型及有限模型检查之上；F3 的组合理论和 F5
的“以检查谓词保持 interestingness”也有明确先例。因此，单独完成它们可能形成
可靠工具，却未必形成新的方法论文。F2 若只是覆盖贪心和失败特征加权，同样属于
常见启发式实例。可能有研究价值的是 F2–F4 间具体的语义约束反馈与证书机制，
但必须给出确定算法、非平凡区分例和相对于已有组合的差异后才能评价。

算法可靠性与搜索有效性也必须分开：可以证明所有已确认报告都有合法证据，而
不保证搜索必然发现缺陷；反过来，找到某个问题不能证明所有报告都可靠。
纯理论阶段能够建立前一类条件式保证、反例和复杂度边界，不能声称后一类实测收益。

## 6. 本阶段判定和后续证据门槛

**直接复用而不申报新颖性的基础：** 有限语义建模、结果集合 oracle、定义良好
生成、关系驱动 litmus 测试、语义保持变形、SMT 翻译验证、上下文交互摘要、
独立见证核验、检查谓词驱动缩减。

**本项目仍需论证的算法差异：** 是否存在一种可计算的跨层语义反馈，能够通过
可核查的关系障碍或边界条件生成有效测试；是否能把它与充分的定位及具体化证书
组合，且其收益不退化为换工具链、增大白名单或重新分类已有失败信息。

当前可给出的结论是 **独立算法创新 NOT_ESTABLISHED**，而不是“因理论基础已有
就不可能有工具贡献”。若候选最终只是上述机制的直接组合，应明确对“独立新算法”
给出 No-Go，同时保留其受限工具价值。若推导出现新的充分条件，必须进一步判断
它是否只是标准定理的实例，不能把正确性证明本身等同于创新。

本纯理论交付不授予实现、运行或扩展实验的授权；不引用此前未验收运行证明
方法有效，不作真实缺陷数、检测率、覆盖收益或投稿准备度结论。新的算法及证明
完成后，应先独立审阅，再由用户决定是否进入实现与受控实验。
