# 原始 CK 内联调用的条件性组合证明与实现前提审计

本文件证明的是明确定义的受限算法，包含实现检查点与外部前提的对应。
它不是 Python/C++/Java 的机械化精化证明。测试结果不作为任何引理的假设。
先行设计见 [08](08-provenance-design.md)，实际对象见[独立验收报告](../15-ck-acceptance.md)。

## 1. 对象、标识及不可省略的信任边界

记同次 Clang 编译的 AST 为 A、SourceManager 为 S、实际优化后 LLVM 为 L。
观察器只读 A、S，同时导出完整 AST 和全部 GCCAsmStmt 清单；L 由该进程的
正常 CodeGen/优化产生。源码、依赖、观察器源码/构建记录与产物均保存原始字节。

对源 asm s，K(s) 为固定 Clang `getAsmSrcLocInfo` 定义的原始位置编码元组。
接受子类的字符串只有一行，因此 K(s) 只有 StringLiteral 开始位置的编码。
该位置可以是宏位置，不能用 spelling 文件偏移替代。对实际 LLVM 调用 c，
K_L(c) 是其实际 `!srcloc` 整数元组。对象 ID 只在这一次编译内有意义。

外部契约 T_front：

1. 固定 Clang 正确处理输入 GNU C、预处理和类型；观察器如实序列化所读取的对象。
2. CodeGen 为 c 写入其真正来源 s 的 K(s)，所用优化保留这个来源关系。
3. 普通宿主 C 的编译及调试内联链满足所列编译器契约。

这些是既有编译器/导出器可信边界的具体化，**不是新增一个“来源已经正确”的
抽象公理**。观察器实际使用 `getAsmStringExpr`、`getBeginLoc().getRawEncoding()`、
约束/表达式访问器；没有实现独立的 C 预处理器，更没有证明 Clang 全部正确。
字节哈希只防止证据混用，不能推出 T_front。

原始输入的 GNU 语义、有效对齐 WB 内存、局部 ISA 解释与固定 TSO 模型对应、
Dat3M 普通宿主/pthread/断言/CAT 编码、求解器和检查器实现正确性仍是外部前提。
本轮没有把 ISO C 数据竞争语义、完整 RC11Ex86 或任意 LLVM 优化引入定理。

## 2. 来源连接引理 P

算法对每个实际 surviving inline-asm c 计算

`J(c) = {s ∈ A.GCCAsmStmt | K(s) = K_L(c)}`。

它先对**全部**节点做此连接，再读取选中节点的函数、类型、模板；要求
`|J(c)|=1`。当前接受域进一步要求 L 只有一个 surviving 静态 asm。
因此并未宣称同时认证全部 188 个节点，也不会偷偷过滤多余的 LLVM asm。

在 T_front 下，真正来源 s₀ 必有 `K(s₀)=K_L(c)`，所以 s₀∈J(c)。
由唯一性，J(c)={s₀}。故选中的就是实际来源。□

证明依赖来源编码的保真性，但不依赖编码全局唯一：同一次编译若发生碰撞，
基数检查拒绝。函数名和模板相同不足以证明 P；本算法不以它们选取节点。

连接后还做独立检查：宏 caller 链无环且终止于文件位置；spelling/expansion
偏移、行列与原始 SourceManager buffer 字节一致；实际物理 buffer 与捕获依赖
字节相同；三个原始字符串 token 逐个从 spelling 字节重读并拼接。当前不支持的
转义、多行、宽字符串直接拒绝。GNU 模板与 LLVM 模板还必须逐字匹配。
这些检查不能取代 T_front，但可以发现视图不一致和证据混用。

## 3. 类型化求值与内联替换引理 I

值域区分标量值、指针值、局部 lvalue 和共享对象 lvalue。类型判定采用 Clang
canonical type、位宽和限定符，同时保留 `uint32_t` 原始拼写。仅允许无限定的
unsigned 32/64 位标量、指向相同标量的 64 位指针，以及下面的表达式构造。

接受的包装函数体严格为 `asm; return output_parameter;`，恰有两个参数、
一个 `+m` 输出和一个 `+q`/`+r` 标量输出。不允许隐藏调用、分支、额外语句。
实际直接调用由 CallExpr→FunctionDecl 的对象 ID 连接恢复，实参顺序决定替换 θ。
实际实参仅可求值得到静态全局地址与可表示的整数常量。

对受支持表达式 e，定义解释 E(e,ρ)：

- DeclRef：查找声明身份，不查找同名字符串；局部返回带值的 lvalue，
  全局返回带对象地址的 lvalue。
- Paren：类型相同且保留子表达式结果。
- LValueToRValue：仅允许无限定局部值，不允许读取一般共享内存。
- 地址与解引用：`&g` 得到 g 的对象地址；`*p` 得到 p 指向的 lvalue，
  此时不提前读取共享值。
- NoOp 指针转换：源/目标 canonical pointer 与 pointee 完全一致。
- IntegerLiteral 与 IntegralCast：只允许可表示的非负常量转换；拒绝截断、
  指针整数互转和一般表达式转换。

引理 I1：E 与上述子语言的 C 求值相同，且求值没有新增共享事件。
证明对表达式构造归纳。变量/字面量为定义的基例；括号保持归纳结果；
局部读取仅取环境值；恒等指针转换保持表示与指定对象；地址和解引用互为
指定对象关系，不访问对象内容；受检查范围内的整数转换数值不变。
其余构造没有接受规则，故不能构成接受导出的反例。□

引理 I2：以 θ 为包装函数形参环境，原 asm 的地址/输入槽与实际 LLVM 操作数一致。
I1 给出 θ 下的真实已求值操作数。已有 H 引理按输出、隐含 `+` 输入和 clobber
的消费规则归纳，产生独立的 LLVM 消费表。逐项比较实际 LLVM 参数、类型和
tie，特别要求 `+m` 的两个实际地址相同；再与 I1 的结果比较。因此两种
独立恢复得到相同绑定。该结论不从候选 lifter 的输出反推。□

引理 I3：包装函数返回值是 asm 更新后的标量输出。执行 asm 后只改变该参数
对应的局部值为 z；函数剩余唯一语句的表达式经 I1 求值为 z，且返回类型相同。
若返回常量、另一个变量、转换后的值或包含额外行为，检查不能通过。□

CK 的实例为 θ(target)=`&x`、θ(d)=1；源操作数次序保持为内存 0、标量 1，
得到 `p0=@x, o1=1`，不是将原接口改写成以前样例的顺序。

## 4. 源 C 活跃返回值到原始 LLVM 的引理 C-source

worker 的第一条语句必须是用该直接调用初始化一个同类型局部变量。
后续只允许以这个变量/常量构成的同类型 `==`/`!=` 断言，最后返回空指针。
I3 给出初始局部值 z。按顺序解释 C 断言得到布尔列表 B_C(z)；
独立解释原始 L 的 icmp/zext/assert 后继得到 B_L(z)。

每个证明义务为 `∃z. B_C(z)[j] ≠ B_L(z)[j]`，并检查列表长度相同。
若公式 UNSAT，由反证法有逐项全称相等。C 中比较结果的 int 0/1 与 LLVM
icmp→zext 后按非零解释的结果相同：相等关系成立时两者均为 1，否则均为 0；
`!=` 是同一关系的布尔取反。该说明覆盖全部位向量值，非一次运行中的旧值。
由 I3 和逐项相等，源 C 返回值的后续观察与原始 L 相同。□

后续原始 L→实际 Q 的活跃寄存器对应仍由 C-live 检查：
`区域真实写寄存器 ∩ 区域外真实读寄存器` 必须唯一且同宽；区域输出义务证明
它等于 z，后继义务再证明每个真实 Assert 的条件相同。寄存器名称从未作为
输入映射。活跃性 SAT 查询是排除恒真观察的额外验收条件，不用于推出等价。

## 5. 内联上下文与实例覆盖引理 N

一个证明实例标识为 `(s,i,a)`：源 asm 节点、静态内联调用上下文、潜在线程
激活。P 只确定 s，不能由一个 s 推出 i 或 a。

实现检查包装函数的直接 CallExpr 唯一，worker 完整语句形状满足上节条件；
原始 LLVM 包含该 worker 的唯一 asm，前面没有可执行指令。
LLVM DILocation→DISubprogram→DIFile 的文件内容校验与已选定源对象相同，
inlinedAt 精确对应该实际 CallExpr 的行列和 caller；更深内联链拒绝。
这些检查用调试信息验证已经恢复的上下文，不用文件名选取源 asm。

源 main 与原始 LLVM 均为受限直线创建结构。C 调用的目标声明身份必须是该
worker；C/LLVM 创建位置清单相同，位置不能歧义。拒绝额外调用入口、未知
属性（含构造/别名等）、额外 surviving LLVM 函数及未支持的控制流。
main 的声明必须为无初始化、无子表达式的受支持无符号标量；仅“无初始化”
不足以排除 VLA 长度中的求值，故不能省略后两项检查。
设该清单为 I={i₁,…,iₙ}，n 来自输入，不是手填的 2。

实际 Q 的 worker 集合 W 必须大小 n，创建位置给 I→ThreadCreate 的双射，
真实 spawned_thread/ThreadStart.creator 再给 ThreadCreate→W 的双射。
组合得到 I→W 双射。每个 worker 的闭合区域均须存在并检查通过；所有用户
共享事件都必须在该区域内，区域外仅允许已经检查的运行时框架和纯断言后继。

故对每个潜在创建出现都恰有一个实际区域证明，既无遗漏，也无重复借用。
这是有限集合双射及域穷尽的逻辑推论，不是“观察到了两个线程”的统计推断。
实际 OS 是否创建失败、真实 pthread 调度与 join 语义仍由宿主契约承担。□

Dat3M 在此程序上保留 header 的 asm 源行，却在主文件记录 pthread_create。
实现把这两个经检查的路径分别使用；旧实现将它们混用会错误拒绝合法内联。
路径/行仅用于提出区域候选；区域的完整语义、活跃值与所有未覆盖事件另行检查。

## 6. 条件性组合定理

在本文件的 T_front 和所列外部契约下，假设 P、I、C-source、N、已有
BLOCK_EXACT、LLVM_FRAGMENT_EXACT、REGION_EXACT、C-live 及宿主框架检查成立。
则这个受限原始 GNU 内联调用的转换，在每个潜在线程激活中保持其开放读取响应
行为、端点、A 标签、真实 RMW 配对、返回值及已检查断言观察。

证明：P 确定真实 s，I 给出 θ 与返回接口。已有局部定理对任意开放读取 u
给出相同地址、端点存在性、值和返回 z；对 xadd，写值恒为 `u+1 mod 2^32`，
返回 u。N 把该全称结果实例化到每个 a，区域互不交叠且没有未分配的用户事件。
C-source 与 C-live 通过共同中间值 z 作关系合成。合并各区域映射与受契约约束
的外部框架映射，已有 T 定理逐个输送 po/rf/co/rmw/标签与固定 CAT 公理。
由此得到所声明的上下文保持结论。各步骤只使用先前结论和明确前提，未使用
后端 PASS、候选生成器正确性、有限输入枚举，亦未使用结论证明自身。□

这不是任意 GNU C 整程序的形式化正确性证明：通用宿主对应和编码正确性仍未
机械证明，所以 `program_verdict_eligible=false` 必须保持。

## 7. 证明前提如何落实

| 前提 | 实现中的独立检查 | 尚未由代码证明的部分 |
|---|---|---|
| 同次对象与原始输入 | `capture_ck.py` 单次 CodeGen+observer，依赖前后哈希；`authenticate_capture` 重读原始 buffer/依赖/原始 CK 哈希 | OS、观察器序列化、Clang 前端真实性 |
| P | `_reconcile_objects` 先全集 cookie 连接，基数为一；实际源 token 与 LLVM 字符串核对 | 元数据来源保真性 |
| I | `evaluate` 类型化解释；原函数完整 body 形状；`llvm_site` 独立约束消费；实际实参与 C 替换相等 | Clang 类型/声明对象真实、有效地址域 |
| C-source | `prove_source_assertions` 保存反例 SMT，SAT/unknown 拒绝 | Python/Z3 实现正确性 |
| i | 实际 CallExpr 声明 ID、源/LLVM worker、校验和及精确 inlinedAt | 编译器调试信息真实 |
| N | C/LLVM 创建清单；真实创建/线程双射；逐实例区域+框架穷尽 | pthread 建模符合声明宿主契约 |
| 局部与后端语义 | 独立参考、实际 LLVM 解释、同次最终 Program、真实配对/标签/guard/值/输出检查 | ISA/CAT 桥、导出器/编码器与实现精化 |

最终审计额外收紧了字符串转义、属性、额外 surviving 函数等边界；没有为了
通过 CK 而改变参考 RMW 语义或跳过旧检查。上述对应仍是代码审阅结果，
不是自动证明了各实现满足数学算法。
