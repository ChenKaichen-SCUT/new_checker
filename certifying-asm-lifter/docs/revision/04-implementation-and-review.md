## 2. 已做的语义修补

旧 emitter 的 fallback 被移除。XCHG 分支只接受不含当前 old 的表达式。
ADD 同时识别 `old+d`、`d+old`，并检查 d 不依赖当前读。
CAS 检查 expected/desired 的读前可计算性。对不支持的等价表达式允许拒绝；
独立 lowering checker 可以在后续检查其他候选产生器给出的实际 LLVM。

还有这些必要保护：

- 仅接受 TSO mode 与匹配位宽，不把 acq/rel/sc 静默改成 monotonic。
- 校验 IR envelope、statement schema、地址绑定和标量名字。
- SSA 分配避开已有实参名；原位补丁还检查整个宿主模块的名字冲突。
- 未知源码语法、LLVM 指令、后端事件/表达式、标签、CFG 和 SMT unknown 全部拒绝。
- 实际区域 checker 检查配对指针，不以 printer 注释 `Linked to E...` 作为依据。

## 3. 哪些环节仍不能伪报完成

新增真实入口解决了“手填 64 位”和“按名称猜绑定”的设计问题，
受控编译/同次求解驱动 `run_pipeline.py` 已写出，但尚未执行，
因此还没有通过它产生的真实封存包。
只用 `prepare.py` 读入外部包时，来源仍显式标为 `EXTERNAL_UNATTESTED`。

区域 checker 提供了对一个实际闭合区域的接受算法。
进一步限定最小 worker 子类后，新增 `coverage.py` 从实际 LLVM 的函数体、
直接创建引用和实际 ThreadCreate 链接重建 census，逐个检查所有 worker，
并核对不存在未覆盖的用户内存端点。返回值不可观察性也由源码 LLVM use 检查建立。
它不提供通用内联/循环/活跃输出映射。
安装脚本与同次求解驱动已有源码；导出器尚未实际安装/编译。
当前没有新 `REGION_EXACT` 实际结果，不能将接口接线代码的存在替代执行证据。

因此第 1–4 阶段已经有可审阅的范围、定义、算法证明与对应代码，
但“自动认证一条真实整程序转换链”的系统验收尚未完成。
这个缺口不能因用户同意实验而自动变成已闭合；应核验受控构建与导出接线，
再在获准后用实验查错。任何后续接线导致理论接受条件改变，须先修订证明。

## 4. 不启动实验的审阅顺序

1. 先审阶段 1 的 Clang/ISA/Dat3M 可信边界与受支持子类是否符合研究目标。
2. 再审阶段 2 的四个实际对象、guard、真实配对、活跃输出和全部实例覆盖。
3. 再审阶段 3 H/L/V/D/R/T 的推导，尤其“先展开源，再做端点双射”。
4. 对照本表审实现是否漏掉前提。未实现项应使门禁保持关闭，不能只留文字提醒。
