# 最小验收前的证明—实现审阅

审阅基线：`51321dcc3e5f30663e93120335baa9b4cb081d7e`。
本文件在本轮真实程序编译/求解前建立。授权对象只有
`benchmarks/backend-source.c`，不改变源参考指令语义，不扩大指令集合。

## 依赖方向与非循环性

源字节及受控 Clang AST/LLVM → 接口槽 → 独立源指令语义；
候选 lifter → J；独立 J 解释器与源语义比较；
emitter → 实际替换字节；独立 LLVM 解释器与源语义比较；
实际 Dat3M solver Task → 只读导出 → 区域解释器与源展开比较。

三种目标解释器不从 emitter 的期望结果生成语义。端点展开的 A、条件写、
rmw 关系由先前固定定义给出，不能根据真实输出改变。结构归纳证明的对象
是算法；Python/Java 实现没有机械化精化证明，属于显式 TCB。

## 保留的可信前提

Clang 对该 GNU C 宿主与 opaque asm 接口的实现、受控进程/文件系统的真实性、
受限 x86 指令到固定 TSO 端点语义的解释、Dat3M 对区域外普通代码及 pthread/
初始化/属性的处理、CAT parser/encoder、SMT 求解器和检查器自身实现均在 TCB。
这些不能写成“已经由 EXACT 证明”。尤其是 pthread_create 成功的验证器模型
不是所有操作系统执行的保证；WB/有效内存域也不是实验发现的事实。

对于该固定程序，原位字节框架、静态全局大小/对齐、无循环 worker、
死返回值、真实创建链接及全部 worker 区域可由实际检查建立。
线程模型/宿主后端正确性仍是外部可信条件，不用它假设新 asm 转换正确。

## 负面检查计划

只对真实生成的候选模块作四种可追溯的机械变异：丢共享写、错误 RMW 更新、
把 RMW 拆成无原子配对/排序的读写、缺失一个实例。每个变异独立记录拒绝层级；
需要后端诊断时必须重新求解该实际变异模块，并从其同一次运行导出对象。
不手造事件 JSON、不用手写 LLVM 冒充编译器输出。
这些是查错证据，不是定理证明；无法独立覆盖的负面条件必须明说。
