# 修订阶段 3：实际转换检查算法与逻辑证明

证明对象是阶段 2 定义的算法及接受条件。这里不把尚未运行的新 Python/Java
实现当作已经机械验证的定理实例，也不以有限测试代替下述全称证明。

## 1. 算法

输入 `S, AST, L, L', Q, B`；候选 J 与事件对应关系只是提示。

1. 按阶段 1 重建接口 I。任何类型、约束消费、源位置或编译目标不一致则拒绝。
2. 逐字节比较 L 与 L' 的替换外框架，检查 SSA 新名字不捕获宿主名字，
   原返回 SSA 在相同位置被同类型值定义。独立解释 L' 的实际替换指令。
3. 从源参考语义构造宏事件及 E 展开；不调用 emitter 来构造期望目标。
4. 从同一次求解任务的 Q 快照重建目标 CFG/表达式/端点。验证区域闭合、
   真实 rmw 指针、所有相关标签、实例覆盖、出口和上下文活跃值。
5. 用拓扑符号解释得到 guard 与值函数；提交阶段 2 的反例公式。
   只有全部 UNSAT 才接受对应层级。SAT/unknown/缺项都拒绝。
6. 固定实际模型和依赖闭包。所有局部证据、覆盖与宿主条件完整后，才允许
   产生整程序判定转移证书；否则仅报告已经检查的局部层级。

算法不要求新的数学公理。困难部分是自动建立真实接口、完整对象对应和
精确排序/条件写义务；不能把这些前提移入一个未解释的 `B` 之后宣称问题解决。

## 2. 接口重建引理 H

假设指定 Clang 正确实现其 GNU extended-asm 接口；构建包真实；I 的检查通过。
则规范化参考块的入口槽、地址槽和公开输出，分别对应 L 中该实际调用的
已求值输入、间接操作数地址和返回分量。

证明：

对约束序列作归纳。入口游标为 0、返回游标为 0。
直接寄存器输出只推进返回游标；间接输出推进实参游标，并以实参作为地址；
寄存器输入推进实参游标并初始化该输入槽；数字 tie 初始化指定输出槽；
间接输入初始化相应地址槽；clobber 不推进两个游标。
这些正是阶段 1 中独立重建且逐项与实际 LLVM 类型/列表比较的规则。
归纳完成时，实参数和返回分量均耗尽，故没有遗漏或重用不属于该约束的实参。

对于 `+` 输出，Clang 追加的隐含输入被显式核对；对于 `+m`，
两次消费的地址 operand 必须相同。对模板占位符作结构替换，保留 token 编号，
因此每个指令读取的是刚才建立的同一槽。类型比较给每槽的位宽。
规范化只改槽名，不重新执行 C 表达式，故不会合并两次宿主读。

源 C 的输入求值发生在调用前、输出 lvalue 回写发生在调用后；
原位替换框架保留这些宿主指令。因此它们没有从共享事件中被“消去”。
由受信 Clang 接口正确性和以上归纳得到结论。□

此引理依赖的是明确的既有编译器接口，不依赖新 lifter/emitter 正确，
也没有声称字符串哈希能证明 Clang 正确。
寄存器分配的全称约束仍使用原 06 引理 4 的保守 hazard 条件。

## 3. RMW 时点和可降低子类引理 L

令一个 IR RMW 的旧值绑定名为 o，读前状态为 σ，任意响应为 u，
`σu=σ[o↦u]`。接受的 emitter 子类为：

- ADD：`h=true`，`v=o+d` 或 `v=d+o`，d 不含当前 o。
- XCHG：`h=true`，v 不含当前 o。
- CAS：`h=(o=e)` 或 `(e=o)`，e 与 v 均不含当前 o。

另要求：TSO mode、匹配的宽度、先求地址、表达式有定义、SSA 新名字无冲突。
不属于这些子类则拒绝；不是默认 XCHG。

### 引理 L1：独立表达式

若表达式 t 不含 o，则 `eval(t,σu)=eval(t,σ)`。

证明：对 t 的结构归纳。常量不读状态；非 o 变量在两状态中相同；
加法等完全定义操作对相等的子值给出相等结果。□

这里 t 中另一个变量 tmp 的值即使来自旧 o，也是已经求值的状态分量；
重绑定 o 不会回溯修改 tmp。因此不能把“曾经依赖”与“当前表达式包含”混淆。

### 引理 L2：三个 lowering 分支

ADD：LLVM 的实参加数在操作前求值为 dσ；原子操作产生读响应 u、
写入 `u+dσ (mod 2^w)` 并返回 u。由 L1，IR 写入同值；
反序表达式用位向量加法交换律得相等。

XCHG：LLVM 写入读前求得的 vσ 并返回 u。由 L1，
`vσ=vσu`，恰是 IR 规定的新值。

CAS：LLVM 操作前求得 eσ 与 vσ；对每个 u，
成功谓词为 `u=eσ`。由 L1 及等式对称性，它与 IR h 完全相等。
成功时同写 vσ，失败时双方都不产生写；返回分量 0 恒为 u。
本分支必须使用 strong cmpxchg，不能允许 spurious failure。

三种情况均先求同一地址、不改变其余可见状态，并在操作后把 o 绑定为 u。
对纯步骤和共享切点序列归纳，得到 emitter 接受子类在固定 TSO lowering
解释下的开放等价。□

L2 不声称 `monotonic cmpxchg` 在任意 LLVM 优化上下文中是完整 x86 fence。
固定 Dat3M 的 `VisitorTso` 为读端点加 A，是后续证明必须核对的对象。
在替换之后再运行未知 LLVM 优化 pass 不满足本定理的前提。

### 对审查反例的逻辑修复

`v=0+o` 被 ADD 分支识别，d=0 不含 o，所以写 `u+0=u`。
`v=o+o` 的另一个加数仍含 o，被拒绝；不能读取一次旧 σ(o) 来代替第二个 u。
CAS 的 expected 或 desired 若含当前 o，也被拒绝。
这些结论对所有 u 成立，不来自 native 运行的某一个初值。

## 4. 实际 LLVM 片段检查引理 V

`lowering.py` 从实际片段重新解释 add、load/store、atomicrmw、strong cmpxchg
及 extractvalue，不导入 emitter。它拒绝额外指令、未知 ordering、毒值 flags、
不匹配类型、重复 SSA 定义和未定义操作数。

令算法的符号解释为 EvalL。对实际 LLVM 指令序列长度归纳：

- SSA add 是 BV 加法，没有 nsw/nuw；与其具体模算术相同。
- load 引入同一个独立 u；store 不修改 SSA 状态。
- atomicrmw 的地址和实参先从入口环境读取，再将结果赋给新的 SSA 名；
  这与 LLVM 的 SSA 求值时点一致。
- cmpxchg 的结果为 `(u,u=expected)`，其可选写条件相同；
  extractvalue 0 投影 u。
- 每个合法赋值只定义一次名字，故后续引用不存在状态覆盖歧义。

所以符号求值得到的字段，对任意入口与响应赋值等于具体片段的字段。
若 `¬(source_field=target_field)` 为 UNSAT，反证法给出字段全称相等；
CAS 写值只在相同成功谓词下比较。相同静态骨架与全输出相等遂给出开放等价。□

这个检查可以接受 emitter 没有专门识别的等价片段，也能拒绝错误 emitter
产生的实际 `atomicrmw xchg ...,0`。它认证的字节是 L' 中的替换片段，
不是降低前 J 的哈希。

## 5. 真实端点的符号解释引理 D

设闭合区域的 CFG 无环，所有节点操作都属于支持语义。令任意实际入口状态 X
和独立读取响应 U 固定。对拓扑顺序归纳，证明：

1. 节点 guard 的估值当且仅当该执行到达该节点。
2. guard 为真时，符号环境估值等于实际核心 IR 状态。

入口直接成立。普通边继承 guard；条件边以相同条件值将它分成互补的两部分。
节点 guard 的析取因此恰好描述可达性。
对汇合节点，所有入边 guard 已证明两两互斥；在可达估值下唯一激活的前驱
决定状态，故 ite 合并选择的就是实际前驱状态。不可达估值中的占位值不参与观察。
Local 按表达式结构归纳；Load 用独立新 u；Store 取当前状态的新值；
跳转不修改数据。各步骤保持归纳不变量。

出口 guard=true 排除了某条入口响应路径被偷偷丢弃。
无环和共同出口排除了内部发散与提前逃逸。□

此证明是对 CFG 结构的归纳，不是枚举执行路径，也不是有界输入测试。
实际实现更保守：CFG 回边和非互斥合并直接拒绝。

## 6. RMW 端点匹配定理 R

假设 D 成立，全部端点 guard/值义务通过，实际 RMWStore→Load 配对、
类型、宽度、A 标签和区域出口检查通过。对任意 X,U，
源展开 E 与目标区域具有一个按位置确定的**已执行端点双射** h，
并保持 po、标签、地址、读写值、rmw 和指定出口观察。

证明：对每个静态端点 i，guard 等式保证其两侧同时存在或同时不存在。
因此按位置映射限制在已执行端点上是双射。条件字段等式保证存在时完整标签相同。
目标中不存在额外共享节点，因为区域解析穷尽全部节点且计数一致。
静态位置相同、核心 successor 顺序受检查，故任意两已执行端点的 po 相同。
源/目标配对集合相同，且配对存在条件由同一端点 guard 给出，故 rmw 保持。
输出义务和保守活跃值检查给出口观察相同。□

失败 CAS：r 的 guard=true 且 A 保持；s 的 guard=false；
双方都没有执行的 rmw 对。证明不需要把失败 CAS 伪装成成功 RMW，
也没有丢掉其排序标签。

## 7. 实际 TSO 模型保持定理 T

把源展开端点和目标区域放入相同端点上下文，h 在上下文与初始化事件上恒等。
对任意候选一致图，令 `rf'=h(rf)`、`co'=h(co)`。
则固定阶段 2 TSO 模型的良构性与所有列出的公理双向保持。

证明：

1. 每个读取的唯一 rf 来源、值一致、同址关系，由 h 的标签保持得到；
   每个地址上的 co 严格全序及初始写顺序，由双射输送得到。
2. 同线程被保留，所以 rf_i/rf_e、co_i/co_e 的限制被保留。
   `fr=rf⁻¹;co` 及其外部限制也被保留。
3. R、W、M、A、mfence 集合、po 与同址限制被保留。
   因而阶段 2 的 com、po-loc、implied、po-tso 和 ghb 每一项均被输送。
4. R 定理另外给出原生 rmw 配对保持，故 `rmw∩(fre;coe)` 被输送。
5. 双射保空性和有向有限环：任意环逐点映射成环，反向用 h⁻¹。
   因此两条 acyclic 与 atomic-empty 公理分别当且仅当成立。

不能将宏事件到端点的一对多映射直接当成双射；
本证明先独立展开源，再比较两个端点图，消除了旧论证中这一类型不匹配。□

## 8. 失败 CAS 排序的单独核对

取同线程前序写 w、失败 CAS 读取 rA、后序读 r。
在实际 CAT 中：

- `(w,rA)∈implied`，因为 w∈W、rA∈R∩A；
- `(rA,r)∈po-tso`，因为 rA∈R、r∈M。

故 ghb 的传递可达性保留从 w 经 rA 到 r 的路径，即使 CAS 没有执行写端点。
若移除 rA 的 A 标签，第一个边不再由同一规则保证。
这说明为什么 guard/值相等不足以认证失败路径；标签也是语义义务。

这段推导只证明上述边存在，不把它扩大成“所有 x86 硬件行为与该 CAT 等价”。
完整 ISA、异常、非 WB、混合大小和 RC11Ex86 跨模型桥接仍不在本定理内。

## 9. 宿主框架与上下文组合

在 LLVM 层，替换外字节相同、新 SSA 名无捕获、原输出 SSA 同类型同值，
所以每次进入片段时可选择相同实际输入，退出后宿主可选择相同分支；
按有限次调用归纳得到相同宿主事件与源点实例序列。

在核心层，若**全部实例**都有闭合区域证明，区域外宿主对应和其语义正确性成立，
R 的映射与区域外映射合并为全图双射；T 保持一致性；
公开输出与安全监视器保持，于是有限安全观察集合相等。

这里必须逐项保留两个前提：

- 全实例覆盖与区域外对应，不由一个 REGION_EXACT 推出；
- 既有 Clang/Dat3M 宿主语义的可信假设，不由局部 SMT 推出。

本轮没有给出任意 Dat3M 优化 pass 的通用正确性证明。
替换后优化若改变区域边界且当前检查无法追踪，就不满足本命题。

## 10. 最小 worker 子类的自动实例覆盖引理 C

对阶段1最后限定的 worker 子类，`coverage.py` 不接收候选指定的实例数、
入口寄存器表或输出投影。它从 L 重建 worker 函数和所有直接 pthread_create
引用，确认 worker 内只有 asm 和常量 null return，标量结果确实没有其他 use。

记直接创建引用数为任意自然数 n。其检查要求：

1. 实际 Q 中同源 worker 恰有 n 个，且实际 ThreadCreate 到这些线程的链接构成双射；
2. 每个 worker 都找到一个可检查区域；整个区域消失也必须拒绝；
3. 用户内存端点无一位于区域之外；区域外未知地址、意外跳转拒绝；
4. 每个区域分别满足 D/R，静态全局对象的大小/对齐满足访问域；
5. 标量实参常量直接代入，地址由真实全局对象解释，不以寄存器名猜测状态。

证明：在受信宿主线程创建语义下，对直线 main 的创建引用顺序归纳，
得到 n 个可能激活的 worker 实例；worker 内无循环/其他调用且只有一个 asm，
故每个激活实例至多、在正常到达该点时恰执行一次该 asm。
实际创建链接和线程集合的双射检查给出实例匹配，逐实例区域检查覆盖其全部
用户内存端点。任何整实例丢失破坏数量或区域存在检查；多出的用户访问破坏
端点计数或区域外检查。

输出投影为空不是由候选声明的：源 worker 只返回 null，asm 的 SSA 标量结果
无 use，故该标量输出对其宿主后缀不可观察；实际区域若向其他宿主活跃寄存器
写值，保守 live-out 检查仍拒绝。全局共享写和原子排序从未被投影掉。

因此该有限但非固定 n 的子类可以由程序结构建立全部实例覆盖，
不需要测试 n=1、2、... 后外推。对更一般程序，此证明不适用，算法拒绝。□

本引理不替代“宿主 LLVM 到 Q 区域外上下文”的既有后端可信条件；
它也不把 source debug line 自身当作语义证据。位置仅提出区间，
数据/控制/配对义务独立决定接受。

## 11. 程序 verdict 的门槛与证明缺口

只有完整观察等式和可靠后端编码成立，才能双向转移 PASS/FAIL。
若只证明源包含于目标，仅能转移安全 PASS；反例还需独立可行性检查。
不完整有界展开中的“未发现错误”仍是 UNKNOWN。

已经给出的逻辑证明：H、L1–L2、V、D、R、固定 CAT 的 T、最小 worker 子类 C，
以及明确列出前提的组合推论。

尚未交付的证明/工程事实：完整 ISA 到所选端点语义的普遍桥接、
最小 worker 子类以外的任意优化/内联/循环展开来源覆盖、完整 GNU C 语义、
新增 Python/Java 实现的机械化精化、实际导出接入后的执行验证。
这些不是“再跑几个 litmus 就成立”的结论。程序级门禁保持关闭，
直到适用范围内的必要条件有实际证据，而不是把未知项写成 true。
