# 受限程序级安全转移：条件、定理与完整解析证明

基线：`25e67f8cf379c74857dd78bdf6e83f334555a269`。日期：2026-10-20。
本文件是**条件性数学结果**；不是已启用的程序级认证功能，也不是新对应合成算法。
现有实现是否落实每个条件，见 [02](02-chain-gap-audit.md)。
候选生成器正确性、后端 PASS、测试通过率都不作为证明前提。

## 1. 刻意收窄的语义域

首先只考虑如下 D₀，而非任意 C/C++：

- 固定 x86-64 Linux ABI、Clang 21.1.8、指定 Dat3M 提交及固定 TSO 模型。
  unsigned 32/64 位数值；有效、足够对齐、非混合宽度的普通 WB 内存。
  不包括 MMIO、信号、异常、自修改代码、事务、动态释放和未建模外部调用。
- 源宿主、展开的调用图、每个线程控制流都有限无环；线程创建树有限；
  创建、参数传递、正常返回和 join 的语义明确。D₀ 进一步取直线 main，
  静态整数全局对象、直接创建 worker、按指定 handle join、最后读取并断言；
  worker 使用已支持的 asm 和已支持的标量比较/断言。
- 输入域 D 写入证据，线程库模型暂规定创建/join 成功；否则必须建模失败路径。
  不能把无检查的 POSIX 创建成功或某个固定运行输入说成真实程序的全部行为。
- GNU 接口和汇编语义作为宿主的显式扩展。对竞争共享访存采用下面的硬件事件模型，
  **不借 ISO C 数据竞争 UB 把所有反例排除掉**。C 其余部分必须有定义；
  指针有效性、对齐和无溢出前提若未由检查器证明，必须列为输入契约。
  unsigned 模运算不需无溢出假设；LLVM poison/undef/带溢出标志运算不能默认套用。
- 目标没有后续任意 LLVM 优化。asm 替换前的 Clang 优化由宿主编译契约约束；
  替换后的实际文本、实际最终 Program 都要检查。

这不是把所有第三方库归入 D₀。CK 现有自建 harness 的形状接近 D₀；
其完整宿主契约仍未被实现检查。未来有限分支、多 asm 的推广不在本定理的
已实现范围中。D₀ 的有意义之处是允许多个真实并发 worker、共享原子操作、
活跃返回值与 main 的共享结果断言，不是只检查一个孤立块。

### 观察与模型

观察 `obs(g)` 包含输入、用户声明要观察的返回/局部值，以及已执行用户断言
`(源位置身份, 成立与否)`；`Bad(g)` 表示其中至少一个断言失败。
内部寄存器名、临时节点数及 `__com_...` 名称不是观察。
安全指所有合法**有限错误前缀**均不存在，而非只检查正常终止路径。
截断点在宿主步骤或原子操作边界，不把一个成功 RMW 截成半个指令。
线程阻塞/尚未终止不自动取消此前发生的错误。

参考执行由独立源语义产生，而非反向把 Q 定义为源：
`g=(E,lab,po,rf,co,rmw,activation,obs)`。
初始化写和全部宿主共享访存也在 E 内。每个读有一个同地址、同宽、同值的供值写；
每地址 co 为其全部执行写的严格全序，初始化符合初始状态。
`M=R∪W` 为内存端点集，`fr = rf⁻¹ ; co`，带 e 的关系限制为跨线程端点。
`A` 为 locked 相关原子标签。
以固定 CAT 中下列 T 公理为目标模型：

```
acyclic(po-loc ∪ rf ∪ co ∪ fr)
empty(rmw ∩ (fre ; coe))
acyclic(K ∪ co ∪ fr ∪ rfe)

K = (po ∩ ((R×M) ∪ (W×W)))
  ∪ (po ∩ (W×R) ∩ ((M×A) ∪ (A×M)))
  ∪ mfence
mfence = (po ; [MFENCE] ; po) restricted to M×M
```

另加控制、数值和显式线程生命周期约束。采用的实际 CAT 必须与这个实例对应；
仅有 “TSO” 字符串不够。固定文件见
[Dat3M tso.cat](https://github.com/hernanponcedeleon/Dat3M/blob/b81ec6c55503e824bb0ddc4ebac6c6f0a63d56d8/cat/tso.cat)。
ISA 到此 T 的桥接（包括失败 locked CAS 的 A 读）仍在 Γ 内。
本轮不声称证明完整 x86 ISA 与 CAT 等价。

## 2. 链中对象与五组可审阅条件

`S` 是真实源文件及依赖/config；`A` 是同次捕获的 AST/来源对象；
`L` 是该次 Clang 实际原始 LLVM；`L′` 是实际送入 Dat3M 的替换文本；
`Q` 是编码阶段实际 Task 的最终 Program；`Φ_bad` 是该 Task 的安全错误查询。
给源宿主 H 的 asm 位置留洞；一个静态洞、一个内联调用上下文、一个线程激活
是不同身份。D₀ 恰好限制到每 worker 一个静态洞；不因此把两个 worker 当作一次执行。

### C0：真实对象和完整作用域

固定源/依赖/config、编译器、模块、替换文本、后端二进制/CAT/选项及同次运行身份；
全部 surviving LLVM asm、可达源调用、入口和激活都在独立清单中。
源对象若被编译器消除，需由宿主编译契约证明对本观察不可见，否则拒绝；
不能只对幸存 asm 倒推源清单。D₀ 可通过拒绝额外可达函数/asm 避免一般消除问题。
来源连接依赖当前 Clang 元数据保真契约；缺失/冲突/不支持就拒绝。
本定理不提供不可信来源元数据下的新保证。

### C1：局部开放接口和语义检查

每个实际替换满足真实 GNU 绑定、类型、tie、clobber、生命周期条件；
原始操作数的求值、LLVM 入参和 Q 入区状态相关。
`BLOCK_EXACT`、`LLVM_FRAGMENT_EXACT` 和实际 `REGION_EXACT` 必须满足：

对任意合法入口 X 及任意独立共享读响应 U，各阶段的执行端点依次相同：
读写种类、宽度、地址、读值、条件写 guard/写值、A 标签、真实 rmw 配对、
必要排序；全部 live-out 相同。未声明局部状态不受破坏。
所有分支出口都覆盖，区域闭合且没有隐藏共享效果。候选生成器不提供参考答案。

纯计算可以产生多个 Q 节点；源 RMW 独立展开为读与有条件写。
成功 CAS 的写 guard 是 `u=expected`，失败时保留读、更新后的返回值和 A 标签，
不虚构写或成功配对。本轮不允许合并/删除执行的共享端点或任意移动 Fence。
因此无需一般非双射合成定理。

### C2：完整、开放的宿主契约 H

这正是当前链路尚未完整落实的条件。H 的内容不是一句“宿主正确”，而是：

1. 源/LLVM/Q 的对象身份、初值、宽度和指针绑定相同；入口输入域相同。
2. asm 洞之间每个纯宿主步骤有一个局部状态关系；真实求值给相同地址、值、
   分支条件与用户断言。每个源出边被覆盖，未走的边须语义不可能。
   live-out 成为下一个宿主步骤的输入；检查对**任意合法洞返回及读响应**成立，
   不能使用“目标最终安全”限制这些值。main 与 worker 一样必须解释。
3. 所有普通共享读写、初始化、监视器都被包含，顺序及其原子/排序种类相同；
   源/目标完整非洞清单恰为这些被检查步骤，不能遗漏未知语句或多余 Q 事件。
4. 创建条件、目标、参数、返回及 join 的 handle 关联保持。Q 的内部 pthread
   协议单独满足 `Γ_runtime`：投影隐去私有协议事件后，所有合法源生命周期
   前缀都能由 Q 实现；不添加用户对象访问、不删用户执行，不增加源已规定的
   生命周期/排序之外的用户限制。协议对象与用户对象不别名。
   只核对线程数量/名称不满足此条件。
5. 用户安全监视器一一对应，真假条件相同，错误标记不被后继 assume、
   提前终止要求或运行时隐藏。内部运行时断言可以另加，不能替换用户断言。

可选实现方式是一个只接受 D₀ 的宿主解释/比较器，逐语句检查上述关系；
不必实现一般 C 验证器。但本轮没有写出该检查器。
如选择把某一宿主步骤交给编译器 TCB，必须在证据中列出具体步骤及开放契约，
不能把 `STRUCTURAL_HOST_CONTRACTS_CHECKED` 改名为 H 已证明。

**有限组合用的局部充分条件。** 入口关系成立；每个非洞步骤对所有相关状态和
读响应保持关系、事件和观察；每个洞由 C1 保持；每次创建建立子线程入口关系；
每个出口/错误点都列出；全部步骤有有限秩且每次推进下降。
这些是检查 H 的有限义务，而非先假定最终 S/Q 观察包含。任意复杂宿主拒绝。

### C3：实例覆盖和全图框架

独立从 S/L 和 Q 各自产生全部潜在激活清单，经实际创建对象/目标/参数关联；
每个激活中的洞都有且仅有一个闭合区域证据。区域互不重叠，不共享证据冒充两次。
每条可执行源路径的洞均被覆盖；目标完整执行清单等于区域、已核对宿主与
已密封运行时的并集。守卫不允许把漏掉的实例解释成未执行。

在 C1/C2 的相关路径上，端点映射保持**跨区域** po，而非只保持每个区域内部顺序。
Fence 位置/排序同样属于完整线程框架。D₀ 无用户 Fence 时该项为空，
有 Fence 却未支持实际导出时必须拒绝，不能“当作 TSO 已经足够强”。
所有线程共用一个对象空间及全局 rf/co，局部检查不各自选择一套环境。

### C4：查询及结论释放

将源观察中的全部错误绑定到实际 Task 的安全属性（ASSERT/program_spec 等）
及 Q 的监视器。明确同一次运行的查询边界、push/pop、assumptions、SAT/UNSAT/
UNKNOWN、bound 检查结果；按 safety 类型解读结果，不能只读 PASS。
编码的必要外部契约是单向的：

```
Q 存在 D 范围内合法错误前缀  ⇒  实际 Φ_bad 可满足。   (ENC−)
```

它包含程序/数值/CAT 编码、静态分析、对称性约简、变量边界和错误前缀的保全；
不能通过不完整展开或不成立的对称性消掉错误。无环/有限线程必须是源码域检查，
不是随便指定一个 unroll 数。实际 backend 的 bound 协议也须完成或给出不截断证明。
要求正确求解**这一个**查询为 UNSAT，且求解器 UNSAT 可靠。
“保守过近似”会妨碍 FALSE，但可满足 ENC−；欠近似不满足。

## 4. 引理与证明

### 引理 1：局部语义接续

在 Γ_check/Γ_ISA 和 C1 下，每个洞对任意相关入口和开放读响应，在实际 L′ 片段
及 Q 区域中产生相同执行端点与 live-out。

证明：真实接口消费表和类型化源求值把 X 绑定到同一个入口。
每一级独立解释为无环、无 poison 的位向量表达式及带 guard 事件序列。
若某个被检查字段对某个 X,U 不等，这组赋值满足该字段差异查询，与可靠 UNSAT
矛盾；因此全称相等。guard 相等给出相同执行端点域，写值只在 guard 真时比较。
输出义务给相同 live-out。相同中间绑定上的等式具传递性，
遂从源参考到候选 IR、实际 LLVM、实际 Q 得到结论。未匹配事件/未知语句由清单
和闭合检查排除。未使用候选生成器的实现正确性。□

### 引理 2：有限开放线程及激活组合

假设 H 的局部充分条件和 C3 成立。固定一组源线程开放执行及其读响应，
存在一组相关目标执行，保持所有用户端点、观察、生命周期和全线程顺序。

证明：沿每线程有限步骤秩归纳。入口由 H.1；纯步骤/普通访存由 H.2/H.3
保持状态和单步事件；遇洞应用引理 1，其输出成为后继归纳假设，不能另选输出。
分支条件相同，所以跟随相同源边；所有边被覆盖故不存在只能沿未证明边
继续的接受情形。错误点按 H.5 保留，可以在该点终止前缀论证。
创建时 H.4 建立对应子线程入口，按有限创建树归纳将同一论证应用于子线程；
join 对象相同，已规定的生命周期约束随之保持。C3 禁止重复借用一个激活。
每个有限源前缀均在有限次归纳后得到目标前缀，无循环空进展。
普通访存和区域内端点互不交叠且穷尽，故所有局部映射的并是用户与初始化
端点上的双射 f。C3 的全线程检查给跨区域 po 保持，不只给局部 po。
目标运行时内部事件随后由 Γ_runtime 的全环境契约实现。
这里还未选择新的 rf/co；构造统一使用给定源的读响应。□

### 引理 3：固定 T 的全局相容性

在前两引理及 C3 下，每个合法源用户执行图有观察相同的合法目标用户图；
Γ_runtime 将后者实现为 Q 的合法图。

证明：任取合法源图 g。用 g 的读值作为引理 2 的 U。令
`rf′=f(rf)`、`co′=f(co)`，而不是让每区域各自选择 rf/co。
f 保持全部写、初始化、地址/值/宽度，故供值唯一性、co 严格总序及初始条件保持。
由关系逆、复合和限制在双射下可交换，`fr′=f(fr)`，
`rfe′=f(rfe)`、`fre′=f(fre)`、`coe′=f(coe)`。
po-loc、真实 rmw、A 和 mfence 均保持，故三条 T 公理的关系分别是源关系的
重命名。若目标有一条禁止的环或原子性违规边，沿 f⁻¹ 即得源的同一违规，
与源合法矛盾。因此目标用户图合法。失败 CAS 的读仍带 A，所以 K 的推导未
遗失失败排序；成功 rmw 的真实配对用于原子性公理，不能被“两个事件相邻”替代。
H/C3 保持控制与激活，Γ_runtime 按其全图实现契约增加私有协议事件且不破坏
用户可实现性。引理 2 保持观察，得到结论。□

这里使用端点保持子类；纯计算/CondJump 数量可不同，但没有发明一般事件
消除/合并证明。Γ_runtime 是明确外部缺口，并未由关系重命名证明任意运行时。

### 定理 E2E-SAFE（最小条件式安全结果转移）

在 D₀、Γ 下，若 C0–C4 全成立且实际 `Φ_bad` 得到可靠 UNSAT，则

```
Obs_T,D(S) ⊆ Obs_T,D(Q)
不存在合法源错误前缀；即 Safe_T,D(S)。
```

证明：C0 使所有检查引用当前 S/L/L′/Q，而不是旁路副本。
引理 1–3 对任意源合法图构造同观察的 Q 图，得到第一式。
若源不安全，取其有限错误前缀 g。第一式和 H.5 给出 Q 的错误前缀；
ENC− 蕴含实际 Φ_bad 可满足，与 Γ_solve 和已绑定的 UNSAT 矛盾。
因此源安全。证明没有使用 S 安全以选择输入、路径或对称性；也没有使用 PASS
来证明 Γ_encode、Γ_runtime 或宿主正确。□

这是一个闭合的**条件定理**：所有未证明的外部事实明确列为 Γ，
所有尚未实现的证据条件明确列为 C。逻辑证明完成不等于这些条件对现有产物已成立。
定理主要内容是把局部开放等价、完整宿主/激活、统一环境与真实查询接起来；
不是对已有 PAA/Stellite/VALID/Kater 机制的新数学贡献主张。

### FALSE 方向不能偷换

上面的包含方向用于安全 TRUE：源行为必须包含在验证目标允许的行为中。
只证明 `Obs(Q) ⊆ Obs(S)` 可丢掉源坏行为，不能转移 SAFE。
目标 FAIL/SAT 要推出真实源错误，另需具体满足赋值解码为合法 Q 错误执行，
以及该执行的源回译见证；或完整反向包含与精确编码。
本定理不给出这个结论，也不把目标的内部运行时断言失败称为源用户断言失败。
发布协议应区分 `CONDITIONAL_SAFE`、`VALIDATED_SOURCE_COUNTEREXAMPLE`、
`BACKEND_FAIL_UNCONFIRMED`、`REJECT/UNKNOWN`。

## 5. 对前提的解析攻击（不是本轮运行的负例）

| 去掉的条件 | 有限反例及推导 |
|---|---|
| main 监视器核对 | 源 main 在 join 后断言 `x=0`，worker 确实写 1；目标删除该断言。局部 asm 完全正确但源错误不再是目标错误 |
| 活跃输出接续 | 源 FAA 返回旧值 u，断言 `u!=0`；目标把返回寄存器替成 1。共享事件相同仍会漏掉初始 x=0 的错误 |
| join 关联/生命周期 | join 第一个 worker 被当成 join 两个；源允许第二个尚未完成时观察中间值，目标过强等待会删行为。反方向错 join 也可能增加伪错误 |
| 覆盖源域、执行条件 | 源有两个无条件创建，目标保留一个；只认证剩余区域仍全部 EXACT，第二个 worker 造成的错误遗漏 |
| 全局环境 | 每片段各选相容 rf/co，不能推出选项可合并成一个全图；引理 3 必须从同一源 g 输送一次 |
| 原子标签/真实配对 | 删除 A 改变 W→R 顺序；改 pair 可允许另一写插入 RMW；“R/W 值相等”不蕴含原子性 |
| 安全方向 | 加强目标为 SC 可消去 TSO Store Buffering 的双零行为；目标证明“非双零”不能证明源 TSO 同性质 |
| 有效输入域 | 把自由增量误绑定常量 1，可能删掉零增量/溢回路径；这不是同一程序的安全证明 |
| 查询边界/属性 | 最后一个边界查询为 `false` 时 UNSAT 恒成立，不论先前错误查询是否 SAT；或漏掉用户断言时属性本来恒真 |
| 前缀约定 | 源先失败 assert 后执行不可满足 assume，若只检查可完整终止路径则错误被未来条件擦除 |

这些反例说明条件不能省略，不说明当前 gate 已放行了它们。
当前 `program_verdict_eligible=false` 必须保留。
