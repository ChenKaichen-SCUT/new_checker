## 对当前状态的四个关键回答

1. **受限程序级安全转移还没自动闭合。**
   worker 的 asm/活跃输出/实例证据已存在，但 main 用户监视器、join/普通宿主
   语义及实际错误查询绑定尚未完整核对。保持 `program_verdict_eligible=false`
   是正确的；这轮条件定理不能将其自动改成 true。
2. **正确行为方向已经明确。**
   从源错误构造实际 Q 错误，再由无遗漏的错误编码得到可满足查询，
   才能用该查询的 UNSAT 推出源安全。全局只输送同一套 rf/co。
   后端 PASS、末次 UNSAT 和局部 EXACT 都不单独具备这个含义。
3. **最优先的覆盖扩展是接口和上下文。**
   P0 先补宿主/任务门禁；P1 优先非固定参数、有限宿主数据流、活跃输出和
   多 asm/多调用上下文。真实库循环、复杂指针/运行时仍构成明确上限，
   不能用新增指令数替代客户端覆盖。
4. **系统贡献有机会，但证据明显不足。**
   已有原理的组合可以形成可复用且可信边界清晰的系统；
   一个原始 CK 例程在自建 harness 中成功，尚不能证明实际库覆盖、低成本或
   广泛有效性。当前不继续包装 PAA/Stellite/VALID/TSO 关系技术为新算法。
