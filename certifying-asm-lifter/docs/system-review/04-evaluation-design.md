## 1. 研究问题与主张边界

| RQ | 要回答的问题 | 不能替代它的指标 |
|---|---|---|
| RQ1 适用性 | 固定真实配置中，多少源位置/调用上下文能解析、提升、逐层认证？拒绝在哪里？ | 库头文件中 asm 字符串数量、单个例程成功 |
| RQ2 安全结果可信性 | 完整契约成立后，SAFE/FALSE 是否能按各自方向转移？不支持是否拒绝？ | 后端 PASS 比例、全部局部 UNSAT |
| RQ3 实际价值 | 相比现有流程，是否新增真实可验证对象、阻止真实错误结论或减少人工工作？ | 注入故障数、支持指令数、只在自建 litmus 上跑通 |
| RQ4 成本 | 捕获、合成/提升、独立认证、后端验证各耗多少资源？成本随什么增长？ | 只统计成功小查询时间，忽略构建/捕获/失败 |
| RQ5 复用性 | 独立重查器能否在干净环境核验证据，另一个转换候选是否可接入？ | 与 lifter 共用预设映射、依赖作者机器缓存 |

主张限定为固定 ISA/模型/宿主子域内的可认证转换系统。
“适用于某库的一些例程”和“验证整个库”分开；发现的运行时/接口问题也不自动等于
源程序缺陷。理论正确性依赖解析证明，实验用于检验实现与外部有效性。

## 2. 样本和不可变单位

预先冻结项目提交、许可、配置、ABI/类型、原始源与依赖哈希、Clang/后端版本、
优化选项、内存模型、线程/输入域、性质及资源限制。
一个 program task 是
`(项目,提交,原始客户端/TU,配置,输入域,性质,模型)`，不是一次线程实例。

样本分四组，分别汇总：

1. **历史回归**：现有最小例、活跃输出、CAS、CK；保留旧快照，之后新跑另存目录。
   用于防退化，不当作新外部验证证据。
2. **未修改上游例程/客户端**：第三方原始接口及真实调用方。
   可写单独 harness 提供输入/线程/观察，但必须公开其大小和假设，
   标注“上游例程+自建 harness”，不能叫未修改上游整程序。
   上游自带测试、完整上游并发客户端另列。
3. **区分性受控样例**：多调用、同 asm 多上下文、参数/活跃控制/活跃地址、
   单因素错误。用于归因，不计作真实库覆盖或新缺陷。
4. **范围外对象**：循环、未支持类型/指令/调用等。检查稳定拒绝和诊断，
   不把不支持隐藏为 timeout，也不修改来源使它变成范围内。

静态 census 必须先于挑选正例：记录配置下 TU 的完整 asm 清单、静态位置、
调用上下文、可达性及未知项；预处理/构建失败也进入 task 母集。
无非空 asm 的 builtin 配置单独报告，非空 asm 分母为零时写 N/A。
空 compiler barrier 单列，不能和非空指令混成“提升数”。
宏同一模板的不同上下文既分别统计上下文，又按模板去重报告，避免数量虚胖。
URCU/AO 的来源相似性按模板谱系聚类，不能据三项目名字推独立多样性。

开发集与留出集按例程族/客户端划分，避免同宏在两边泄漏。
观察到失败后新增支持的对象回到开发集；不能事后仍称完全留出。
不宣称小型目的性样本代表全部 GitHub 或所有并发库。

## 3. 指标、分母和结果标签

每阶段同时给 task 级和源实例级记录，绝不将它们相除：

| 指标 | 分子 / 分母 | 必须补充报告 |
|---|---|---|
| 解析率 | 完整恢复 GNU 类型/约束/操作数的源实例 / 配置后独立识别出的非空相关源实例 | 未能配置的 task 数另列；宏/内联位置去重口径；词法扫描不算解析 |
| 提升率 | 自动产生合法实际替换 LLVM 的实例 / 已解析实例；另报 / 全部相关实例 | 编译成功只是 lifting 成功；源码/接口是否修改 |
| 局部认证率 | 所需局部层均通过的实例 / 已提升实例；另报 / 全部相关实例 | BLOCK、LLVM、REGION、live-out 分层漏斗和所有拒绝原因 |
| 完整链认证率 | 所有源/目标实例、宿主、任务绑定均满足的 task / 全部非空 asm task | 缺一个实例的 task 整体不成功；partial 不充数；Γ 随结果发布 |
| 程序结论可转移率 | 满足 C0–C4 并得到有资格结论的 task / 全部 task | 分 SAFE、已核源反例、REJECT、UNKNOWN、TIMEOUT、CRASH；不得只报 PASS |
| 程序验证正确率 | 在**独立真值已确定**子集上，正确有结论数 / 有结论数 | 必须同时给整张真值×输出矩阵及有结论覆盖；未标注任务不算正确 |
| 真实缺陷 | 经独立语义论证/真实见证确认的不同根因数 | 源缺陷、上游转换缺陷、checker 缺陷分开；注入、历史已知、新发现、维护者确认分开 |
| 认证开销 | 同一候选/后端任务增加 checker 的墙钟/CPU/峰值内存、义务和证据大小 | 捕获、生成、认证、后端单列；成功与失败成本、cache/冷启动分开 |

真值矩阵至少列：

| 真值 \ 输出 | 条件 SAFE | 经源验证的 FALSE | UNKNOWN/REJECT/资源失败 |
|---|---|---|---|
| Safe | 正确安全结论 | 错误 FALSE | 无结论 |
| Unsafe | **错误 SAFE（必须停止释放）** | 正确反例 | 无结论 |
| Unknown | 不计正确率，保留待核 | 不计正确率，保留待核 | 无结论 |

报告“正确率 100%”而只给两个有结论对象没有说服力；
同时报告 false-SAFE、false-FALSE、拒绝比例和真值覆盖。
零观测错误不证明系统无错误，也不替代定理/TCB。

### 独立真值与非循环性

- 小受控程序优先用可人工审阅的解析全行为论证，明确同一个 T 与输入域。
  错误程序用真实源执行见证及 T 合法性证明；原生运行只能给某些存在性证据，
  不能证明所有 TSO 行为或安全。
- 真实客户端可以使用独立可信验证/证明或公开已核对性质。
  未获真值时保留 Unknown。不同工具意见不一致只触发调查，不以多数票定真值。
- Checker 自己的 EXACT、同一后端的 PASS、同一 SMT 编码的第二个 solver
  都不能充当整个系统的独立真值 oracle。第二 solver 可定位 solver 问题，
  无法证明共同编码没漏错误。
- 若环境前提不同（内存域/线程成功/别名/边界），结果不能直接放入同一正确率表。
  严格子域结论必须携带该域，不能作为原始无限域 SAFE。

## 4. 公平对照

| 对照 | 固定什么 | 能回答什么；不能声称什么 |
|---|---|---|
| 无 Checker 的直接转换 | **同字节 L′**、同 Clang 捕获、同 Dat3M/CAT/性质/资源；仅绕过认证 | 隔离检查成本和阻止错误释放的作用；两边 PASS 都不自动是正确结果 |
| 原始 Dat3M | 固定未修改上游版本，真实原始 LLVM（含 asm）；相同程序/属性/模型；保存工具原始支持/忽略/崩溃行为 | 判断现有流程可处理什么和真实转换风险；不手动删 asm、不替原工具修输入后称原始基线 |
| 带只读导出的 Dat3M | 与上游差异明列、钩子只读的代码审阅；后续可做相同候选的结果核对 | 核对 instrumentation 干扰；一致性运行是辅助证据，不是只读性的数学证明 |
| 旧 Checker（本基线） | 同捕获对象/版本和合法输入域 | 新非固定输入/多调用等能力的增量；旧系统拒绝是正常范围结果，不记“错误” |
| TInA / 适用 lifting | 冻结其公开 artifact 与支持 ABI/编译器；共同支持的原始输入交集；分别记录工具所需编译流程 | 比较提升/接口适用性、人工工作和验证友好性；没有 TSO/RMW 语义桥时不直接比较 SAFE 准确率 |
| RUSTInA 等接口分析 | 各自真实支持域，原始 GNU 接口 | 补充接口错误检测，不冒充完整并发 lifting 竞品 |

[TInA 论文 §VI](https://arxiv.org/pdf/1903.06407) 有块级对应/SMT 检查，并在失败时使用
测试后备；本方案必须将其形式验证结果和后备测试分开，不能将全部 lifting
标为已证明并发安全。实际 artifact 的架构/版本兼容性需在后续预检确认，
当前没有运行它，不能预先宣称其在这些 64 位对象上成功或失败。
若工具只能支持另一个 ABI，选择真实同 ABI 配置作独立子组；
不可静默把 64 位源改为 32 位。
[RUSTInA](https://arxiv.org/abs/2102.07485) 的接口合规任务与本系统结论不同，
报告互补能力即可。其他 lifting（包括 Hetrify）只有在取得相应公开实现、
确定语义与输入范围后加入；全文/实现信息缺失写不可评，不作无能力推断。

PAA/VALID/Stellite/Kater/KATI 是原理/证明条件对照，不是已经开箱可运行同一
GNU→Dat3M 工作负载的性能基线。沿用[既有组合审查](../combination-review/00-delivery.md)，
不再把它们的基本机制重新命名为新算法。

**不可比时的处理：** 共同支持交集的 paired 数据与整体适用性表同时展示；
unsupported 不计为错误 SAFE，也不能从总成功分母中消失。
所有适配/手写规范/手动映射的行数、时间、是否需作者知识都记录。
无需用不公平的“所有工具都失败”论证系统价值。

## 5. 正确性压力与真实缺陷

受控故障每次只破坏一个条件，并先确认其余层前提仍成立：

- 丢一个共享写；只错更新表达式；只改条件写 guard；
- 仅去掉 A 而保留 rmw、仅错配 rmw 而保留 A；失败 CAS 排序单独检查；
- LLVM 宿主不变，真实 Q 漏一个激活；或保留数量却换创建参数；
- 源/实际 LLVM 输出仍相同，但 Q live-out 使用错误；错入口 SSA 绑定；
- 仅删/改 main 用户断言；仅错 join handle；仅错任务 safety 属性/查询阶段。

对应的良性变动也要检查（合法临时寄存器重命名、等价局部表达式、重复宏不同上下文），
否则一个“一律拒绝”的实现也能捕获全部坏例。
良性范围外变动必须标为保守拒绝，不谎称 checker 误报语义错误。
每个坏例有独立解析理由，检测数量不是可靠性证明。

现有 Dat3M 真实转换错误是**历史已知缺陷**，后续重新检出算回归/价值示例；
多个输入触发同一根因只计一个。现有人工 ControlledFaults 不是上游真实缺陷。
新缺陷须保留原始源、配置、实际对象、最小化但未手改接口的复现、正确行为推导，
以及定位到工具或源的根因。没有独立确认的只叫“疑似”。
这份计划不授权向维护者发送消息或提交报告。

## 6. 开销、消融和数据保存

运行预算/硬件/并发度/内存限制在批准实验前冻结；不同工具同资源，
工具专属参数公开，不为每个失败对象事后调参。
同一候选拆出：

`T_capture + T_lift + T_local-cert + T_backend + T_global/host-cert + T_verdict-bind`

并给未启用 checker 的配对总时间与差值。backend 计算和导出混在一起时同时给
只读导出成本的单独对照；不可把已产生 Q 的成本算成零成本。
重查已有证据与首次生成是两种工作流，分别统计。
冷/暖 cache 分组；若测时，每组建议预定 5 次并打乱顺序，报告中位数和范围，
不是五次挑最快。具体预算需后续批准，不在本轮启动。

同时给义务数量、最大 SMT 大小、候选区域/上下文/激活数、实际共享事件数、
峰值内存、原始证据字节；timeout 与 crash 独立列且报告已耗时间。
paired 成功子集的比值必须伴随总体覆盖，不能用删掉超时对象制造加速。
小样本不做总体优越性的显著性宣传；若后续规模足够，按独立程序/谱系聚类分析，
不把同一程序两个 worker 或多次测时当成独立项目样本。

消融只用于回答清楚的问题：

- 同候选开/关 checker：成本与错误释放差异；
- 固定工具链下依次加完整宿主、多调用、非固定绑定、活跃后继：新增可认证对象；
- 去掉某证据层：仅用于诊断其必要性，不发布该配置的 SAFE；
- 用来源提示/不用提示的通用搜索不在本轮系统路线。

每 task 保存原始 S/依赖/config、同次 A/L、L′、实际 Q、具体 SMT/查询协议、
检查输出、日志、TCB/作用域、所有拒绝原因及不可变哈希。
证据重查器应消费这些实际对象并重建义务，不能只信任 `result=EXACT`。
历史目录只读，新运行另建版本目录；公开数据排除工具链二进制缓存/凭据。

## 7. 执行门禁与可能否定结论

下一次只允许在批准后做小批 P0 与一个 P1 功能验收，不直接启动本方案的全面评测。
若实际源码 census 显示有限无环域几乎没有有意义客户端，应明确报告范围不足；
不能挑出原语后仍称验证了其算法。
若独立 lifting 在相同保证/成本下已解决全部需求，应缩小为复用/复现贡献或停止
独立论文定位；若系统能可靠认证更多真实调用但无新数学机制，仍可成立工具贡献。
