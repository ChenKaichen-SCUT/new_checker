# 解析反例、区分性设计实例与退出条件

**全部例子均为逻辑构造，不是本批运行结果。** 没有生成替代 LLVM、伪造后端快照，
也没有用枚举、测试或 SMT 运行代替下列论证。伪码中的 R/W/FAA/CAS 表示明确模型
中的操作；不是声称含数据竞争的普通 ISO C 自动具有这种语义。
GNU/宿主桥接仍按 [02](02-problem-definition.md) 单列。

## 1. 攻击“常规编译精化就够了”

初值 x=0，源线程执行 `W(x,1); W(x,2)`，另一线程执行
`r=R(x); assert(r!=1)`。目标将前一线程缩为 `W(x,2)`。

源存在执行顺序 `W1,R1,W2`，使断言失败；此 SC 顺序也为固定 TSO 允许。
目标只有初始写 0 和写 2，读不可能从任何写取得 1，因此这个错误消失。
在只观察末态、没有并发上下文时，两段写序列同为 x=2；该检查不充分。

目标行为减少可以符合常规优化精化方向，却破坏由目标安全推源安全的要求。
不能以 VALID/Stellite 证明了某方向的删除合法，就未核对方向地收入 `EXACT`。
如果声称只保持特定性质，必须另外证明该性质的错误反射。

## 2. 攻击“相同模板就能选择来源”

单线程 x=0，执行两次 `r1=FAA(x,1); r2=FAA(x,1)`，随后检查 `r1==0`。
原子语义与线程顺序给出 r1=0、r2=1。若把第一调用的活跃结果绑定为第二次返回，
断言会失败，尽管两处 asm 模板、约束和事件类型完全相同，最终 x 仍为 2。

反之，两个完全相同且无可区分后继的来源交换，可能存在两个都充分的语义对应。
算法不能一方面按文本随意选择、另一方面声称找到了唯一历史。
需要的是输入关系、路径顺序、活跃输出和完整覆盖共同验证。

## 3. 攻击“一个源点通过一次就是全部出现通过”

主线程创建两个 worker，每个 worker 对 x=0 执行一次 `FAA(x,1)`，join 后观察 x。
两次原子更新不溢出且串行化，源最终 x=2。若目标保留创建框架和两个线程对象，
只删除第二个线程的 FAA，最终 x=1。

保留下来的区域即使全部义务成立，也不能覆盖消失的出现。
检测应来自源创建/调用结构和目标执行责任，不是碰巧 LLVM 字节也改变，
更不能用目标实际发现一个区域反推“源只需要一个实例”。

## 4. 攻击“RMW 拆成同地址读写即可”

两个线程各执行一次原子 `FAA(x,1)`，x 初值为 0。
若拆成彼此没有真实 rmw 约束的普通 `r=R(x); W(x,r+1)`，
允许两线程都读取 0，再各写 1；最终 x=1。原子 FAA 的两次成功更新则最终为 2。

同地址、同写值公式、每个节点都被匹配，仍不足以保证原子性。
该变化否定 `EXACT` 与一般反例转移；**仅多出目标行为不必否定安全方向的过近似**。
因此，负例的拒绝理由必须对应证书模式，而不是将所有行为差异混为同一种不可靠。

## 5. 攻击“失败 CAS 没写，所以其 A 标签可以消失”

固定使用基线 `tso.cat` 的定义（见 [修订定义 §7](../revision/02-objects-and-obligations.md)）。
x=y=z=0，且无其他线程写 z：

```
T0: W(x,1); locked CAS(z, expected=1, desired=2); r0=R(y)
T1: W(y,1); mfence; r1=R(x)
```

CAS 必失败，保留读 `Rz(A)`，其写 guard 为假。考虑 r0=r1=0：

- `Wx → Rz(A)` 属于 `implied`；
- `Rz(A) → Ry` 属于 `po-tso`；
- `Ry → Wy` 属于 fr；
- `Wy → Rx` 属于 mfence；
- `Rx → Wx` 属于 fr。

这些边形成 ghb-tso 环，故源禁止该观察。
仅删 `Rz` 的 A 标签、保持静态 RMWStore 配对和 false guard 时，
`Wx→Rz` 的 implied 边消失。取两个读各读初始写，co 为各初始写在对应写之前：
剩余跨线程链为 `Rz→Ry→Wy→Rx→Wx`，没有返回 Rz 的边；同址一致性成立，
执行 rmw 为空，故该候选满足这些 TSO 公理。目标因此新增该观察。

这隔离了标签作用，未同时破坏配对。它否定双向等价/反例真实性；
如只要求安全过近似，仍须证明全部源行为被目标包含，不能仅凭这个例子接受。
此论证针对固定 CAT，不替代所有 ISA 内存域的架构证明。

## 6. 攻击“条件写只需核对成功时的值”

源 CAS 写 guard 为 `u=e`。目标误用 true，其他字段均相同。
在 `u≠e` 时源无写、目标有写，写值在 `u=e` 下相等毫无帮助。
反向误用 false 又会漏掉成功写。两者都可能改变另一线程可读到的值。

义务必须包含执行条件的相应方向关系，`EXACT` 需要等价。
不能把源条件附加为所有义务的全局前提，使失败路径自动消失。

## 7. 攻击“入口不变量由合成器自由给定”

源 `if (b) FAA(x,1); else assert(false)`，目标只有相同 FAA。
合成器选择入口关系 b=true，可使选中区域看起来正确，却丢掉 b=false 的源错误。
即使后续不变量保持全部成立，仍不能得到全输入保证。
入口完整性必须由原合法输入域推出关系，不能仅证明关系可满足。

## 8. 攻击“名称不同可以重排”

源 `W(p,1); W(q,2)`，目标交换两写。若 p=q 且无其他线程，
源最终值为 2、目标为 1。参数名不同、LLVM SSA 不同都不蕴含地址不等。
除非 ABI/已证明路径条件给出不别名，必须覆盖该别名赋值。
同理，按地址给两次读复用一个响应会错误禁止其他线程在两读间写入。

## 9. 攻击“每个区域分别正确，就可以任意组合”

源 T0：`W(x,1); W(y,1)`；目标交换二者。
T1：`a=R(y); b=R(x)`，初值均为 0。

源中若 a=1 且 b=0，则 `Wx→Wy` 为 po-tso，`Wy→Ry` 为 rfe，
`Ry→Rx` 为 po-tso，`Rx→Wx` 为 fr，构成禁止的环。
目标可先写 y，随后 T1 读 y=1、x=0，最后写 x；这是合法 SC/TSO 执行。
两个单写区域的字段分别完全相同，丢失的是跨边界顺序关系。

更一般地，`∀H. ∧j ∃Wj. Local(j,H,Wj)` 不推出存在一个彼此相容的全局 W。
例如分别允许的两份局部见证可能要求同位置写的 co 顺序分别为 a<b 与 b<a；
各条件独立可满足，合取不可能。这里是量词/兼容性反例模式，不声称已构造了一个
通过完整 Stellite/SEQ 检查的程序；这些框架的环境条件正是为排除此类问题。
新组合引理必须保留相同环境及共享边界见证，不能把这些条件省略。

## 10. 攻击“静态全覆盖足以处理循环”

源前两次循环安全、第三次执行 `assert(false)`。目标的有限展开只保留前两次。
每个被导出的静态副本均有证书，仍没有证明源所有动态出现被覆盖。
仅有展开界 k 的结论必须标成有界；要升级为整程序结论，需证明实际访问不超过 k，
或提供归纳关系与必要进展证明。

同样，把某一侧可无限执行的纯 τ 环当成一次“无观察停顿”，会使其永远不达到
另一侧的有限错误。若证明通过局部模拟建立有限坏前缀包含，就必须排除这种伪匹配，
或在所选语义下提供足够的进展条件；不能仅写“双方均可走零步”。

## 11. 攻击“快照有哈希所以对象真实”

不忠实导出器可以输出预期事件并给它算正确摘要，而实际 encoder 使用另一图。
摘要校验仍通过。因而输入真实性需要实际对象身份、运行接入点及可信捕获器，
不能仅由 JSON 内容相符建立。
不信来源提示的目标也不等于已经消除了 AST 解释器、ISA 参考或导出器的 TCB。

## 12. 五个未来区分性实例：仅设计，不伪报接受

| 编号 | 计划的真实输入/变化 | 预期接受条件 | 旧方法的静态障碍/新方法状态 |
|---|---|---|---|
| D-A | 同一 worker 两次调用原始 CK `ck_pr_faa_32`，第一次返回影响第二次实参或后继断言 | 两次 GNU 接口、原 LLVM 与 Q 均实际捕获；活跃关系与所有效果/创建完整；不得改 CK | 旧唯一 asm/worker 形状拒绝；新方法尚未实现 |
| D-B | 同一个原始 CK 内联函数从两个静态上下文调用 | 自动合成两份调用实参/结果关系及实际复制覆盖 | 旧单一直接调用与内联上下文限制；新方法待证明 |
| D-C | D-A/B 的提示缺失、重复或错误，真实语义对象保留 | 不把 h 当接受事实，找到任一完整语义对应；无法恢复唯一历史不影响正确接受 | 旧唯一 cookie/debug lineage 前提不满足；未运行提示故障 |
| D-D | 两个互斥源分支中的相同操作，目标只有一个共享操作；或相邻双 mfence 合为一个 | 前者须 guard 完整及分支关系；后者须固定 TSO 的独立删除规则和观察限制 | 旧静态结构/端点限制不能直接表达；是否实际发生需以后用真实产物验证 |
| D-E | 保留 LLVM 宿主和真实线程创建，仅后端漏掉一个执行实例 | 完整覆盖义务拒绝，不依赖其他字段同时坏掉 | 未来隔离检测能力；不是证明替代物 |

D-A 的调用壳可采用如下**设计伪码**，不是对上游 CK 的修改：

```c
uint32_t a = ck_pr_faa_32(&x, 1);
uint32_t b = ck_pr_faa_32(&x, a + 1);
assert(a != FORBIDDEN_A);
assert(b != FORBIDDEN_B);
```

验收时参数、输入域和断言应另行固定，保留上游 header、类型和接口原样，
由真实 LLVM/Q 恢复关联；本批没有声称该壳已被当前 Clang/Dat3M 接受。
其非平凡之处是第一结果跨 asm 边界成为后一个更新的输入，不仅增加相同模板次数。

D-D 的两个版本须区分：

- 互斥静态合并：每条执行仍只有一次共享操作，动态事件无需真正合并；
  这很可能落入 PAA/JTFG 已有能力，不作为强创新证据。
- 共同执行的 fence 合并：真正改变内部事件数；固定 TSO 中两个相邻 mfence
  约束的同一批前后访存不因保留一个而减弱，是已有 fence 优化理论的候选实例。
  它能区别旧实现，不能区别 CompCertTSO。是否有真实流水线产物体现该变化尚未知；
  不能为得到这个例子手写替代 LLVM 或宣称 volatile asm 必然被合并。

因此，**本批没有满足“新算法已经认证一个旧算法不能认证的实例”**；
那是第二、第三批要分别以定理和真实材料建立的成果，不能提前用设计填充。

## 13. 研究退出条件与审稿判断

| 审稿问题 | 本批答案 | 下一批才可改变判断的证据 |
|---|---|---|
| 技术问题明确吗 | 是：提示不可信时的语义对应、动态覆盖及非双射并发历史 | 精确受限定理与可检查实例 |
| 新算法机制已成立吗 | 否；候选搜索/产品/SMT/覆盖均有强先例 | 超出已知简单组合的充分性或分解结果 |
| 保证更强/范围更大吗 | 规格目标更大，尚无新保证 | 完整证明，不能以定义当结果 |
| 能处理真实程序吗 | 旧系统有 CK 证据；新范围没有 | 未改上游真实对象的新链 |
| 定理有实质内容吗 | 待定；真正难点是环境与覆盖组合 | 非双射充分性、进展及错误转移闭合 |
| 成本可管理吗 | 未知；最坏情况明确可能爆炸 | 先给结构界，之后少量针对性检查 |
| 简单组合可完成怎么办 | 停止独立理论创新主张 | 可另评工程系统价值，但不改名包装 |

第二批建议先尝试把 D-A–D-D 完全归约到 PAA/JTFG + 已知并发规则。
若没有一个不能由合理组合直接处理的关键技术义务，给方法路线 **No-Go**。
若存在明确差距，再选择一种固定模型和窄变换闭合证明。
若证明需要假定“所有历史可匹配”或“所有动态实例已正确恢复”，仍未完成本任务，
应报告缺口或缩小结论，不进入实现以实验掩盖。
