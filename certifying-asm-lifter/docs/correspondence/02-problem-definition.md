# 问题定义：认证语义对应，而非猜测唯一历史

状态：第一批的规格设计。下文的目标性质不是新算法已满足的定理。
已有范围见 [基线审阅](05-baseline-review.md)，文献归属见 [算法审计](01-literature-audit.md)。

## 1. 对象、身份和语义分别定义

一次待认证任务输入以下不可变对象；对象身份用原始字节摘要和实际捕获记录固定，
但摘要本身不证明捕获器忠实。

| 符号 | 对象 | 不得偷换为 |
|---|---|---|
| S | 原始 GNU C/C++ 翻译单元、实际包含文件、编译选项及宿主语义 | 从目标事件反推的“预期源程序” |
| A(S) | 可信解析/经检查解析得到的类型化源表示，含宏展开后的全部 asm 节点、约束、表达式和宿主控制流 | 人工选出的一个 GCCAsmStmt |
| L | 同次实际编译得到的、尚含 inline asm 的 LLVM 程序 | 手写的规范 LLVM |
| L′ | 待验证转换器实际生成并交给后端的 LLVM 程序 | 只证明转换模板、却不检查实例化结果 |
| Q | 同次实际求解所用的最终核心 Program，含真实事件、表达式、控制流、线程和关系端点 | 另一轮导出的近似事件清单 |
| M | 固定版本的 ISA/混合宿主语义桥接与目标内存模型，及模型之间的明确关系 | “x86”或“弱内存”这样的名称 |
| Γ | 明列的语义、工具与上下文前提 | 把尚待证明的对应充分性藏成假设 |
| h | 可缺失、冲突或错误的 debug、cookie、行号、内联来源等搜索提示 | 最终接受的真值依据 |

若源侧混合模型与 Q 的 CAT 模型不是同一个模型，使用 `M_S`、`M_Q`。
写 `Obs_M` 只是已明确建立桥接后的简写；不能由模型名称相似推出桥接。
本项目现有可运行范围是固定 x86/TSO 子类，**不是完整 GNU C++ 内存模型**。

### 五种不同的“实例”

1. **拼写位置** `p`：文件内容身份、token 区间和宏定义位置。一份宏体可被展开多次。
2. **展开后静态源节点** `a`：实际 A(S) 中的 asm 身份。记录完整展开栈；`p→a`
   可以一对多。源节点数不等于 LLVM 存活 asm 数。
3. **调用上下文** `κ`：从入口到 a 的源调用路径；无递归时可有限表示。
   相同函数中的 a 可在多个 κ 执行。真实 LLVM 的静态复制身份另外记为 `ℓ`，
   不先假设有可信函数 `ℓ↦(a,κ)`。
4. **动态出现** `o=(a,κ,τ,ν)`：某条执行中，线程激活身份 τ 下的访问序号 ν；
   ν 可含循环/递归访问历史。同一静态节点可以零次、一次或多次发生。
5. **目标静态事件节点与执行事件**：Q 中节点 `q` 可在某次有限展开中有独立身份，
   在一般循环语义下则须连同其动态访问身份使用。静态节点存在不代表执行 guard 为真。

τ 是创建关系产生的身份，不是仅凭线程名认定。对循环/线程创建进行有限展开后，
证书必须写明展开语义及界；不能把展开到第 k 次的覆盖说成无限出现覆盖。
LLVM/后端可能将多个互斥源调用合并到一个静态位置，也可能将一处复制为多个位置。
因此，静态计数不等、来源不唯一，不应自动等价于错误转换。

## 2. 执行与观察

记 `Exec_{M_P}(P,I)` 为在合法初态集合 I 上、满足 P 的控制/数据语义和模型
一致性的有限执行图集合。执行图至少含：

```
G = (E, lab, po, rf, co, rmw, ctrl, thread/create/join, local valuations)
lab(e) = (kind, address, width, value, ordering tags, executed guard)
```

不同模型还可能需要依赖、栅栏、生命周期、混合语言标签等；此处不是用这些字段
替代完整 CAT 定义。`rmw` 使用真实端点关系；失败 CAS 有读，成功写的 guard 为假，
并不推出读的 locked 排序标签可以删掉。

一个读得到的值是该读的响应变量，不是按地址复用的缓存值。是否由同一写提供、
可否相等、能否满足原子性和一致性，要在完整执行的 rf/co/M 中决定。
公理内存模型不一般等同于“读当前内存值”的逐步 SC 执行。

观察函数 `obs` 明确选定：

- 安全错误标签、位置和到达性；
- 外部可见返回值、被后继使用的输出及指定最终状态；
- 与允许的上下文交互所需的共享历史。

纯临时 SSA、未逃逸局部存储、内部跳转可在满足条件时隐藏。共享写即使其值不在
本线程末态中保留，也可能被另一线程读到，不能据末态等价隐藏。这里不观察时间、
指令条数或 fence 数；若应用观察它们，合法变换集合也必须改变。

有限安全性质以有限坏前缀表述；不声称活性、调度公平性或终止等价。
对无限执行语义，仍要保证坏前缀不会被无限内部停顿隐藏。

## 3. 三种保证方向

令 `B_S(C)=Obs_{M_S}(C[S],I_S)`，`B_Q(C)=Obs_{M_Q}(C[Q],I_Q)`；
跨语言的 C 指具有同一外部接口和约定观察的上下文对，不能假定 C 的编译免费正确。
源/目标观察空间先由明确接口重命名统一；该重命名不能丢掉待验证的错误标签。

| 模式 | 所需性质，对全部允许 C | 可以转移的结论 |
|---|---|---|
| `SAFE_TRANSFER` | `B_S(C) ⊆ B_Q(C)` | Q 无错误 ⇒ S 无错误 |
| `COUNTEREXAMPLE_TRANSFER` | `B_Q(C) ⊆ B_S(C)` | Q 的错误有对应源错误；具体反例可再单独提升 |
| `EXACT` | 双向包含 | 两个方向均可用 |

若只要求特定断言，可用较弱的错误反射 `Bad(S) ⇒ Bad(Q)`，但证书必须声明
性质依赖，不能标作全部观察包含。反例转移也可只认证给定执行，不冒充全称保证。

**方向的直接论证。** 在第一行，若 S 有坏观察 b，包含给出 Q 也有 b；
与 Q 无坏观察矛盾。第二行的证明对称。这是集合包含的标准结果，不是新方法。
通常编译优化证明的是第二行方向；消除某些源行为，可能掩盖待验证的源错误。
因此，“这是一项合法优化”还不足以允许验证前转换接受它。

本批建议后续新范围默认追求 `EXACT`；若降为 `SAFE_TRANSFER`，须在每条规则、
证书和报告中保留模式。多出目标行为可能只是安全的过近似，不能一律叫错误转换；
但它不支持自动把目标反例判成真实源错误。

## 4. μ 的含义与不应许诺的事情

μ 是有限、可独立解释的**语义对应证据**，其执行实例化可为一对多、多对一或带
条件的关系。它包括状态/路径关系、来源与目标的责任划分、合法隐藏/变换理由和
覆盖义务。一般不要求 `μ:E_S↔E_Q` 是双射，也不要求每个源节点有存活目标节点。

区分两种任务：

- **历史恢复**：声称 LLVM 节点实际由哪个源节点生成。缺失可信记录时不总可辨识。
- **语义认证**：找到至少一个覆盖完整且保证目标性质的对应，不声称其为唯一历史。

例如两个相同、互不影响的源调用交换内部历史身份后，S/L/Q 的可见对象可以相同。
任何只观察这些对象的确定程序面对两段历史都会输出同一结果，不可能都恢复正确
唯一来源。这个不可辨识论证不阻止证明两种对应都语义充分。
因此，可靠性目标是“不因错误提示而错误接受”，不是“总能还原唯一来源”。

对所有 h 都满足 `ACCEPT ⇒ 声明的性质` 是提示无关可靠性。
有资源上限时不同 h 可以导致不同搜索顺序和超时；不必承诺接受结果始终相同。
若还声称给定有限候选域内搜索完备，就不能用 h 永久排除其他候选。

## 5. 允许的结构变化必须逐项给条件

| 变化 | 至少需要什么证据 | 不充分的替代条件 |
|---|---|---|
| 纯计算拆分/合并 | 类型/位宽/UB/poison 处理、活跃输出与分支等价、无隐含共享作用 | opcode 看起来相似 |
| RMW 拆成读、跳转、条件写 | 读响应、成功条件、写值、真实配对、A/其他排序标签及模型关系充分性 | 两个端点访问同地址 |
| 互斥路径的两个静态操作合为一个 | guards 互斥且覆盖、入口状态对应、每条执行中的效果和后继观察 | 源静态节点数必须等于目标数 |
| 删除不可达操作 | 源语义下入口不可达的证明，且不可达性不是由错误目标反推 | 找不到目标 |
| 删除局部死计算 | 无共享/异常/错误效果，且不影响活跃值与可达控制 | 返回值没人读 |
| 删除/合并共同执行的共享事件或 Fence | 针对 M、观察模式和全部允许环境的规则证明及实例前提 | 末态相同或访问次数相同 |
| 重排 | 地址别名、依赖、错误、po 与模型关系在声明方向下可输送 | 两段局部算术分别正确 |

所有成功执行的源相关操作都须有语义责任归属；所有目标共享动作和错误动作也须
被解释。对于被合法消除的动作，责任是“消除规则证书”，不是伪造空事件。
对新增目标动作也分别检查模式允许的引入规则，不能因为它没有源身份就忽略。

## 6. 完整性不是一个静态计数公式

需要分开验证：

1. **输入完整**：全部可执行源入口/调用/asm/线程与实际 Q 可达结构被解释。
   未引用的头文件 asm 可以保留在 census 中而无需有目标节点。
2. **入口完整**：关系包含全部合法入口状态，不能用一个偏窄的不变量删除坏输入。
3. **路径完整**：声明方向上的每条可行执行路径都有证书分解；不可行须证明。
4. **出现完整**：分解沿真实调用/循环/创建结构实例化，每次发生均有责任；静态
   “这个点检查过一次”不等于动态覆盖。
5. **上下文完整**：环境提供的读值、rf/co 与排序组合没有被局部选择悄悄缩窄。
6. **目标完整**：多出的访存、错误、返回或排序变化均在模式允许的证明之内。

按某个方向作精化时，不要求双向完全覆盖相同观察；仍须完整解释两侧语义，
并证明被比较一侧的所有执行存在另一侧见证，不能仅挑选成功匹配的执行。

## 7. 第一版可有效检查的子类

建议区分以下三个层次，不混写一个“完整算法”：

**D0：有限封闭任务。** 固定位宽和对象布局、有限线程/直接无递归调用、无环控制流、
有限内存对象，使用已解释的宿主表达式与既有 ISA 家族，全部错误/UB 条件有处理。
允许多个 asm、多静态调用上下文、任意来源提示；线程创建关系须有限且完整。
对每个完整程序可构造有限图公式，直接检查观察包含；这提供已知的可判定基线。
内存别名仍须计算，不能把不同指针参数当成不同地址。

**D1：可组合子类，研究目标。** 对 D0 形状的开放片段，允许任意满足 Γ 的并发
上下文。需要固定 M 下充分、可有效检查的边界历史摘要和组合定理。
有限片段并不自动推出任意上下文检查有有限完备界；这一点尚未建立。

**D2：循环/递归/动态创建。** 使用归纳关系、协议/摘要和进展证明，保证有限坏前缀
覆盖。若只提供展开界，则结论只到该界。一般无限内存/无界创建程序不期待完备
自动判定。固定有限状态的特殊情形原则上可判定，不应被笼统称作不可判定。
本批不提出已经支持 D2 的实现或完备算法。

## 8. Γ 中可以有什么，不能有什么

| 前提 | 当前归属及后续要求 |
|---|---|
| 原文件与捕获对象绑定、AST/LLVM/Q 未偷换 | 可用摘要/运行身份检查；捕获器真实观察执行对象仍属 TCB |
| 完整 GNU 解析、目标 ABI、ISA 与模型解释 | 显式可信语义/前端契约；新范围要么检查，要么精确限定 |
| 来源提示完整正确 | **新目标不允许作为接受前提**；可保留原检查器的历史结果 |
| 宿主表达式、所有调用/线程/错误被解释 | 新输入的检查义务；不支持就拒绝，不能假定其无关 |
| SMT/证明核正确，义务编码忠实 | 实现 TCB；可用证明证书缩小但本批未实现 |
| 所有实例已匹配、μ 已充分、全局历史一定可粘合 | **不得放入 Γ**；正是待建立的算法与定理内容 |
| Dat3M 编码/求解与导出 Q 的语义一致 | 外部可信契约或独立证明；`PASS` 不证明它 |
| 安全源语言域及无 UB 条件 | 明确输入域/证明义务；不能事后增加假设消除反例 |

最终目标形状是：在**不含所求结论**的 Γ 下，对所有允许上下文 C，
`CheckCertificate(S,L,L′,Q,μ,Γ,mode)=ACCEPT` 推出第 3 节相应包含。
输入真实性、工具对象真实性、证书充分性、检查器实现可靠性分别承担责任。
本批只定义这个命题；没有由定义推出它已被证明。
