## 结论先行

**不能把“自动寻找对应 + SMT + 完整覆盖”作为新的算法贡献。**
VALID 的 CIM 已搜索并发访存对应；黑盒等价检查和 PAA 已联合寻找路径对应、
状态关系并验证完整覆盖；Stellite 已在非同构内部事件之间证明上下文精化。
原来的比较只强调 Stellite/Kater/TInA，还不足以排除这些更直接的竞争机制。

**目前不具备方法型论文 Go 的依据。** 但也没有查实某个现成方法直接覆盖完整
GNU 接口、实际后端对象、多实例和本项目所需的安全证明方向。
审计给出的结论是：

| 主张或路线 | 本批判断 |
|---|---|
| 将标准匹配、产品程序、CEGIS、覆盖检查重新包装为新算法 | **No-Go** |
| 只在旧检查器外增加多调用与缺失元数据适配 | 可以有工程价值；**不足以建立独立方法贡献** |
| 固定有限整程序，直接编码源/目标执行图包含 | 可作为已知技术基线；不可把“有一个判定公式”当成新方法 |
| 面向固定弱内存模型、可组合的非双射开放历史证书，并联合搜索对应与覆盖 | **待验证的研究假设**；尚无闭合新定理、实现或独立创新性结论 |
| 现在进入全量竞赛、性能实验或论文撰写 | **不进入** |

## 三个影响后续设计的发现

1. **保证方向必须重写清楚。** 常规编译精化通常是目标行为包含于源行为。
   本项目要由验证器的安全结论推出原始程序安全，需要源行为包含于目标行为，
   或更弱但明确的错误反射条件。合法编译优化并不自动满足这个要求。
2. **历史来源不能由语义唯一恢复。** 两个语义不可区分的 asm 实例交换来源标签，
   可以得到相同的可见输入输出对象。无可信历史记录时，能够认证的是一个充分的
   语义对应；不能承诺还原唯一的“编译器实际选择了哪个来源”。
3. **完整覆盖是执行层面的证明。** 静态节点数相等、每个找到的区域正确、或每个
   源点有一个候选，都不足以保证所有分支、复制和动态出现得到认证。合法删除也
   不能由“找不到目标节点”推断。

以上是本批的定义审查和逻辑分析。没有把新构想称为已证明的方法。
