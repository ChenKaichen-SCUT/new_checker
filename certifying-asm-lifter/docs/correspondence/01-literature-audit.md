# 算法级文献与创新性审计

基线与状态见 [交付说明](00-delivery.md)。本审计区分论文定理、搜索算法、实现范围
与本项目推论。“没有 GNU/Dat3M 适配”不作为算法创新证据。
来源与查阅位置见 [sources.json](evidence/sources.json)；全文获取失败也记录在案。

## 1. 比较的任务与判据

比较输入是两个独立解释的实际程序及明确语义，而不是已正确匹配的局部事件表。
六项能力分别为：

- **A**：发现一对多、多对一、条件对应或不同长度路径对应。
- **B**：不依赖正确、唯一、完整的来源元数据建立语义证明。
- **C**：对所声明方向证明完整执行覆盖；不是只检查找到的区域。
- **D**：共享内存、RMW、Fence 和弱内存结构变化。
- **E**：同时检查数据/接口/活跃观察，而非只核对访存骨架。
- **F**：直接承担本项目的真实 S→L→L′→Q 认证保证。

“支持”均受各行所列语言、模型和保证方向限制。没有一列等同于“支持任意 GNU C”。

## 2. 最需要正面比较的定理与算法

### VALID：此前不能弱化为“只核对已经找到的匹配”

[原文 §3.1–3.2、§5](https://plv.mpi-sws.org/validc/paper.pdf)
给出 CIM：先标记不可删、可删、条件可删访问，再匹配同步访问，利用已匹配的
不可交换邻居限定搜索窗口，最后分析剩余目标引入和源删除。条件删除须追溯其
justifier，不能只看最终邻居。MD 另外核对有序对、路径条件和合并后的 guard 析取。

其保证针对合法访存变换序列；论文明确不检查完整程序功能等价。无环是可靠范围，
循环采用启发式截断；原实现不处理一般指针/数组和循环优化。CIM 的“compiler
independent”也不代表 CFG 名称完全任意：§3.1.3 使用基本块名和可达条件。
故可以说新目标超出其已述范围，不能说它不会自动匹配、遗漏检查或条件合并。

[官方项目](https://plv.mpi-sws.org/validc/)提供论文与工件。
本批未运行工件，也没有为其未说明的复杂输入填入“必然拒绝”。

### PAA / JTFG：覆盖检查和候选不可信已经是核心机制

[PAA §3.1，Lemma 3.1 / Corollary 3.2，§4](https://cs.stanford.edu/people/sharmar/pubs/veceq.pdf)
要求边关系保持、未表示路径不可行、无单边空步环和出口观察相等。测试只产生
候选；充分性来自归纳证明。其语义将错误/不终止与正常返回区分的方式，不能直接
搬作本项目的断言错误观察。§5.6 的不变量/路径表达限制也不能被说成一般不可能性。

[JTFG Algorithm 1、§4.3](https://www.cse.iitd.ac.in/~sbansal/pubs/aplas17.pdf)
联合尝试复合边、猜测并剔除不成立的关系谓词，失败回溯；不需要知道优化序列。
若本项目只把 JTFG 的状态增加来源 ID、把边增加 SMT 字段，算法独立性并未成立。

[Direct PAA §2，Algorithms 1–2](https://arxiv.org/pdf/2109.01864)
进一步提醒：不使用具体测试构造 PAA 也有先例。其对齐谓词输入、搜索终止与证明
范围须与“全自动合成”分别比较。此处按预印本审计，不把摘要的批评误读为 PAA
2019 不检查覆盖或用测试替代证明。

### Stellite：真正需要复用或超越的是上下文历史，不是同构

[原文 §§3–6，Theorems 1–4](https://www.cs.kent.ac.uk/people/staff/mjb211/docs/esop18.pdf)
定义相同外部环境下的历史包含，隐藏块内部动作，保留上下文可见保证关系。
完整版本有 adequacy 和 full abstraction；带 deny 的有限版本有 adequacy，
不再完全抽象。有限化界来自定理，故原型不能简单归为“只枚举十个事件的 BMC”。

模型为特定 RA 风格语义，理论语言包括 LL/SC、分支；原型仅实现原子读写和 fence。
不能把原型缺少分支当成理论障碍。也不能把其 hb 历史原封不动套给固定 Dat3M
TSO，尤其不能省略原子配对和失败 locked 读的排序作用。

它验证给定块变换的常规精化方向。其历史搜索已处理内部非双射；新项目必须说明
为何实际完整程序的候选发现与覆盖不能由已知 PAA/VALID 加这种判定直接完成。

### Kater / KATI：区分“证明映射条件够用”与“实际产物满足条件”

[Kater §§3.1–3.2、3.7](https://plv.mpi-sws.org/kater/paper.pdf)
用自动机语言包含与假设消去证明关系结论。RC11→TSO 示例把映射插入 fence
表达成关系包含假设，再证明模型公理；RMW 在实现中已用两个事件表示。
其部分饱和启发式不保证完备，不能称为任意映射的完整决策器。

[KATI §§3–6](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.CONCUR.2024.33)
允许表达式与原始未解释关系求交；包含通过扩展字母表处理，交运算嵌套深度有界时为
PSPACE-complete。寄存器自动机用于一致性检查，不是用一般寄存器自动机包含
来解决该问题。Theorems 16/20 给出相应语言包含的判定等价；
Theorem 18 对模型非自反性蕴含给出充分条件，不能由前者声称任意模型包含都有
完备判定。它们都不自动证明某次 GNU 操作数绑定和实际 Q 的映射假设。
但我们若只是自动生成这些假设的实例检查，仍需另外建立方法贡献。

### SEQ / CompCertTSO：不能笼统排除成熟的模拟路线

[SEQ §3、Theorem 6.2、Appendix A](https://www.cs.tau.ac.il/~orilahav/papers/pldi22_full.pdf)
将带环境 oracle 的精化提升到 PSna 上下文精化；Theorem 6.2 另有源确定性条件，
并要求相同内存布局、区分原子与非原子位置。普通顺序终态相等远远不够。
[Coq 工件](https://github.com/snu-sf/promising-seq-coq)包含更丰富同步原语和优化证明；
没有重新构建它就不声称本批复现了机械证明。

[CompCertTSO §§4、6](https://fzn.fr/projects/wmc/readings/compcerttso-long.pdf)
已用模拟验证 TSO 编译与 fence 删除，某些删除还需要处理不可见非确定性的
weak-tau simulation。将两个 fence 合成一个可以区别旧 Checker，但不能区别这条
文献线。模型、观察和方向必须逐个实例化，而非把 pass 正确性当作黑盒搜索算法。

## 4. 直接复用与简单组合审查

### 方案 A：PAA/JTFG + 当前字段等价

能扩大多调用、缺失来源提示、纯控制流变化的支持。只要全部共享事件在每条执行
中仍有完整保标号对应，旧 CAT 输送结果可复用。
这条路线技术上有价值，但核心仍是已知产品关系搜索加已有同构检查。
**以此单独主张新方法，No-Go。**

### 方案 B：VALID + 数据等价检查

可以将访存匹配与算术/活跃值证明分开。需要解决实际接口、符号地址、
不同失败原子语义及保证方向；不能直接假定 VALID 的删除规则适用于本项目。
若这些只是有限规则的实例化和适配，仍应定位系统贡献。

### 方案 C：PAA + Stellite / SEQ

这是对候选路线最强的“已知组合”挑战。PAA 提供路径与实例覆盖，历史/模拟框架
提供并发替换充分条件。尚需核实的技术差距是：自动切块时的边界状态与跨边界
关系如何生成、给定模型下的历史摘要是否充分、对应搜索是否依赖完整环境历史、
多块摘要能否同时实现一个共同环境见证。不能仅把这些写成未解释的 oracle。

当前**未证明这项组合做不到**。没有性能或表达力分离结果，不能称候选“现有
方法无法直接完成的新问题”。本批将其作为第二批必须先解决的对照，而非竞争
方法的缺点。

### 方案 D：有限整程序精化公式

对有限位宽、有限对象、无环控制流、有限线程的两个完整程序，逐侧构造完整执行
图公式，直接检查所需方向的观察包含。不存在逐节点正确映射的输入要求。
这在原则上已解决这个有限子类的语义判定；μ 可以是加速搜索和解释结果的证书。
因此本项目不能宣称“只要无元数据的有限例子通过，就解决了此前不可解的问题”。
真正需要说明的是更强的可组合保证或可核验且可管理的搜索/检查成本。

## 5. 有条件保留的研究空间与停止条件

有意义的候选是：**在明确模型下，以可检查的开放历史摘要为边条件，联合搜索
语义对应与完整执行覆盖，并使摘要在来源复制及非双射事件变化下仍可组合。**
它需超出“标准搜索器 + 大量解析规则”，至少给出以下之一：

1. 现有历史摘要无法直接支持的实际边界条件，以及闭合的新充分性结果；
2. 保持同等保证、避免全程序或全环境展开的可证明搜索/检查分解；
3. 对强竞争基线的明确表达或成本差别，并有真实对象支持，而不是只比旧 Checker。

若候选实例均由方案 A–C 直接表达，新增部分仅是读取对象，应停止独立理论创新
主张。若 Hetrify 全文或其他工作已有相同算法和保证，应给整条候选路线 No-Go。
目前没有依据声称已经满足以上条件；也没有依据因全文不可得而断言完整目标已被
某工具直接解决。论文判断维持 **NOT_ESTABLISHED**。
