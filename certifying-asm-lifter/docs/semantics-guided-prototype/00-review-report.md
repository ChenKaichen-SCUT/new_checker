## 2. 已实现范围和有意收缩

`finite-tso-1` 使用有限结构化 sequence/if，无循环、无调用、无提前错误退出。
固定线程全部正常完成；对象已知、有效、对齐、完整、同名精确别名、异名不相交。
全 bv32 共享读写及 FAA 模加，FAA 返回旧值；Fence和A/pair保留；纯表达式为总函数。
输入、全部声明的对象终值和活跃返回结果组成观察。所有结构路径都进行定义检查。

B 在整个已实现 DSL 上生成精确符号图候选；读值没有小范围限制，co/rf/fr 在同一
全局图中处理。实际独立完整性门禁收缩为 **A₀：布尔输入，Store/FAA操作数只依赖
输入，不依赖局部变量**。分支和观察仍可以依赖读取结果。A₀用显式co/rf枚举及FAA
直接前驱引理恢复全部32位值，重新核对B的整个图集合，不只是每个终态的一个样本。

这个域覆盖本次100候选和所有用于等价/差异声明的正负实例；全域bv32输入、依赖
先前读值的写回等仍可进入B，但如果A₀不适用，不授权独立完整集合/SAFE。高位输入
`n=2^31` 的单元案例可由B求得正确结果，独立门禁仍如实拒绝，未将输入宽度伪装成bool。
全bv32自由输入在图数预算后返回UNKNOWN。两种能力在接口与报告中明确分开。

这不是第二种独立内存模型：A和B都实现同一固定CAT，结构差异是显式关系枚举与
符号约束求解。具体核验器不读候选事件清单来定义正确事件，也不读取任何Dat3M对象。
共享的Python运行时、DSL校验和具体图核验仍是实现可信表面；没有证明FIFO缓冲机
与CAT的一般等价，也没有声称Python代码经形式化验证。

## 3. 确定性与对抗性验收

最终 [acceptance-05](../../experiments/semantics-guided-prototype/acceptance-05) 包含19次
独立Oracle调用：17个完整集合、1个刻意图数截断、1个空输入域。共有62个候选合法
图记录，其中截断记录1图；全部见证重新核验，24条完成路径的最终排除查询重放。
28项验收条件全部满足。30项单元测试在普通Python及`python -O`下均通过；关键门禁
使用显式异常检查，不能被优化模式删除。

| 边界 | 独立结果 |
|---|---|
| Store Buffering | 无屏障4种终态，含双零；双Fence3种，排除双零；只剩一道Fence又允许双零 |
| 两线程FAA | 只有最终2、旧值(0,1)/(1,0)两种观察；同读0丢失更新见证拒绝 |
| 三线程FAA | 最终3，旧值的6种排列；没有以两线程结果替代三线程检查 |
| bv32回绕 | 初值`2^32−1`，两FAA后最终1；读取序列按模32恢复 |
| 互斥FAA复制/合并 | 两静态FAA与一个ite操作数FAA的完整输入域/全部观察相同；活跃返回及后续加法保留 |
| 纯表达式/重命名 | `e+0`及无捕获重命名规则通过，完整集合也相同 |
| 错误ITE、删除guard | 有输入保留的一侧观察，另一侧完整排除；不是一对执行不一致 |
| 合并两个实际FAA | 源观察`final=2, r=0, s=1, observer=1`目标不能匹配；中间共享写不能删 |
| 返回新值替代旧值 | 共享终值不足以遮蔽返回和后续局部观察差异 |
| 开放读7 | 两FAA完整图内无扩展，判UNREACHABLE；截断图集下同一问题只能UNKNOWN |
| 完整性篡改 | 删掉图且同步删观察、伪COMPLETE，独立A图集比对拒绝 |
| 证书篡改 | 错误对象rf、init排末、缺pair写、额外非活跃读、标签/关系/路径/观察改动拒绝 |
| 查询篡改 | 保存的基础SMT额外添false，原DSL重编码绑定拒绝；不相信UNSAT文本 |

数学错误变换及证书篡改只用于本原型核验；没有向实际验证器注入故障。
SAFE预期由完整观察表的成员谓词产生，UNSAFE预期由排除一个已核验观察的谓词
产生。每个完整程序均保存两种明确预期；这证明可产生真值，不证明性质揭错能力。

## 4. 固定100候选预实验

10种线程结构的10×10笛卡尔积是完整实验母集；未宣称穷尽所有界内DSL。
包含普通读/写、FAA、Store→Load、Fence、读后写、FAA后读、跨对象FAA、输入分支
与读取结果分支。每个任务固定两个线程、两个对象，布尔输入两值全部保留。
每线程最多两个实际共享操作，每任务最多两个分支。3线程/单对象/回绕放在边界集，
没有充作额外独立项目。全部100个输入在首次Oracle运行前写入并提交。

最终：**100/100良构、100/100 B COMPLETE、100/100 A AGREEMENT**；没有UNKNOWN、
超时、崩溃或未解释的语义矛盾。共458个合法完整图、446个带输入的终态观察；
100个程序各产生一对SAFE/UNSAFE预期。B执行602次check：458 SAT、144 UNSAT。
A检查750个全局候选，逐个保存合法核心或拒绝计数；完整图与B双向相等。

这些数包含同模板/不同输入的实例，不是458个独立程序或缺陷。部分相同终态有
多个关系图，全部保留用于特征。独立重放重新恢复完整图集、144条路径公式及其
全部阻断、全部特征证书与45条选择记录，结果VERIFIED。

## 5. 同池、同数量预算、五种子的选择对照

semantic优化1–2端点关系模式；syntax优化操作/邻接/地址类别；random均匀打散
后选固定前缀。种子11/29/47/71/101，预算5/10/20，合计45条选择记录。
全池模式并集：目标53、留出三端点265、留出行为探针43、语法20。
100个候选中，完整两端点特征集合有52种，三端点集合54种，语法集合40种；
候选存在明确冗余，这有利于覆盖选择，不应被误读为100个互不相似的语义场景。
每种策略每次选出精确预算数，全部被选程序有效率100%；UNKNOWN未从分母剔除。

表内为五种子的中位数；括号为最小–最大。三端点和行为探针未进入贪心评分。

| 5 | random | 40 (39–46) | 97 (88–158) | 17 (14–21) |

预算5，两个留出指标的逐种子结果均优于两种基线（各5/5），有固定域内可复核的
选择收益，不只提高自身目标评分。预算10，对syntax的三端点仅3胜2负；预算20仅
2胜3负。预算20的行为探针对random是1胜1平3负，对syntax也是1胜1平3负。
因此**不宣称所有预算持续获益**。目标模式在5项时已饱和，之后主要是种子填充。

留出三端点仍与两端点模式相关；行为探针也是本研究预登记的粗粒度指标，不是
缺陷、目标工具代码路径或独立软件覆盖。五种子小池不支持统计泛化或显著性结论。
标准最大覆盖贪心及其近似证明不是新算法贡献；没有跨层反馈或实际缺陷发现数据。

## 6. 成本，不能隐藏全池预处理

本地Windows 11 build26200，i7-13700F（16核/24逻辑CPU），物理内存
34,163,974,144 bytes；Python3.13.12，z3-solver5.0.0.0。单进程顺序执行小池，
没有专用CPU隔离或冷/暖缓存性能实验。这些是最小可行性测量，不是系统论文基准。
[环境原件](../../experiments/semantics-guided-prototype/environment-host.json)。

最终pilot-03一次全池+45次选择含文件I/O：墙钟 **7.403s**、CPU **7.141s**，
进程峰值工作集 **66,596,864 bytes（约63.5MiB）**。该峰值是整个进程的累积峰值，
不是每个候选隔离内存。逐任务完整证据总 **8,629,448 bytes**，不含总表、日志、早期尝试。

分量不能机械相加成CPU隔离计时；task资源账本另记录性质生成、完整性重核验和

random/syntax原本不需要全池语义预处理。本实验为公平评价预先算全池，但不能
把该费用免费授予semantic后声称更快。预算5被选任务B墙钟实测求和中位分别
约0.216/0.265/0.265s，证据量约376/495/527KB；这只是相同任务单次测量的求和，
不是三个策略各自重新运行的端到端计时。semantic还需要其全池Oracle/特征成本。
本轮提供等数量预算收益，不提供等时间优势、加速比或缺陷发现成本结论。

## 7. 开发失败与修复没有删除

* `unit-01`：测试夹具索引错误；Windows沙箱临时目录ACL导致4项无法创建证据。
  改为工作区独立证据目录并永久保留，而非跳过测试。普通/优化模式30项最终通过。
* 初版公开性质入口仅核验所列见证。审阅发现缺少独立完整性门禁，已改为每次从
  原DSL运行A、双向比对图/观察集合；增加“同时删图和观察”拒绝检查。
* `audit-acceptance-01…05`保留全部失败：`to_smt2`打印会改写断言或在false下简化，
  simplify排序不稳定，Python/Z3字面量比较方向不同，以及未用输入未被声明。
  最终用保留完整断言的sexpr、同类型阻断字面量及输入恒等声明，逐项重建绑定。
  没有丢掉字段、忽略未知表达式或接受任意false来使排除通过。
* FAA复制规则原先直接返回逆合并的证书方向，关系等价成立但源/目标标签不直观。
  最终证书明确正向源/目标并内嵌逆规则证明；acceptance-05为最终版本。
* `pilot-01/02`均保留；pilot-03补足全任务成本账本，作为最终版本，并非挑最快结果。
  三次固定池的全部图和观察集合逐任务完全一致，记录在
  [revision-consistency.json](../../experiments/semantics-guided-prototype/summary-01/revision-consistency.json)。

以上均是新原型开发/证据接口问题，未计为任何实际验证器缺陷。最终验收与重放
未留下未解释的语义矛盾。工作站Python启动器每次提示`Failed to find real location`
原样保留；实际解释器/包版本及成功退出记录明确，没有因此更换语义工具版本。

## 8. 分层判断及下一步边界

| 判断层 | 结论 | 限制 |
|---|---|---|
| 独立有限Oracle与真值 | 受限GO | A₀完整图重算；非已验证机器代码；无C桥 |
| 非平凡变换及完整观察 | 受限GO | 单FAA臂/共同出口菱形及两条纯规则 |
| 固定池选择收益 | 小预算预实验GO | 预算5留出指标5/5；大预算不稳定；成本显式 |
| 一般语义反馈测试算法 | 未建立 | 只实现S覆盖选择，没有R反向合成或工具反馈 |
| 独立算法创新/ISSTA充分基础 | NO_GO / NOT_ESTABLISHED | 标准图枚举、规则变换和贪心组合；无真实目标增量证据 |
| 进入真实Clang/Dat3M测试 | 本轮不进入 | 等待本阶段独立审阅和另行授权 |

本阶段GO只表示用户指定的有限最小原型具有可执行、独立可复核的基础；它不保证
同样优势出现在其他语言池，更不证明可以投稿。若进一步研究，最值得审查的是
小预算收益是否超出相关模式指标、A₀之外的完整性证书是否可负担，以及如何在不
增加隐藏语义假设的情况下建立DSL到真实工具的桥。本轮不实现这些扩展。
