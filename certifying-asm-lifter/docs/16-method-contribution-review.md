# 独立方法贡献复核：CK 接通之后仍不能自动成立

日期：2026-10-20。判断：**本轮建立了有用的真实转换认证链，但目前证据不足以
把它确认为 FSE/CAV/ISSTA 级别的独立方法贡献。** 不能把这个判断继续延后到
大规模实验之后，也不能用 CK 首次通过替代新颖性论证。

## 1. 先回答核心问题

“给定真实 GNU 来源、实际 LLVM 和同次最终验证器对象，验证它们确实对应，
且全部激活和可见行为都被覆盖”是一个清楚、值得解决的工具链契约问题。
查阅工作没有提供本项目所需的现成 GNU→Dat3M 对象证据链。
但**缺少现成适配器不等于存在新的核心算法问题**。

本轮实现的来源连接是已有 Clang `!srcloc` 标识的唯一连接；类型恢复是受限
AST 解释；实例覆盖是有限集合双射；语义检查仍是开放读取、符号解释、SMT
等价与既有关系组合。它们比手填映射可靠，却尚未证明具有超出已知机制组合的
方法创新。可以主张“实现并审计了这些契约”，不能主张“首次提出组合验证、
GNU 接口检查、调试对应或并发汇编语义”。

## 3. 哪个契约确实不能由已有局部检查直接推出？

令 A 的预期出现集合为 D，实际核心区域集合为 R。局部证明只能给

`∀r∈R. Equivalent(reference(r), r)`。

这不能推出存在覆盖 D 的对应关系。取 D={a₁,a₂}、R={r₁}，且 r₁ 确实等价；
上述全称式成立，但 a₂ 被漏掉。这个反例是集合逻辑构造，不依赖运行测试。
同样，若 reference(r₁) 是错误的源节点，只证明它与 r₁ 等价无法识别源混用。
模型包含证明也无法单独发现工具在特定输入上违反了其编译映射前提。

因此实际链需要额外验证：

`存在且唯一的来源连接 ∧ 类型化绑定 ∧ 出现覆盖 ∧ 局部语义等价 ∧ 活跃观察对应`。

这个合取澄清了研究问题，并解释当前检查器为何能拒绝“每个找到的区域都正确、
但少了一个区域”。**这不是不可归约性或新颖性定理**：已有关系连接、翻译
验证和程序逻辑完全可以表达这些义务；必须避免声称现有方法在原理上做不到。

## 4. 当前算法已经解决什么，尚未解决什么

已实现：同一 TU 的 188 个 asm 中自动选择真实 surviving 来源；原始宏 token、
typed AST、内联 CallExpr、实际 LLVM 操作数相互核对；单一静态调用上下文的
任意有限直线 worker 创建清单；最终区域活跃值和真实线程双射。
在本工件上 n=2。选中逻辑没有 CK 函数名常量或人工返回寄存器表。

当前算法仍要求：

- 只有一个 surviving 静态 asm 和一个直接内联调用上下文；
- 源包装函数只有 asm 与返回输出，参数为常量/静态对象地址；
- 单层内联链可恢复，debug 来源必须完整且唯一；
- 每个 worker 的源行能提出唯一候选区域；区域内只接受当前受支持无环结构；
- 核心共享端点在参考展开后按位置匹配，不能任意合并、重排、删去或跨区域移动。

宏展开和两个线程激活已经处理，但“多 surviving 调用、深层内联、来源合并/
丢失、跨块优化、一般事件结构变化下自动恢复对应”的困难尚未解决。不能把
这些限制写成已实现的一般算法，也不能把已支持的 RMW→两个端点称为一般
结构变化处理。

## 5. 方法论文的具体判定

当前比较支持的结论是：**有明确的端到端契约与工程系统价值；独立方法型论文
的核心贡献仍未建立。** 不应承诺 FSE/CAV/ISSTA 录用潜力已被本轮确认。

更强的候选问题可以精确定义为：给定不可信、允许复制/部分丢失的来源提示，
同时合成并检查 `源出现→内联实例→最终区域族` 的对应，约束事件分裂/条件存在、
跨区域活跃值与出现覆盖；来源提示只缩小候选空间，最终接受不依赖其真实性。
这需要新的对应搜索/证书结构，以及候选无关的可靠性证明；还必须给出已知
方法简单组合不能直接处理的接受实例和拒绝反例。

这只是**后续研究假设**，不是本轮完成的算法。目前仍信任 Clang 来源元数据，
故尚未达到该更强目标。若后续只能继续增加 AST 语法规则与工具适配，应优先
诚实定位为系统/工具贡献，而不是通过改名包装成新方法。本轮到此停止，
不以扩大指令或批量竞赛实验回避这个判断。
