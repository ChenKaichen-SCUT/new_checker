# 阶段 2：形式化问题定义

## 1. 对象和参数

Γ=(w,a,ISA,ABI,I,P,M,H,B,ObsPolicy)。
w∈{32,64} 为数据宽度，a=64 为地址宽度；V=BV_w，L⊆BV_a。
所有内存访问自然对齐、同宽度、完整对象内且对象存活；不假定两个符号地址不同。
ISA 是本文有限指令表的抽象架构语义，不包含缓存时序、异常和推测执行。
H 是宿主语言语义契约；B 是后端契约；二者可标为未建立，此时结论只属于块级。
P 是受信任接口/调用方给出的前置条件，不能从不可信证书读取后直接相信。

A=(asmText,I)，I=(inputs,outputs,clobbers,bindings,allocationPolicy)。
GNU 源级解释是所有合法寄存器分配的联合；只证明一个具体 bindings 时必须相应缩小结论。
输入求值、输出回写中的宿主共享访问属于上下文，不能偷偷移入局部 τ 步。
本实现只提取表达式无副作用的标量变量与 `*identifier` 内存操作数。
指针有效性和实际 C 类型需要宿主前端证明；文本解析器不证明它们。

T 是有类型的位向量 Event IR 程序。共享操作不能降成普通 C 有符号算术。
局部状态 σ 是有限寄存器/临时变量到位向量的映射；不含一个被冻结的共享内存数组。

## 2. 开放转换器

状态为 (pc,σ)。纯局部指令作 τ 转移，必须有限终止到下一个事件或出口。
一个共享切点由请求和恢复函数组成：

* Read：请求 (R,m,address,w)，任意环境响应 u∈V；
  完整事件 R^m(address,u)，恢复函数更新目标寄存器为 u。
* Write：(W,m,address,w,value)，无响应。
* RMW：(RMW,tso,address,w,f)，任意响应 u；
  发出 RMW^tso(address,u,f(σ,u))，其中 f 可返回 ⊥。
  xchg：f=原交换寄存器值；xadd：f=u+operand mod 2^w；
  cmpxchg：f=desired 当 u=expected，否则 ⊥。
* Fence：F^sc 或 F^sf；没有数据响应。
* CompilerBarrier：编译元数据边界，不是架构图中的事件。

每一个读取/RMW 切点使用新的 u_i，即使地址相同。**任意响应不是声称任意读都硬件可行**：
它生成候选路径，全局 rf/mo 和 M 负责筛选。不能按“当前内存值”生成唯一响应。
局部循环/非终止被排除；否则同一事件迹但不同 τ 发散会破坏下述边界匹配。

观察边界还包括 `Exit(outputs)` 和 `Fault(kind)`；两侧必须相同。
不观察未声明 clobber 后的机器寄存器。若后续 asm 使用 flags，则 flags 也是状态，
不能用 cc clobber 为理由忽略 asm 内部对 flags 的读取。

第一版固定事件骨架，每个事件位置始终出现。CAS 的可选写值是标签的一部分，
不通过删掉失败路径的 RMW 实现。允许局部 ite 表达式，不允许条件性省略事件。
这是刻意限制；通用 DAG 版本需要额外覆盖义务，未实现时拒绝。

## 3. 图、上下文和观察

G=(E,tid,λ,po,rf,mo)，采用 01 中单节点 RMW 定义，不另加 rmw。
额外保留事件宽度、退出值和有限安全监视器状态。所有初始写固定。
对候选图取 M 一致性判定；SC 实例要求普通存储操作存在保持线程顺序的总执行序，
原子 RMW 占据一个不可分割位置。RC11Ex86 实例直接使用 01 的 B.8。

CΓ 是任意有限线程数、任意顺序/并行组合的宿主程序，可以含循环，但每个被观察执行有限；
被替换块不能跳入/跳出上下文。上下文只依赖可见输出/共享值，不检查汇编代码字节、
耗时或隐藏临时寄存器。上下文保留其 C 模式，不将 C relaxed/sc 统统改成 tso。
同一线程的前缀和后缀都包含在上下文中；不能只量化“并行的其他线程”。

Obs_M(P) 包含每个完整有限一致执行的公开寄存器/内存结果和监视器错误记录；
也包含有限、po/rf 闭合的一致执行的安全错误。没有把任意 po 前缀的 rf 擅自截断：
读可能依赖图中别处的写。对原论文 na 数据竞争，另外记录 UB 标志；
若采用 catch-fire，则出现 UB 后的观察集合取全集。两侧必须保留 UB 可达性。
对 data-race 属性，观察的是冲突访问及 hb，不先假定 DRF。
对越界/溢出等不在参考语义中的性质只能拒绝整程序保证，不靠本文定理补足。

“有限安全错误”的定义不覆盖公平性、无穷执行、终止与活性。宿主存在发散不会使
有限安全性定理自动变成终止等价定理。

## 4. 检查器目标

Check(A,T,Γ,cert) 接受时，先给出块级结论：

    ∀σ满足P，∀有限开放响应序列u：
    两侧逐事件完整标签相同，边界输出/错误相同。

若接口提升、H、B 契约均建立，则组合定理给：

    ∀C∈CΓ，Obs_M(C[A]) = Obs_M(C[T])。

输出 EXACT 表示该声明范围下的精确块转换；不是“程序没有 bug”。
超时、SMT unknown、类型不匹配、任何不支持输入、额外/缺失事件均 REJECT。
证书不能改变 M、P、位宽、错误策略或源 hash。

## 5. TRUE / FALSE 的方向

设 S 为源观察集合，T 为后端模型的观察集合，Bad 为一致编码的安全错误。

* S⊆T 且 T∩Bad=∅ ⇒ S∩Bad=∅，故过近似足够支持 TRUE。
* T⊆S 且存在 t∈T∩Bad ⇒ 存在源错误，故欠近似足够支持 FALSE。
* 只有 S⊆T 时，目标反例可能虚假；须独立重放源事件、rf/mo、属性和前提才可 FALSE。
* T⊆S 不能支持 TRUE；“强化 fence 后证明安全”通常正落在这个错误方向。
* 双向等价且可靠后端才允许双向转移。
* 有界展开尚不完整：无错只能 UNKNOWN；发现的有限源可行反例仍可 FALSE。

这些结论均由集合包含和反证法直接得到，不依赖实验统计。
