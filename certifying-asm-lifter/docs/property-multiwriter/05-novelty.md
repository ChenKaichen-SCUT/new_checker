# 技术比较与 Go/No-Go

2026-10-21 重新查阅下列第一手材料中的模型、算法与证明条件，不根据工具名称
或是否直接支持 GNU asm 判断创新。未找到逐字等同于本轮 M3 的现成定理，
不等于证明了新颖性；以下明确区分直接适用、模型桥接和原理复用。

反过来，也没有因 Clang/Dat3M/源语言接口不同，就判定存在独立算法缺口。

## 2. 最强已有原理组合的具体构造

可以把当前规则解释成下面一条完整的、有限对象层面的组合，而非仅列技术名：

1. 由现有类型化实际对象匹配和完整访问/激活检查得到固定关系骨架及两侧表达式。
2. 用保守依赖/干扰闭包取得观察的 provider 集，投影隐藏其余候选对象的值；
   **仍保留这些对象的全部事件、排序和来源身份**。
3. 对任意源合法图给定的骨架，用本轮从已知 TSO 公理导出的因果排序，拓扑
   求值总函数，构造隐藏目标值的存在见证。直接前驱引理解释 co 递推；H 引理
   使对象依赖 SCC 不再要求额外不动点求解。
4. 对保留部分验证普遍等式，利用标准表达式无干扰归纳保持投影，得到标准
   错误观察包含，再使用原查询/编码契约转移安全。

第 3 步是相对本项目旧证明的实质补充，不能省成一句“切片正确”。但它是
既有有序原子语义与有限 DAG 求值/模拟原则的一个明确充分实例；没有引入新的
反例细化、映射搜索、循环不动点求解或上下文历史摘要算法。整个选择器仍是
受限资格检查加闭包，独立核验是标准 proof-carrying 分区与边界检查。

若把有限 TSO 图语义忠实编码为一个关系系统，通用关系验证方法也能表达
`∀源合法赋值 ∃目标赋值` 的目标。M3 给了无需为修复区逐值搜索的构造见证，
但没有证明通用算法在这个子类上必然付出更高复杂度；原剩余义务仍需 SMT。
本轮没有成本比较，也不能把“理论上省一个量词求解任务”当成实测优势。

## 3. 三类贡献分别判定

| 贡献类型 | 本轮证据 | 判定 |
|---|---|---|
| 比单 owner 更一般的充分条件 | M0–M3 的完整解析证明；C6 允许多动态写者及循环对象依赖；无新 Γ | **成立**，是本项目新的受限理论结果 |
| 具有实质差异的独立新算法 | 有具体选择器/证书规则，但核心仍为闭包、模型导出的因果性、总函数求值和模拟；没有既有合理组合不能处理的区分障碍或成本分离 | **未建立 / No-Go** |
| 已有原理的工具链实例化 | 设计可接现有 GNU/LLVM/Q 检查；生产代码和接受范围保持冻结，未签发多写者新证书 | **本轮只有设计，未实现该扩展** |
| ISSTA Research Paper 方法基础 | 有更精确的保证与反例，但不足以独立支持方法新颖性、现实收益和普适性论证 | **当前 No-Go** |

不能因为 No-Go 否认 M3 的正确性进展；也不能因为 M3 推广成功就宣称方法论文
已具备创新性。未检索到相同名称/定理的证据弱于“已有方法无法直接覆盖”。

## 4. 剩余问题不是本轮已获授权的新路线

如果未来继续寻求方法贡献，应先确定真实输入中存在什么必须处理的关系
不落在这种现成因果 DAG 中，例如必须改变可观察值关系、条件端点、部分开放
环境或需要循环不变式的情况，再判断是否有现成关系/上下文方法可解。
本轮不去增加 ISA、放宽环境、恢复通用对应合成，也不以实验数量补足新颖性。
依据目前证据，只支持交付并审阅这条更强充分规则，不支持直接进入完整论文实验。
