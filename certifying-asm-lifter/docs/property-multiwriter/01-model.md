# 固定 TSO 模型、量词与范围

冻结基线 `5e744abf48669d3ee6014e127c344ac5a00e1d43`，2026-10-21。
本轮是理论与算法设计；不修改 `certification/`、Lifter、后端或旧证书。

## 1. 实际模型而非笼统的 TSO

沿用 Dat3M `b81ec6c55503e824bb0ddc4ebac6c6f0a63d56d8`。核对的是既有同次
运行捕获的 `experiments/property/final-02/owned/backend/model/cat/` 文件，
与 `backend/dat3m/pins.json` 一致：

| 文件 | SHA-256 |
|---|---|
| tso.cat | `8561d85057c449c0828b888c61e3cfeda8b73750474353eee1dd3f0383b192ac` |
| x86fences.cat | `b7d347726619c89e336bb19fd0ed5284d0b2fb893f06c957644ab769de691766` |
| stdlib.cat | `af333bb3cba3d511510b3be3a1d9d372e6a635d76f7cc214dd9eabf8121d1857` |

这些是项目中已有的原始模型字节；本轮没有换用更强的 SC 模型。
以下记 U 为 uniproc 关系、H 为 ghb-tso，`int/ext` 表示同/不同动态线程：

```text
fr_full = rf^-1 ; co ∪ [R \ range(rf)] ; loc ; [W]
U = po-loc ∪ co ∪ fr_full ∪ rf
J = po ∩ (W×R) ∩ ((M×A) ∪ (A×M))
K = (po ∩ ((R×M) ∪ (W×W))) ∪ mfence
H = K ∪ J ∪ co ∪ fr_full ∪ rfe

acyclic U
empty (rmw ∩ (fre ; coe))
acyclic H
empty ([R \ range(rf)] ; loc ; [IW])   // force-init-read
```

`x86fences.cat` 的原定义是 `mfence = po ; [mfence] ; po`；不把所有 fence
混为一种，也不删除其边。stdlib 中 `rmw = amo ∪ lxsx`，不是仅由 A 标签定义。
对这里所有有效且有初始化写的对象，force-init-read 排除无 rf 的读，配合
执行图基本约束的唯一供值写，可使用 `fr = rf^-1 ; co`。这个化简依赖域检查；
未初始化、无供值、混宽、非法指针不能默默归入本模型。

H 的无环性取实际模型中的关系，不要求 H 是全序。后文使用 H 的某个拓扑序
**求值**，不是用一条 SC 调度替换目标模型，也不固定所有执行共用一个 co。

## 2. 对象与判断方向

P 是独立定义 GNU asm 扩展语义的真实源程序；L 是实际 Clang LLVM，L' 是
实际替换文本；Q 是固定同次运行的完整 Dat3M Program，含其所有表达式和属性。
phi 是已绑定的安全观察，初始设计继续取全部源用户断言。错误仅要求存在合法
有限错误前缀；不要求错误之后终止，不以未来 assume 擦除此前错误。

有限执行图写作

```text
g = (E, loc, width, kind, A, po, rf, co, rmw, fences, activation, val, obs).
```

每线程 po 在该路径上严格全序；co 在每个对象执行的写上严格全序且初始化最小；
rf 对每读恰有一个同对象同宽、数值一致的写。rmw 的读/写是不同端点。
一个真实 FAA 展开为同线程 `r po w`、配对 `(r,w)`、A 标签及正确类型；两端点
之间没有另一个同对象写。这是指令/区域形状条件，不能从 CAT 的 rmw 名称推断。

沿用原来**逐位置、逐激活**检查的端点对应 h。这里不研究一般事件增删、融合
或映射合成。纯局部 SSA 节点可不同，但全部内存端点、fence 作用及控制/生命周期
都必须由完整框架 F 对应；不是只把找到的目标区域组成 h。

必须区分源用户图和含 Dat3M 私有线程协议的完整图。令
`Ext_runtime(h(g))` 是：把源用户图经 h 重命名后，按**既有**运行时前缀契约
补全私有协议事件所得的合法全图。用户写式在此仍用源值，不要求这个中间图已经
满足目标 Q 的用户写式；否则会循环论证。运行时语义只处理已核对的创建/join/
协议接口，不提供 FAA 用户表达式正确性。原 Γ_runtime 保证这种补全存在；
协议对象与用户对象分离，全部协议值/控制接口属于保留边界。

下文的图引理对已补全图也成立。值修复固定的是选定的**一张完整**图 G，含其
全部私有事件/关系；不重新挑选运行时的 rf/co。精确量词是：

```text
对每个合法输入 i、每个 g ∈ Exec_T(P,i)，
对每个 G ∈ Ext_runtime(h(g))，存在 g' ∈ Exec_T(Q,i)，
skeleton(g')=skeleton(G)，且 obs_phi(g')=obs_phi(g)。
原 Γ_runtime 给 Ext_runtime(h(g)) 非空。
因此 Bad_phi(P,i) ⇒ Bad_phi(Q,i)。
```

g' 可以有不同的修复对象数值；**Q 的代码、事件对象、表达式、属性和查询字节
不变**。求值函数始终是实际 Q 中的函数，不是为配合源图修改函数或参考语义。
源图 g 先任意给定，补全后 rf/co 一次整体固定，不能选择“有利的源执行”或给各片段
分别找环境。整个证明不以前置 Safe(P) 或 Safe(Q) 为条件。

如果一开始把 P 的执行也定义在相同已展开协议的事件域上，可直接取 G=h(g)。
没有展开时，不能声称用户图与含私有节点的 Q 全图有相同节点数；这是沿用旧
运行时桥的区别，不是本轮通过值修复证明了 pthread 实现。

## 3. 值修复域及不能省略的框架

选一组完整用户对象 D。记 R_D、W_D 为 D 上的全部非初始化读/写。最小及最终
本轮已证范围都要求：源访问全是无条件 FAA，目标是完整对应的 FAA 形状读/写
端点，已配对且每个写带 A；不要求所有访问来自同一动态线程。这里“FAA 形状”
不预设目标写值已经等于源加法：实际目标总表达式可以不同，正是待修复的差异。
D 外对象、初始化、线程库私有协议全部保留完整检查。
本轮不借此推广普通 C 冲突访问；普通 C 输入仍在执行期间只读且与 asm 写对象分离。

F 的具体义务仍包括：

1. P/AST/L/L'/Q、版本/配置、源静态位置、调用上下文、动态激活、每个事件及
   监视器身份的完整检查；源域有有限无环 CFG、有限直接线程激活。
2. C→LLVM 与 L1/L2 的全部原始开放等式；未修改框架和每个宿主语句的消费。
3. Q 中所有地址、宽度、执行存在性、配对、A、fence、跨区域 po、同步/创建/
   join、错误前缀及查询绑定。不能省掉这些条件，省略范围只可能是写值等式。
4. 每个实际目标写值表达式是总的类型化位向量函数。其输入仅为合法固定入口、
   不修复的输入值和本线程**已经执行**的读结果；包含自身 RMW 读。
   展开纯 SSA 后每个读→写依赖都需证明在同线程 po 内，不能靠 `%name` 猜测。
   未支持调用、跨线程裸寄存器绑定、未来值、poison/undef/偏函数均拒绝。
5. 边界 B 包含全部安全观察，以及地址/存在性/分支/生命周期/assume、跨修复簇
   外部接口返回等保持路径所需的值。簇内部绑定且只供修复写使用的 asm 返回值
   不自动成为观察。B 和 D 外写值对 R_D 的两侧依赖均被排除；对应的源/目标
   普遍等式仍验证。纯 ITE 的条件和两个分支都计依赖。

这些是可列举的输入范围/检查义务，不是新的外部 Γ，也不是把全程序行为包含
作为 F 假设。边界独立性可用保守自由变量检查充分保证；更精确的关系式无干扰
证明未在本轮设计中依赖。

## 4. 分层推广

| 层 | 新允许的情形 | 已证明的构造 | 状态 |
|---|---|---|---|
| M0 | 一个共享对象，任意有限多个动态 FAA 线程；增量仅依赖固定边界输入 | 沿固定 co 递推 | 解析证明闭合 |
| M1 | 同一对象的较早本线程返回值参与后续增量 | co 递推及局部历史因果性 | 解析证明闭合 |
| M2 | 多个共享 FAA 对象，跨对象依赖图无环 | 对象拓扑序内分别按 co 递推 | 解析证明闭合，但不是必要限制 |
| M3 | 对象依赖图允许成环；值依赖仍是合法本线程读→写 | 在同一源 H 的拓扑序上联合求值 | 解析证明闭合，比 M2 更一般 |
| 稳定分支 | 有限分支 guard 仅依赖不修复边界，全部路径/激活已覆盖 | 每个源路径保持，路径内应用 M3 | 条件性推论；新 CFG 实现义务未实现 |
| 一般分支/环境/循环 | guard 依赖修复值、未审计访问、无界激活等 | 不能直接使用上述规则 | 反例或未闭合；保留全检查/拒绝 |

M3 容许修复值流入其他修复写及死的局部值；不能流到保留写或观察/结构边界。
“对象依赖有环”不等于“合法执行的值方程有环”。混淆两者会不必要地拒绝 M3。

## 5. 与冻结成果的关系

旧 PD-SAFE 的单 owner 引理没有被改写；它说的是本线程最新写。这里证明的
共享 FAA 引理说的是**全局 co** 直接前驱，两者命题不同。旧完整 L3/L4 的
全值含义不变；新数学规则即使成立，也只能作为性质专用关系的候选授权依据。

所有源语义/实际对象链接、ISA 桥、运行时与编码可靠性仍按原八项 Γ；本轮
没有证明这些组件，也没有宣称 M3 已落实到生产 Checker 或真实新的程序证书。
新前提若没有独立实现检查，必须阻止新范围授权，而不是转入 Γ。
