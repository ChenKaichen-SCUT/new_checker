# 反例、区分性例子与不能偷换的方向

以下都是解析构造，不是手写 Q 的认证实验，也不代表新编译/后端运行。
例子中的 FAA 使用 32 位无符号模运算，返回旧值。除明确的 CAT-only 例子外，FAA 都是
完整 locked 指令；普通主线程观察置于成功 join 后，避免普通 C 并发冲突。

**合法性的共同验证办法**：若给出一条按完整 FAA 连续执行的 SC 线性次序，
每个读取该次序中的最新同对象写，co 为写在该次序中的限制，则所有 po-loc、
rf、co、fr、rfe、K、J、mfence 边均沿该次序向前；两个 FAA 端点之间没有其他写，
原子性成立。因此满足本轮固定 CAT。这只是构造若干合法见证的办法，理论并未
把全部 TSO 执行缩成 SC。文中省略的 create/join 可在前/后按同次序扩展；实际
运行时桥仍是原 Γ_runtime，不在这些手算中被证明。

## C1：CAT 的外部原子性不能替代真实区域形状

同一线程上 `r_x po u_x po w_x`，另有初始写 i=0。设 `rmw={(r,w)}`，
`rf={(i,r)}`，`co=i<u<w`，u 写 1，w 写 2。r 和 w 可带 A。
U 和 H 中的边都在 `i,r,u,w` 的顺序向前；`fre;coe` 中不能形成 `(r,w)`，
因为中间写 u 与 r/w 同线程。因此这个关系结构满足列出的 CAT 公理。
但 r 读 i，而 w 的 co 直接前驱是 u。

这是 **CAT-only** 命题的反例，不是真实 FAA 的反例：u 插进同一指令的读/写，
违反指令语义及独立区域检查的既有前提。不能用它否定满足前提的引理 1；
也不能忽略它而声称原子性一个空关系约束已经足够。

## C2：去掉真正的原子更新，co 递推不再正确

两线程各执行非原子的 `load x; store x=old+1`。初值 0，取
`r0,r1,w0,w1` 的执行次序，rf 都来自初始化，co 为 `i<w0<w1`，写值均为 1。
rmw 为空，这是合法 TSO 图。若错误地沿 co 把第二个读的值设为第一写的 1，
就改变了固定 rf 所要求的初值 0；即使源/目标程序完全相同，这种递推也失败。

该例证明“沿 co 的前驱递推”依赖真正的 RMW 前提，不证明所有普通读写上的
其他联合值算法都不可能。当前 M3 不扩展到这类对象。

## C3：返回值进入性质时，修复存在不等于错误保持

源：两个线程分别执行 `r=FAA(x,1); assert(r!=1)`，x 初值 0。
目标只把增量改为 2，断言和所有原子/配对/线程结构保持。

任一合法完整源执行中，两个返回值为 0、1，至少一个断言失败。目标的返回值
为 0、2，两个断言都成立；未完成前缀也没有返回值 1。固定同一 co/rf 后，
源图和目标图各自合法且值修复能完成，但源错误被消掉。没有假定源程序安全。
缺失的是返回值到观察的边界闭包；正确算法把 x 保留，而非修复其写值。

## C4：依赖修复值的条件事件破坏完整事件集合

两个源线程分别执行：

```text
r = FAA(x,1);
if (r==1) FAA(y,1);
```

x,y 初始均为 0。main join 后断言 `y==0`。目标将两次 x 的增量改成 2，
其余代码不变。源有且只有一个 r=1，故执行一次 y 更新，main 出错；目标没有
r=1，y 不更新，main 安全。源/目标各自都可按完整 FAA 顺序得到合法 TSO 图。
但不能保持源中那对 y 事件：目标 guard 为假。

因此不能以“写值可重算”为理由保持一个实际上不可执行的事件集合。guard 必须
属于边界；保守算法使 x 不可修复。若某分支只在两个纯局部总表达式间选择，
结果仅供修复区使用，它是另一回事：总 ITE 已被 M3 证明涵盖。

## C5：分别认证各对象而不检查交界，会得到错误结论

源：T0 执行 `a=FAA(x,1); FAA(y,a)`；T1 执行 `FAA(x,1)`。x,y 初始 0，
main join 后断言 `y!=1`。目标把两个 x 的增量改为 2，y 的更新表达式仍是 a。

选择源次序 T1.x、T0.x、T0.y：a=1，y=1，源错误。目标相应次序 a=2、y=2；
另一种 x 次序 a=0、y=0，目标均不违反 `y!=1`。两侧各自图合法。
在开放参数 a 上，y 的局部等式仍是同一个 `old+a`，恒等比较会通过。
但修复 x、保留 y 的值要求 y 同时写 1 和 2，无法组合。

正确规则：若 y 受观察，就沿 y 写式→x 返回值→x 全部写的边传播，保留 x；
若 y 也确属无干扰修复区，可以把 x,y **联合**按同一源图重建，不能沿各自的
源值独立检查后宣称全局成立。

## C6：对象依赖成环可以合法，不能据此拒绝所有跨对象情况

源程序：

```text
T0: a=FAA(x,1); FAA(y,a+1);
T1: b=FAA(y,1); FAA(x,b+1);
```

记四次操作为 α=T0.x、γ=T0.y、β=T1.y、δ=T1.x，初值 0。
取合法次序 `α,γ,β,δ`：源各 `(读,写)` 是 `(0,1),(0,1),(1,2),(1,3)`。
对象依赖有 `x→y` 和 `y→x`，但具体值依赖沿上述事件次序向前。

在固定目标中把 α 的增量改为 2、γ 的增量改为 a+2，其余表达式不变。
同一 co/rf 上目标四对值是 `(0,2),(0,2),(2,3),(2,5)`（按位宽取模）。
目标表达式、供值边和所有 CAT 约束均成立。若 x/y 的所有返回用途仅在这个
修复簇内部，外部 phi 只观察独立输入/对象，则错误观察保持。此例不预设外部
phi 已安全：例如独立输入 v 的 `assert(v==0)` 在 v=1 时两侧都失败。

反过来，试图同时令 co_x 为 `δ<α`、co_y 为 `γ<β`，保留两线程程序次序，
会得到 `w_δ co w_α po-tso w_γ co w_β po-tso w_δ` 的 H 环。这不是合法
TSO 反例。M3 对所有合法图成立，而不是把不合法循环也要求求值成功。

## C7：不认证环境访问就不能声称任意上下文保持

两个 worker 的源操作各为 `FAA(x,1)`，返回不用；目标各为 `FAA(x,2)`。
若只看这两个 worker，x 没有活跃输出。但增加 main 在 join 后读取 x 并断言
`x!=2`，源 x=2 出错，目标 x=4 不出错。没有普通 C 并发冲突，所有 FAA 均合法。

这同时反驳把“worker 内返回不用”当作完整无干扰证据，以及把检查到的局部
读写表当作全环境表。源码闭包、对象逃逸、外部调用/回调及 main 观察若没有
完整核验，只能保留全等价义务或拒绝；不能另加“环境不观察 x”的未证 Γ。

## C8：结构改变必须分析正确的包含方向

源 store-buffering 程序 `T0: W(x,1); R(y)`、`T1: W(y,1); R(x)` 的双零
图合法 TSO。若目标在两个线程 W→R 间都加强为 MFENCE，双零图出现 H 环而
被删掉；性质“不是双零”可在目标成立而源不成立。这是过强排序漏掉源错误的
反例，说明不能把排序变化当成值修复的一部分。

相反，**仅移除** A/fence 约束通常放宽目标行为；这可以破坏等价，却未必破坏
用于 SAFE 的源→目标包含。不能拿“行为不同”就宣称这种弱化必然产生不可信
SAFE。当前规则要求固定结构，因此仍不接受这种改动；要支持单向排序放宽，
需要另外的精化规则，不属于本轮。原报告中的排序攻击不替代方向分析。

## 剩余边界

- 有限无环总表达式有 DAG，仍不能推出偏函数/poison 的目标有合法值；总性是
  独立义务。CAS 的写存在性还依赖比较结果；M3 不把它当无条件 FAA。
- 未知别名可能把“不可观察簇”与观察对象合并。没有对象分离证据，禁止修复。
- 不经本线程先前读定义的“未来值”输入不符合真实 SSA/源顺序，不能拿这样的
  环充当 FAA-only 合法反例，更不能把它接受到算法中。
- 有限展开实例数、循环携带依赖及线程激活的覆盖没有归纳证明时，不能输出
  无界结论。没有把 bounded PASS 用作该归纳证明。

C2/C8 的普通读写是机器事件层例子；它们不把具有数据竞争的普通 C 程序声明为
有定义源程序。C3–C7 使用原子 FAA 和必要时 join 后的观察，针对本轮接口边界。

这些攻击分别限定模型前提、性质边界、组合和范围；不是新实现的故障通过率。
