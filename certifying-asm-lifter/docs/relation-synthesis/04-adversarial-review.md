# 对抗审阅、独立性与方法贡献边界

## 1. 完成的逐层审查

|问题|充分检查|仍需信任/不作的主张|
|---|---|---|
|合成器擅改输入或观察|从原DSL反向恢复槽位，再完整重构比较所有字段|Python DSL解析/总表达式实现|
|死臂读取变成任意有效值|每槽先置0、选择的Load/FAA才覆盖；旧Oracle遍历全部结构路径|当前固定骨架，非一般C CFG|
|局部图可行但全局不合法|单一全局rf/co、派生fr、U/T与atomic；旧具体图核验|同一固定CAT，不借用目标模型结果|
|一个目标图漏掉其他执行|B完整图集与A₀双向相等；完整集重新提取全部统计|两实现共享具体核验器，不是两个内存模型|
|无边被当通配|false逐边否定；未声明才通配；独立嵌入回溯|非任意二阶模式逻辑|
|多个模式量词混用|共享语法，各目标独立执行符号与完整见证|只证明逐目标存在，不保证一图同时命中|
|合成器提供事件或映射|最小core只给输入/reads/rf/co；原DSL重新产生所有端点|不接受手写Q，无任何Q参与|
|语义相同但静态身份不同|已证FAA菱形运输与完整图特征再核验|终态相等不能一般推出模式相等|
|资源截断冒充排除|所有UNKNOWN/超时保留，截止后结果不计输出|有限域可判定不意味着本次求解完成|
|候选算法进入可信基础|成功必须由旧Oracle/独立A₀确认|UNSAT仍依赖公式与Z3，没有独立求解器证明检查|

Z3重放的首轮失败来自上下文内AST编号导致交换律子项排序不同。修正只对AND/OR/
相等/Distinct/整数与bv加乘进行交换律规范化，保留断言数量、顺序、类型、运算符
和全部叶节点。规范化使用共享结构驻留表，不以文本摘要取代逻辑结构。不同排序
在这些运算下等价；不支持的变化仍拒绝。旧证据文件未重写，pilot-01留作失败记录。

另一个审查发现：`read_control`确实含读值guard，但初次候选只有真臂可达。不是
Oracle错误，亦不是两臂覆盖。补充边界查询共享一个由SMT选择的读值分支位置，
两个完整执行使用同一个b=false，分别要求该分支真假。语法/参数/其他事件仍由
求解器选择。独立核验从原DSL恢复合格分支并检查两个实际路径，不相信focus变量。
该附加条件不进入正式性能策略或其目标集，只用于拒绝退化的正确性演示。

**补充引理。** 若同一程序的两个合法完整图在相同输入下分别执行同一已定义
读值guard的真/假臂，则两臂均语义可达。证明只是从各合法图投影该线程前缀；
不能由其中任何一个图推出另一个。反向查询用共享分支selector和两份独立执行
编码，与引理1–3组合，恰编码存在这一分支及两个图，不需要预先指定故障/位点。

## 2. 保持或改变关系模式的边界

FAA菱形在既有同对象/共同出口/输入总表达式条件下，按实际路径把一臂FAA的
R/W映射到合并FAA；上下文事件恒等。全局关系和标签由旧定理保持，因此无静态id
的诱导模式集相同。这里实现验收再次求两边完整图，而不是用终态相等倒推。

反例：T0 Store(x,1)，T1 Load(x)但不观察其局部结果。删去T1的Load，两边终态
x都为1，却删除了可实现rf模式；所以观察等价不蕴含模式等价。另一个反例是
把活跃两次FAA融合，其他线程可读取中间写；既不保全部图，也未必保观察集合。

## 3. 对已有方法的准确定位

[diy7官方生成器说明§7.2–7.3](https://diy.inria.fr/doc/gen.html) 已经从通信/程序序
关系环生成测试，区分同/异地址及同/异线程，包含rf/co/fr。因此“从关系反向造
并发程序”本身不是本项目的新颖性。其教程是现有直接先例，不将未运行的diy7
列为本轮性能基线，也不推断其不支持本工具链就算法落后。

本轮与旧固定池S的实质实现区别：不需要先求完池中每个程序，而是在一个有界
公式中同时选择语法、两臂、值、地址、完整TSO图及目标单射。这个区别可以从代码
和原始SMT复核；它既不是固定程序查表，也不是只重命名贪心。但联合有限语法
与执行关系的SAT/SMT合成本身是标准有限约束合成；直接co前驱传播来自既有引理，
多请求共享语法是标准合取。当前没有新复杂度界、最优搜索方法或一般性分解定理。

三层贡献须分开：受限公式双向性是所需充分性证明；可复用的独立接受与证据链
属于原型工程贡献；独立算法创新并不因证明或新增模式而自动成立。即使指定关系
比随机更容易到达，也不能推导发现实际软件错误，更不能把相关F3当独立泛化。

本轮不运行真实工具，不比较缺陷数，不把历史Dat3M问题当成本轮发现。算法有效性
必须由修正后的同域/同预算数据决定；独立创新仍需超越直接标准机制组合的证据。
